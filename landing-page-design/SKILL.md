# Landing Page Design — 转化驱动的落地页设计指引

## 快速参考

| 维度         | 规范                                            |
| ------------ | ----------------------------------------------- |
| **技术栈**   | shadcn/ui + Tailwind CSS + Framer Motion        |
| **核心目标** | 单一 CTA 转化率最大化                           |
| **首屏法则** | 5 秒内回答：这是什么？给谁用？为什么关心？      |
| **文案策略** | 特性 → 直接利益 → 终极利益（"So What?" 三级跳） |
| **性能基线** | LCP < 2.5s · CLS < 0.1 · INP < 200ms            |
| **移动端**   | tap target ≥ 44×44px · 吸底 CTA · 数字键盘适配  |

> **职责边界：** 本 skill 管页面策略与信息架构。视觉样式（字号、色值、间距、圆角）交给 visual-design 决定。

## 工作流程

按以下顺序执行，不要跳步：

1. **前置确认** — 向用户确认产品、用户、转化目标、信任素材、产品阶段
2. **页面架构** — 根据产品阶段选取模块组合，确定线性叙事顺序
3. **构图规划** — 为每个模块选择构图类型，规划整页视觉节奏（密度交替）
4. **文案策略** — 对每个功能执行"So What?"三级跳，撰写 Hero 标题和 CTA
5. **实现构建** — 使用 shadcn/ui + Tailwind + Framer Motion 输出代码
6. **审查** — 按审查清单逐条自检，检测反模式

## 前置确认（开始设计前必须明确）

在动手之前，先向用户确认以下信息（如果用户未提供，主动询问）：

1. **产品是什么？** — 一句话描述核心价值
2. **目标用户是谁？** — 决定文案语气和痛点切入角度
3. **转化目标是什么？** — 注册、购买、预约演示、加入等候名单？决定 CTA 文案
4. **有哪些可用的信任素材？** — 现有客户、使用数据、证言、认证？决定信任信号模块选取
5. **产品阶段？** — 早期（无客户）/ 成长期（有数据）/ 成熟期（品牌已知）？决定模块组合

> 缺少以上任何一项，都不要靠猜测填充——宁可少一个模块，也不要编造内容。

## 核心指令

构建落地页时，按此优先级做每个决策：

1. **转化优先** — 每个 Section 必须服务于推动用户走向主 CTA
2. **认知减负** — 利用视觉层次与留白降低用户认知负荷
3. **利益叙事** — 永远展示用户能得到什么，而非产品拥有什么
4. **按需构建** — 根据产品实际阶段选取模块，拒绝填充式堆砌

## 一、页面架构：决策树

落地页是线性叙事通道。不是所有模块都需要——根据产品实际情况选取。

### 必选模块（不可省略）

| 模块       | 核心职责                                             |
| ---------- | ---------------------------------------------------- |
| **Hero**   | 5 秒内完成价值传递，引导用户做出第一次滚动或点击决策 |
| **主 CTA** | 页面的唯一核心转化目标，至少在首屏和页尾各出现一次   |

### 选配模块（按需选取）

| 模块                    | 何时需要                             | 核心职责                               |
| ----------------------- | ------------------------------------ | -------------------------------------- |
| **Nav Bar**             | 页面较长或有多个锚点时               | 品牌锚定 + 快速导航，保持极简（≤5 项） |
| **Social Proof Bar**    | 有知名客户或可量化的使用数据时       | 即时信誉，降低首次信任门槛             |
| **Pain → Solution**     | 用户痛点不明显、需要被唤醒时         | 建立共鸣：先让用户点头，再呈现方案     |
| **Features / Benefits** | 产品有 3 个以上核心卖点需展示时      | 将技术特性翻译为用户利益               |
| **How It Works**        | 产品流程较复杂、用户需要"看到简单"时 | 降低复杂度认知，用 3–4 步讲清楚        |
| **Testimonials**        | 有真实用户的具体成效数据时           | 用他人的成功故事消除犹豫               |
| **Pricing**             | 定价是转化决策的关键因素时           | 透明呈现价值与成本的关系               |
| **FAQ**                 | 用户调研中有反复出现的疑虑时         | 消除临门一脚的异议                     |
| **Footer**              | 始终需要                             | 法律信息、次要链接兜底                 |

### 典型组合（快速路径）

| 产品阶段                         | 推荐模块                                                                                |
| -------------------------------- | --------------------------------------------------------------------------------------- |
| **早期 MVP**（无客户、无数据）   | Hero → Features → CTA                                                                   |
| **成长期**（有用户、有数据）     | Nav → Hero → Social Proof → Features → How It Works → Testimonials → CTA → FAQ → Footer |
| **成熟品牌**（品牌已知、重定价） | Nav → Hero → Pain/Solution → Pricing → FAQ → Footer                                     |

> 以上仅为起点，最终取舍基于前置确认中获得的实际信息。每增加一个模块，都应能回答"它帮助用户向 CTA 迈进了一步吗？"

## 二、Hero Section：黄金 5 秒

### 标题质量标准

一个合格的 Hero 标题，读完后用户能回答这两个问题：

1. **这个产品帮我做什么？**（具体动作，非抽象描述）
2. **结果是什么？**（可感知的变化，最好可量化）

**禁止：** 空洞的自我定位（"最先进的 XX 平台"、"一站式 XX 解决方案"）。标题必须关于用户，不是关于产品。

### 视觉主体选择

| 类型            | 适用场景                                                 |
| --------------- | -------------------------------------------------------- |
| **产品截图**    | UI 型产品，界面本身即卖点                                |
| **短视频/动画** | 工作流型产品，需展示操作过程（≤ 15s，WebM + MP4 双格式） |
| **抽象插画**    | 概念型产品，无具体 UI 可展示                             |
| **交互演示**    | 复杂产品，"先试后买"策略                                 |

### 构图策略

根据产品类型和视觉主体选择 Hero 构图，避免默认套用 Split：

| 构图                             | 结构                             | 选择依据                             |
| -------------------------------- | -------------------------------- | ------------------------------------ |
| **Split（左文右图）**            | 文案与视觉主体左右分栏           | UI 型产品，产品截图本身即卖点        |
| **居中堆叠**                     | 标题居中 → 视觉主体在下方        | 视频/动画演示，或产品需要宽幅展示    |
| **全幅沉浸**                     | 视觉占满视口，文案叠加           | 视觉冲击力强的品牌产品、创意工具     |
| **Editorial**                    | 大标题主导，视觉主体作为配角点缀 | 概念型产品、文案驱动的叙事型落地页   |
| **Product Showcase（产品展台）** | 产品居中放大，文案环绕或上方     | 实体商品、设计工具、需要突出产品形态 |
| **交互先行**                     | 可操作的演示/输入框作为视觉主体  | 开发者工具、搜索产品、"先试后买"策略 |

> 详细变体、响应式退化和产品匹配见 `references/composition-catalog.md`。
> 视觉主体应强化标题承诺，而非装饰填充。

## 三、CTA 设计：转化的终点

### CTA 文案标准

- **动词开头** — 文案以动作驱动，告诉用户"做什么"
- **包含利益** — 让用户在点击前就能预期获得什么
- **匹配实际承诺** — 文案必须与产品真实提供的内容一致，不夸大

**禁止：** 泛化的"提交"、"注册"、"了解更多"。CTA 文案应具体到产品。

### 风险消除

如果产品提供免费试用、无承诺入口或退款保证，在 CTA 旁以微文案标注。不要凭空编造承诺。

### CTA 放置策略

- **首屏**：Hero 区主 CTA（必须）
- **页面中部**：在信任信号（功能介绍或证言）之后重复 CTA
- **页面底部**：最终 CTA 区块
- **移动端**：滚过 Hero 后显示吸底悬浮 CTA

## 四、文案策略：从特性到终极利益

### "So What?" 三级跳

每个功能描述必须完成三次转化：

```
物理特性 → "那又怎样？" → 直接利益 → "那又怎样？" → 终极利益
```

| 层级                     | 含义                     | 检验                     |
| ------------------------ | ------------------------ | ------------------------ |
| **特性**（禁止停留于此） | 产品做了什么（技术描述） | 用户读完会说"所以呢？"   |
| **直接利益**             | 用户因此能做什么         | 能回答"对我有什么用？"   |
| **终极利益**（目标）     | 用户的生活/工作如何改变  | 能回答"为什么我该在意？" |

**跳跃结构示例：**

```
[技术特性]  →  因此你可以 [直接利益]  →  最终 [终极利益]
```

每一跳必须是因果递进，不是同义改写。如果从特性到终极利益跳不过去，说明这个特性不值得放在落地页上。

> 三级跳需要基于产品真实能力推导，不要虚构利益。

## 五、视觉构图与页面节奏

### 视觉节奏 (Visual Rhythm)

整个页面需要密度交替的视觉节奏，不能所有 Section 密度相同（通用间距参数见 visual-design §IV）。落地页规划时额外考虑三个维度：

| 维度         | 含义                           | 典型节奏                                                  |
| ------------ | ------------------------------ | --------------------------------------------------------- |
| **密度交替** | 信息密集区与留白呼吸区交替出现 | 密（Hero）→ 疏（Social Proof）→ 密（Features）→ 疏（CTA） |
| **重量递进** | 视觉重量从轻到重或从重到轻     | 轻量入场 → 中段信息密集 → 重磅终场 CTA                    |
| **焦点迁移** | 用户注意力焦点在不同位置间移动 | 居中 → 左侧 → 右侧 → 居中（避免连续同侧）                 |

**强制规则：** 相邻两个 Section 不得使用相同构图类型。

### Section 构图词汇

| 构图                            | 结构                             | 密度 | 适用场景                                                                                 |
| ------------------------------- | -------------------------------- | ---- | ---------------------------------------------------------------------------------------- |
| **Bento Grid**                  | 多卡片不等尺寸网格               | 高   | 功能汇总（3–6 个），用面积编码优先级                                                     |
| **Feature Zigzag**              | 左图右文交替排列                 | 中   | 逐个深入介绍（3–4 个核心功能）。注意：图片应展示实际产品而非纯装饰插画，否则扫描效率下降 |
| **Icon Grid**                   | 等宽网格，图标+标题+一句话       | 中   | 轻量功能列表（6+ 个）                                                                    |
| **Sticky Scroll（滚动叙事）**   | 左侧文案列表，右侧随滚动切换视觉 | 高   | 需要逐步展示产品不同状态/功能                                                            |
| **Stats Section（数据统计带）** | 大号数字 + 标注，横向排列        | 低   | 成效数据展示（用户量、增长率、节省时间）                                                 |
| **时间线**                      | 垂直/水平步骤连线                | 中   | How It Works 流程、产品演进路线图                                                        |
| **对比分割**                    | 左右或上下 Before/After 对比     | 中   | Pain→Solution 叙事，产品效果前后对比                                                     |
| **Statement Section（声明区）** | 居中大段文案 + 单一视觉元素      | 低   | 品牌宣言、核心理念传递、呼吸留白区                                                       |

> 详细构图描述、密度定位和响应式退化见 `references/composition-catalog.md`。
> 选择依据：功能数量 × 解释深度 × 在页面中的节奏角色。

## 六、信任信号选配指南

根据产品实际情况选择信任信号类型：

| 条件               | 推荐信任信号                                            |
| ------------------ | ------------------------------------------------------- |
| 有知名客户         | Logo 墙（灰度展示，数量根据实际有多少放多少）           |
| 有量化成效数据     | 带具体数据的客户证言                                    |
| 有权威认证         | 安全证书 / 行业评分 / 媒体引用                          |
| 早期产品，尚无客户 | 创始人/团队故事、技术透明度、开源贡献、早期用户等候名单 |

> **不要伪造社会证明。** 没有客户就不放 Logo 墙，没有证言就不编证言。诚实比套路更能建立信任。

## 七、动效规范

动效服务于信息释放节奏，不是装饰。缓动曲线、时长、stagger 参数等由 visual-design skill 决定。

**落地页特有规则（visual-design 没有覆盖的）：**

- 首屏元素用 `animate` 直接播放，**不要用 `whileInView`**（用户看到的第一帧不应该是空白）
- 非首屏 section 和卡片列表可用 `whileInView`（只触发一次），引导视觉阅读顺序
- 必须尊重 `prefers-reduced-motion`

**落地页禁止：** 移动端 parallax · 纯装饰动画 · 每个元素都加入场动画

## 八、表单优化

核心法则：**字段数量与转化率负相关。每增加一个非必要字段，都需要充分理由。**

- 使用 shadcn/ui 表单组件，内联实时验证
- 移动端：数字输入用 `inputMode="numeric"`，所有 tap target ≥ 44×44px
- 长表单拆分多步，每步 1–2 个字段
- 表单字段的选择应基于产品实际需求，而非套用模板

## 九、性能与响应式

遵循 Core Web Vitals 基线（LCP < 2.5s · CLS < 0.1 · INP < 200ms）。Hero 主图 `loading="eager"`，其余 `lazy`，格式优先 AVIF > WebP。语义化 HTML（唯一 `<h1>`、`<main>`/`<section>`/`<footer>`），提供 JSON-LD 结构化数据。

Mobile-First 设计：移动端单列堆叠 + 吸底 CTA + 折叠导航。Logo 墙移动端用横向 marquee，Bento Grid 退化为单列。

## 十、审查清单

构建完成后，逐条自问：

| 维度       | 自问                                                                                             |
| ---------- | ------------------------------------------------------------------------------------------------ |
| **转化**   | 页面是否只有一个主 CTA 目标？首屏能否在 5 秒内传递核心价值？CTA 是否在首屏和页尾至少各出现一次？ |
| **构图**   | Hero 构图是否匹配产品类型？相邻 Section 是否使用了不同构图？整页是否有密度交替节奏？             |
| **文案**   | 每个功能描述是否完成了三级跳？标题是否关于用户而非产品？是否存在空洞的自我定位？                 |
| **信任**   | 社会证明是否基于真实数据？有没有模块是为了"填满页面"而非服务转化？                               |
| **动效**   | 首屏是否用了 `animate` 而非 `whileInView`？是否尊重 `prefers-reduced-motion`？                   |
| **性能**   | Core Web Vitals 是否达标？Hero 图是否 `eager` 加载？是否有唯一 `<h1>`？                          |
| **响应式** | 移动端是否单列无溢出？吸底 CTA 是否正常工作？tap target 是否 ≥ 44px？                            |

## 十一、反模式检测

| 反模式          | 症状                                            | 策略                                            |
| --------------- | ----------------------------------------------- | ----------------------------------------------- |
| **多 CTA 竞争** | 页面有 2+ 个不同目标的主 CTA                    | 明确唯一的转化目标，其余降级为辅助动作          |
| **特性堆砌**    | 功能描述停留在技术术语                          | 对每个特性执行"So What?"三级跳                  |
| **空洞标题**    | 自我定位式标题，不含用户利益                    | 重写至用户能回答"它帮我做什么"和"结果是什么"    |
| **信任真空**    | 无任何信任信号                                  | 根据产品实际情况从信任信号选配指南中选取        |
| **模板填充**    | 每个模块都有但内容空洞、缺乏产品针对性          | 删减至只保留有实质内容支撑的模块                |
| **动效过度**    | 每个元素都有入场动画                            | 只保留 Section 级入场 + CTA 交互反馈            |
| **导航泄露**    | Nav 包含大量外链分散注意力                      | 落地页导航 ≤ 5 项，移除非必要外链               |
| **视觉单调**    | 连续多个 Section 使用相同构图（如全部三列卡片） | 相邻 Section 必须使用不同构图，规划密度交替节奏 |
