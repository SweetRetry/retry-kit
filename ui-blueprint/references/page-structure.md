# Page Structure & User Flow

通用页面结构规则。适用于所有页面类型的结构规划阶段。在生成 blueprint 前，用本文件确认页面动线和功能分区是否合理。

---

## 核心原则

- **一屏一件事**：每屏只传递一个核心信息，用户不需要在同一视口内做多个无关决策
- **顺序对齐**：section 排列顺序 = 用户阅读顺序 = 行动顺序。如果用户需要"先看 A 再做 B"，A 必须在 B 的上方
- **分区服从路由**：功能区域的边界应与路由/Tab 边界一致

---

## 页面类型标准动线

不要自己发明动线，先从标准模板出发，再按需增删。

| 页面类型 | 标准 section 顺序 | 可省略 | 禁止省略 |
|----------|-------------------|--------|----------|
| 落地页 | Hero → 痛点 → 方案 → 亮点 → 社会证明 → 定价 → 终场 CTA（详细模块组合见 landing-page-design skill） | 定价、社会证明 | Hero、终场 CTA |
| Dashboard | 概览指标 → 筛选/过滤 → 主数据区 → 详情/抽屉 | 概览指标（如只有一种数据） | 主数据区 |
| 设置页 | 分组导航 → 表单区 → 保存操作 | 分组导航（≤ 5 项时） | 保存操作 |
| 详情页 | 头部摘要 → 核心内容 → 相关/推荐 → 操作区 | 相关/推荐 | 头部摘要 |
| 引导流（Onboarding） | 欢迎 → 步骤 1…N → 确认/完成 | — | 进度指示、完成确认 |

## 功能分区：三层模型

一个页面最多 3 层信息层级，超过 3 层说明页面该拆分。

| 层级 | 作用 | 视觉处理 | 举例 |
|------|------|---------|------|
| L1 主区 | 用户来这个页面要完成的核心任务 | 占据最大面积（≥ 60%），无装饰干扰 | Dashboard 的数据表格、编辑器的画布 |
| L2 辅助区 | 支撑主任务的上下文或操作 | 紧邻主区，视觉权重低于 L1 | 筛选栏、属性面板、面包屑 |
| L3 全局区 | 导航、状态、与当前任务无直接关系 | 固定位置，最低视觉权重 | 顶栏、侧边导航、通知 |

### 分区自检

- [ ] 主区（L1）是否占据了页面最大面积？
- [ ] 辅助区（L2）的视觉权重是否低于主区？（字号更小、颜色更淡、或收缩为侧栏）
- [ ] 全局区（L3）是否在所有页面保持一致？（不随路由变化而变化）
- [ ] 信息层级是否 ≤ 3 层？超过 3 层考虑拆分页面或用渐进展示

## 导航架构速查

按功能数量和层级深度选，不要凭感觉选。

| 条件 | 推荐导航 | 说明 |
|------|---------|------|
| 一级功能 ≤ 5 个 | 顶部导航 | 简单直接，适合落地页、小型应用 |
| 一级功能 6–12 个 | 侧边导航 | 可展开/折叠，适合中型 SaaS |
| 一级功能 > 12 个 | 侧边导航 + 分组 | 用分组标题分区 |
| 移动端 ≤ 5 个 | 底部 Tab 栏 | 核心功能常驻可见 |
| 移动端 > 5 个 | 底部 Tab（4 个）+ 更多 | 第 5 个 Tab 是"更多"入口 |
| 层级 ≥ 3 层深 | 面包屑 | 辅助用户定位当前位置 |

## 行动层级（CTA 视觉权重分级）

| 层级 | 视觉处理 | 数量限制 |
|------|---------|---------|
| 主行动 | `size="lg"` + 品牌色填充 | 一屏 **1 个** |
| 次行动 | `variant="outline"` 或 `variant="secondary"` | 一屏 ≤ 2 个 |
| 三级行动 | 纯文字链接 / `variant="ghost"` | 不限 |

- 主行动与次行动之间必须有明确的视觉断层（填充 vs 描边、大 vs 小、品牌色 vs 无彩色）
- 同一行动栏内不允许出现 2 个相同 variant 的按钮

## 状态与反馈位置

| 状态 | 位置规则 | 视觉处理 |
|------|---------|---------|
| 加载中 | 原位 skeleton / spinner，不跳转不弹窗 | Skeleton 轮廓匹配最终内容的布局形状 |
| 空状态 | 主区（L1）居中展示 | 图标 + 标题 + 描述 + 一个 CTA |
| 错误 | 就近原则 — 哪个区域出错，错误信息就在哪个区域内 | 语义色 `destructive`，不影响其他区域 |
| 成功 | 操作按钮附近的 inline 反馈，或 toast | 短暂展示（3–5s），不阻塞后续操作 |
