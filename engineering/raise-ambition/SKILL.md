# Raise Ambition

把用户字面上的任务改写成瞄准真实结果的版本。本轮只读不写：交付一份 brief 和一段改写后的 prompt，然后停下，等用户明确说开始。

任务取自调用参数；参数为空时取对话中最近一个待办任务；两者都没有时问一句。

## 1. 摸清现场

只读查看与任务相关的环境：代码与目录、已有脚本和测试、日志、埋点与看板、可用 CLI 与 MCP 工具、已有数据。后面每条“需要的访问”都要据此标出已有还是缺。

**完成标准：**列出已有的原材料与工具，每项附路径、命令或工具名。

## 2. Altitude

- **真实结果**：字面任务背后，用户一个月后靠什么现象或指标判断这件事成了。写成终端用户或使用者身上的变化，交付物本身不算结果。
- **瞄准结果的任务版本**：为达到这个结果，任务的范围应该变成什么。
- **自主推进所需的访问**：日志、analytics、测试设备、脚本、凭据、数据集。每项标“已有”（附位置）或“缺”（写谁能提供，以及缺了时退化成什么做法）。

**完成标准：**真实结果可被观测；每项访问都有状态。

## 3. Depth

写顶尖从业者会做、但用户没要求的事：

- **原材料**：他们从哪里起步，例如生产日志、真实用户录屏、原始数据、竞品实测，而不是需求描述。
- **工具与方法**：具名到工具或技术，例如 profiler、test harness、telemetry、统计检验、A/B 实验、回放测试。
- **过高但可达的目标**：一个数字，附测量方法和可达的依据，依据标明是测量、推断还是猜测。

**完成标准：**每个方法都能直接照着做；目标是带测量方法的数字。

## 4. Range

- **动词重述**：用 3–5 个动词短语写任务必须为用户或玩家*做*什么。
- **跨领域技巧**：选 3–5 个软件之外的领域，每个写成“领域 → 技巧 → 用在本任务哪一步、产出什么”。技巧是可执行的方法，例如人因工程的任务时间测量、医学的鉴别诊断表、军事的红队推演，不是扮演某种角色。
- **对抗视角**：一个试图击穿或证伪成果的人。列出他最可能发起的 2–3 个攻击，每个对应到第 5 步中挡住它的验证项；挡不住的，补一项验证。

**完成标准：**每个技巧都落到本任务的具体步骤；每个攻击都有对应验证项。

## 5. Verification

列出判定成败的外部证据：测试、benchmark、测量或真实用户数据。每项写：

- 怎么跑：命令、脚本或数据查询；
- 通过阈值；
- 基线：当前值，未知时写取基线的方法；
- 能否在用户不在场时运行。

每项都由他人可重跑的命令或数据给出 pass/fail；自评与“看起来更好”只作为补充说明。

**完成标准：**至少一项可在用户不在场时运行；每项都有阈值。

## 6. 改写 prompt 并停下

把第 2–5 步改写成一段可直接交给 agent 执行的 prompt，包含：真实结果、任务范围、原材料、方法、目标数字、验证项与阈值、缺失访问及其退化方案。

按以下顺序输出：

1. Altitude
2. Depth
3. Range
4. Verification
5. 改写后的 prompt（单独代码块）
6. 需要用户提供的访问，每项一行

输出后停下。用户修改时，只重写受影响的部分并再次停下；用户确认后，按改写后的 prompt 执行。
