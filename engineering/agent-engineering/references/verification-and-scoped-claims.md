# 行为评估与交付

代码检查验证实现；行为评估验证 Agent 是否完成任务。两者不能互相代替。

## 选择验证层

| 改动 | 直接验证 |
| --- | --- |
| 参数解析、权限、幂等性或状态迁移 | 确定性检查或测试，覆盖高代价不变量 |
| 提示词、工具描述、路由、压缩或委托策略 | 代表性任务上的 Agent 行为评估 |
| 执行后端、恢复、审批或多 Agent 整合 | 在隔离环境运行关键路径，查最终状态与副作用 |

先运行项目要求及相关检查；仅在新变化、失败或未解决风险需要时扩大范围。文本修改不要求生产运行，缺少评估环境时说明验证范围。

## 行为评估

1. 明确可核验的最终结果和边界不变量。
2. 用原失败任务复现错误决策。
3. 用修订后的规则运行同一任务。
4. 用一个无关任务检查是否过拟合。
5. 检查执行轨迹与最终环境状态。

任务应来自真实用途；边界样本按改动风险选取。工具选择与步骤可以有多个合法路径，评分依据验收和约束，不要求复制固定答案。

规则改动至少做决策级检查。涉及模型随机性或声称可靠率改善时，在一致配置下重复试验，报告样本数和通过标准；一次成功不能证明稳定提升。

[Anthropic — Demystifying evals](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents) 区分任务、试验、评分器、轨迹与最终结果，并讨论重复试验。[OpenAI — Evaluate agent workflows](https://developers.openai.com/api/docs/guides/agent-evals) 建议先用轨迹诊断，再用数据集进行可重复比较。

## 诊断与证据

轨迹保留模型、指令和工具版本，关键输入、调用参数、结果、批准、交接、停止原因及必要成本指标。记录须脱敏，并能定位最终产物或系统状态。

从首个错误决策或执行边界开始归因，不只看最终答案。自动评分器须用人工核对的样本校准；模型裁判的评分不能替代实际副作用和权限检查。

## 完成声明

- 分开报告工作状态与验证状态；未运行、失败和结果未知不计为通过。
- 只有基线复现或直接证据支持时才称“既有失败”；失败文件不在 diff 中不足以排除间接影响。
- 预算耗尽、等待批准、工具仍运行或子任务结束时，保留真实未完成项。
- 最终交付绑定证据：实际变更、相关检查及结果、未验证范围和阻塞。无需为填模板扩大任务。
