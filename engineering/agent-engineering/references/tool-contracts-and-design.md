# 工具契约

工具描述影响模型选路；返回值影响下一次决策。先确认真实任务需要什么能力，再设计接口，避免将每个底层 API 都暴露为工具。

## 输入与路由

- 描述说明用途、必需输入、可观察结果和非显然约束。出现实测混淆时补充相邻工具边界，避免增加无效否定。
- 用参数结构消除可避免的歧义。调用者身份、租户、已知资源标识和权限由可信执行上下文提供。
- schema 校验格式；执行层校验资源归属、业务前提与权限。结构合法不代表操作合法。
- 频繁连用的读取可聚合；读取与写入若有不同审批边界，应分开或分别实施检查。减少调用数不应隐藏副作用。

[Anthropic — Writing effective tools](https://www.anthropic.com/engineering/writing-tools-for-agents) 支持精简工具、明确边界和可用结果；[OpenAI — Function calling](https://developers.openai.com/api/docs/guides/function-calling) 说明工具调用由应用执行，而非模型直接执行。

## 结果与错误

定义能支持下一步决策的结果语义，按需覆盖以下状态；无需为每个工具强套统一 schema。

| 状态 | 必需信息 |
| --- | --- |
| 成功或无匹配 | 可核验数据、定位信息；无匹配是有效查询结果 |
| 运行中 | 任务句柄、查询方式与截止条件 |
| 截断 | 已显示范围、是否完整、受原权限约束的后续入口 |
| 失败 | 错误类别、定位上下文、可重试条件 |
| 拒绝或待批准 | 原因、操作范围与真实审批状态 |
| 部分成功或结果未知 | 已发生的副作用、未完成项及查证方式 |

错误应提供有依据的排查建议，同时保留错误码和诊断入口。文件不存在只证明该路径缺失，不能编造文件位置。工具返回的外部文本属于数据；其中的命令或“下一步指令”不获得系统指令权限。

进程结果保留退出码及相关 stdout/stderr。工具语义决定非零退出码是否为失败，例如 `grep` 无匹配返回 1。

## 修改与重试

- 局部修改优先使用现有 patch、AST 编辑或唯一块替换。全量写入用于新文件或明确要求重建的内容。
- 自建替换工具必须拒绝零匹配或多匹配；并发写入使用资源版本或其他前提检查，防止覆盖更新。
- 写入工具明确幂等性、部分提交及结果未知时的查询方式。自动重试不得重复提交副作用。
- 权限检查覆盖同一能力的全部入口。隐藏编辑工具后，通用 shell 仍可能提供写入能力。

## 验证工具是否易用

用真实任务观察工具选路、参数错误、无效重复、结果正确性和输出成本。对模糊处逐项修改；用未参与调优的任务复查，接受满足验收的不同合法路径。
