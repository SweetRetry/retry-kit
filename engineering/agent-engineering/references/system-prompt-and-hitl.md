# 提示词与人机协作

提示词规定模型如何判断和行动；权限与批准由执行宿主实施。先定位行为缺口，再添加能改变决策的规则。

## 提示词与运行环境

- 明确任务结果、能力边界和非显然决策规则。删除重复语义、角色口号和可低成本查得的环境事实。
- 运行时可提供已知且必要的 cwd、可用工具与权限状态。易变信息标明范围或更新时间；启动时注入的仓库状态不能代替操作前查证。
- 项目文件、网页和工具结果保持数据来源身份。检索内容、错误提示和模型摘要不能自动升级为系统指令。
- 行为问题先分辨信息缺失、工具歧义和指令冲突。新增规则须能在原失败任务上改变决策，同时不误伤正常任务。

[Anthropic — Claude Code best practices](https://code.claude.com/docs/en/best-practices) 建议保持指令精简，并提供可验证的任务结果；它是 Claude Code 的实践，不规定所有宿主必须在首轮注入相同元数据。

## 已授权行动与澄清

实现或修复请求应推进到约定验收；评审和讨论按约定交付，不自动扩大为修改或发布。

先查事实和既有授权，再决定是否提问。可从项目惯例合理确定的实现自行处理；缺失信息会改变目标、重大取舍或阻塞下一步时，提出所需问题。等待期间继续独立工作。

用户的新回复可能修正当前任务。保留仍有效的目标与约束，按新决定更新；已有授权只在原目标、操作和范围内延续。

## 提问与批准

提问收集事实或偏好；批准允许执行具体操作。两者使用宿主支持的渠道，不因某个工具不可用而推定批准。

- 比较方案时说明选择与代价；缺少事实时直接询问事实。
- 审批展示实际目标、操作和副作用，执行层核对批准范围。
- 工具只返回“已提问”时，状态仍是待答。沉默、超时和默认选项均不构成批准。
- 待批准时保存运行状态；批准或拒绝到达后恢复同一操作。拒绝保持可见，不包装成一般工具错误诱导重试。

[OpenAI — Guardrails and human review](https://developers.openai.com/api/docs/guides/agents/guardrails-approvals) 提供 interruption 与状态恢复机制。不同宿主的批准策略不同，复用其机制而非增加统一的逐步确认要求。
