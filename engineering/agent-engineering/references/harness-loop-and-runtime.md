# 执行循环与运行时

## 循环与终止

运行时负责模型调用、工具执行、状态延续与终止。先复用已有 runner，再补已确认缺口。

- 区分任务完成、等待批准、等待工具、执行失败、取消与预算耗尽。模型产生最终文本只代表本次运行结束；任务完成仍由验收判断。
- 预算覆盖模型轮次、工具执行时长、总耗时及必要的成本限制。按任务和风险配置；到限时保留已执行操作、未完成项与恢复入口。
- 工具启动回执不等于执行成功。异步任务保留句柄，并在最终结果到达后更新状态。
- 超时或取消不保证远端操作已停止。记录是否已提交、是否可取消及结果是否未知；不能将结果未知报告成失败后直接重做。

OpenAI 的 [Running agents](https://developers.openai.com/api/docs/guides/agents/running-agents) 区分运行失败和预期暂停，并从原状态继续运行。具体状态结构按所用 SDK 核对。

## 重复调用与恢复

先判断重复是否有增量，再决定重试或阻断。依据包括调用参数、结果、资源版本和任务进展。

| 情况 | 处理 |
| --- | --- |
| 状态轮询，任务仍运行 | 按工具契约轮询，受截止时间约束 |
| 暂时网络故障，操作可安全重试 | 有上限地退避；核对幂等性 |
| 同一策略重复失败，资源与证据未变 | 停止该策略，暴露诊断；有新证据再换路径 |
| 写入超时，提交结果未知 | 先查询结果或使用幂等键，避免重复副作用 |
| 权限拒绝 | 停止该操作，保留拒绝原因 |

“重复两次”或参数哈希可以作为检测信号，不能单独判定死循环。重试预算来自任务和后端契约，不固定为全局次数。

恢复前核对远端会话状态、资源版本与待完成操作。只有后端缺少可靠存活状态时才增加短时只读探针。探针失败须保留原因；自动恢复仅在已定义、已授权且不会丢失或重复操作时启用。

## 执行边界

沙盒限制资源访问；审批决定某次操作是否允许。两者分别实施。模型可见的工具列表不能代替后端鉴权。

- 在产生副作用前校验调用身份、目标资源、参数与批准范围。执行策略来自可信配置，不接受模型参数作为豁免。
- 本地执行本身不是错误。需要隔离时，优先用执行环境限制文件、网络和进程；路径字符串检查不足以覆盖符号链接与竞态。
- 第二个执行后端或明确迁移需求出现时，才抽取执行接口。通用 `read/write/exec` 接口本身不构成沙盒。
- 仅对实际需要休眠或快照的后端设计生命周期。区分业务活动与监控流量；恢复互斥、快照一致性和清理失败须符合后端契约。
- 在统一执行边界放置鉴权、输出处理与清理。拦截应返回明确拒绝；会改变操作含义的参数改写须重新校验授权，并留下记录。

OpenAI 的 [Guardrails and human review](https://developers.openai.com/api/docs/guides/agents/guardrails-approvals) 说明检查的作用范围；并行检查不能保证在副作用发生前阻断。审批与安全检查须覆盖真正执行操作的工具边界。
