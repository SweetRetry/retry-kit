# Agent Engineering

Harness 指 Agent 的执行宿主。将规则放在能执行或验证它的责任层：提示词指导判断，工具契约减少歧义，执行代码强制权限和资源限制，行为评估检验任务效果。代码约束能保证具体边界，不能保证模型的整体判断正确。

## 决策顺序

1. 明确验收结果、允许的副作用与任务范围。
2. 选择能满足验收的最简结构。
3. 用执行证据定位问题所在的责任层。
4. 修改该层，并验证原问题和相邻正常路径。

已有系统先定位缺口，再决定是否调整结构。审查交付证据、影响与建议；实现或已授权修复交付修改和验收结果。这些原则用于被研究的系统，不自动改变本次任务的权限或执行流程。

### 选择结构

| 需求 | 优先结构 | 增加复杂度的依据 |
| --- | --- | --- |
| 单次生成、分类或检索可满足验收 | 单次模型调用，可配检索 | 单次调用在代表性任务上不足 |
| 步骤和分支已知，需要可重放 | 代码编排的工作流 | 某个步骤需要根据环境反馈探索 |
| 下一步依赖执行结果，路径难以预设 | 单 Agent 执行循环 | 存在可独立交付的并行瓶颈或上下文负担 |
| 子任务独立，收益超过协调成本 | 多 Agent，按所有权选拓扑 | 用行为评估证明收益，而非按文件数拆分 |

确定性工作流可以包住 Agent 步骤。采用 SDK 时核对项目版本、类型与运行语义；已有循环、审批和状态机制可满足需求时直接复用。

### 定位责任层

先沿失败轨迹找到首个偏离验收或边界的位置。区分模型选错、工具含糊、执行失效、上下文缺失与评估误判；证据不足时保留归因未确定。

| 当前问题 | 按需读取 |
| --- | --- |
| 循环终止、超时、重复调用、恢复、沙盒或权限失效 | [执行循环与运行时](references/harness-loop-and-runtime.md) |
| 工具选错、参数误用、结果歧义或局部编辑破坏内容 | [工具契约](references/tool-contracts-and-design.md) |
| 输出过量、压缩失忆、重复检索或缓存成本异常 | [上下文与记忆](references/context-and-memory-management.md) |
| 提示词冲突、停在计划、澄清或审批状态错误 | [提示词与人机协作](references/system-prompt-and-hitl.md) |
| 委托无收益、交接缺失、写入冲突或责任不明 | [子代理与委托](references/subagent-delegation-patterns.md) |
| 行为回归、结果无法核验或完成声明超出证据 | [行为评估与交付](references/verification-and-scoped-claims.md) |

只读取当前问题涉及的资料。参考资料区分官方机制与本 skill 的工程判断；涉及具体 API 时查当前官方文档，不把示例接口或供应商策略推广成通用要求。

## 交付标准

- 设计说明结构选择、责任边界和验收方式；为新增复杂度给出实际依据。
- 排障说明失败位置、证据与原因；修复后验证失败路径及正常路径。
- 行为规则改动使用原问题和一个无关任务做决策检查；检查措辞不能代替检查决策。
- 分开说明已完成工作、执行过的验证与剩余缺口。运行结束、预算耗尽和子代理返回均不等于任务完成。

结构选择依据：[Anthropic — Building effective agents](https://www.anthropic.com/engineering/building-effective-agents)。采用其简单性与工作流判断；SDK 能力以当前文档为准。
