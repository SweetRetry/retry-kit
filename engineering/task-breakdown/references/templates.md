# Task Breakdown Document Templates

用仓库事实替换占位符，按任务展开表格行；不适用字段可省略，未知项显式标记。能力画像与执行规则见 [执行契约](execution-contract.md)，配置须映射到宿主实际参数。

## 1. 任务总览模板 (`00-overview.md`)

````markdown
# 任务总览：{Task Name}

> 路径：`docs/tasks/{taskfolder}/` | [Human 看板](kanban.html)
> 需求来源：{来源及版本} | 当前规格版本：{版本标识}
> 关联记录：[`issues.md`](issues.md) · [`legacy-burdens.md`](legacy-burdens.md) · [`changes.md`](changes.md)

## 1. 目标与范围
- **核心目标与现状**：{当前问题与可观察的目标结果}
- **本次范围**：{要改变的行为}
- **非本次目标**：{明确排除的工作}
- **关键决策及权衡**：{影响本次实现的决策与原因}

## 2. 实体、业务规则与数据规模
- **核心实体及契约来源**：{实体、关键字段、权威定义路径及版本}
- **不能破坏的规则**：`[INV-01]` {规则、适用场景}
- **生产数据规模与性能约束（涉及数据访问时）**：{表、量级、查询规模、延迟要求及来源；未知项}
- **数据库核查依据**：{Schema/Migration/DDL 路径，相关索引名称与字段；需验证的查询计划}

## 3. 交付行为、任务依赖与责任人

交付切片以合并后的业务行为验收；执行任务按语义归属分工，一个切片可对应多个任务。

| 交付切片 | 触发条件与预期结果 | 相关失败状态 / 规则 | 执行任务 | 集成验收责任人 | 验收方法 |

- **集成分支与责任人**：{目标分支、负责合并和相关检查的人}

| 任务编号 / 文件 | 所属切片 / 目标 | 复杂度画像 (Profile) | 前置任务与启动条件 | 可并行任务 | 写入范围及责任人 | 验收条件 / 细化条件 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |

| :--- | :--- | :--- |
| {类型、入口、迁移、依赖及锁文件、测试库或端口} | {任务或责任人} | {任务编号} |

## 4. 执行汇报与恢复

主控核对 Agent 汇报后更新 [`kanban.html`](kanban.html) 内的 `board-data` JSON。任务启动、状态或阻塞变化、审查结论、集成验收和交接都需汇报；当前进度不在本文件重复维护。

任务状态：`Todo → Implementing → Verifying → Reviewing → Ready → Integrated`；受阻时标为 `Blocked` 并记录恢复条件。
`Ready` 需当前版本的验证与审查明确通过；`Integrated` 需合并后相关检查通过。交付切片的业务验收单独记录，不能由任务状态推定。

- **恢复断点**：{分支、base/head、未提交改动、进行中的操作与下一步}

恢复时核对断点与实际现场，再由主控更新看板。外部副作用确认执行状态后再决定是否重试。

## 5. 完成验收与最终审查
- [ ] 所有交付切片在集成版本上通过业务验收，相关失败状态已覆盖；
- [ ] 必需验证与审查有版本绑定的证据，修复或契约变更后的受影响检查已更新；
- [ ] 本次新增复杂度已在局部收敛，规则及数据库性能审查通过；
- [ ] 无未解决阻塞，当前规格与变更记录一致；必要的临时兼容有移除条件和责任人；
- [ ] 集成完成且无未提交工作后清理临时 Worktree，证据保留；
- [ ] 最终审查给出 `SIGN_OFF`。

```yaml
role: "Final Reviewer"
context: "docs/tasks/{taskfolder}/00-overview.md"
target: "{集成版本及相对基线}"
prompt: >
  在目标集成版本上核对交付切片、业务规则、跨任务交互与共享状态，寻找整体目标遗漏。
  复用覆盖仍有效的局部审查证据，补查后续变动及集成产生的影响。
  运行项目要求和风险相称的回归，说明未运行或失败的必需检查；既有失败须有基线证据。
  涉及 DB/ORM 的改动核验 Schema/Migration/DDL 中的具体索引与查询约束；单测不能代替性能证据。
  核对阻塞、临时兼容、规格变更及 Worktree 清理条件。
  输出 SIGN_OFF 或 REJECTED，附目标版本、覆盖范围、证据位置与最小修复建议。
  SIGN_OFF 仅表示验收通过，不代表已发布或获得发布授权。
```
````

## 1. 派发配置

```yaml
role: "Task-{X} Executor"
cwd: "{实际工作目录}"
profile:
  complexity: "{低 | 中 | 高}"
  tier: "{fast | standard | reasoning}"
  effort: "{off | low | medium | high}"
budget: "{按任务不确定性设置的时间或工具预算，注明宿主是否强制执行}"
permissions: "{实际权限；仅为执行约定的只读路径需明确标注}"
prompt: >
  按本任务的上下文、写入范围与验收条件执行，先核对前置证据及规格版本。
  启动、状态变化或受阻时向主控汇报任务编号、当前版本、进展及下一步；只由主控更新 HTML 看板的数据区。
  在已有语义归属处实现，检查本次新增的重复规则、无用途扩展点、转发层和应删除的旧路径。
  同一修补思路无增量失败两次时停止该思路，交接失败证据及下一种诊断方向；有新证据时在预算内继续。
  完成相关验证后形成语义完整的提交，回传版本、验证结果、未解决项和证据位置，进入 Reviewing。
  预算耗尽或外部阻塞时记录现场与恢复条件，不将未完成工作标为 Ready。
```

## 5. 审查配置

```yaml
role: "Task-{X} Reviewer"
base: "{审查基线}"
head: "{目标提交}"
permissions: "{由宿主落实的只读权限；未落实则注明执行约定}"
prompt: >
  审查整个任务相对基线的改动及相关调用方，核对业务规则和真实可达缺陷。
  检查测试 diff：不得为通过检查弱化断言、跳过必需测试、吞错或以假实现代替真实行为；
  需求变化引起的验收更新须由验收责任人按新契约同步，正常测试 fixture 不算假实现。
  涉及 DB/ORM 时检索 Schema/Migration/DDL，指出匹配的具体索引及字段，核查大表关联、
  无条件 LATERAL JOIN、全表扫描、N+1 与无分页全量加载；缺少必要索引且未补迁移时 BLOCKER。
  核对历史包袱处置和局部复杂度；明确且范围内低风险可消除的问题给出最小修复，
  纯风格偏好不挂单，跨范围治理只记录有证据的收益与代价。
  输出 PASS / PASS_WITH_SUGGESTIONS / BLOCKER，附 base/head、覆盖范围、验证与数据库证据。
  缺少必需证据时保持 Pending，不能按“未发现 BLOCKER”推定通过。
```

修复、rebase 或契约变动后复核证据覆盖，失效部分补查；审查与验证明确通过才进入 `Ready`。
