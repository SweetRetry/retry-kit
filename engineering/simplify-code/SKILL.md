# Simplify Code

## 1. 核心心智模型 (Mental Model)

代码简化的唯一目标是**缩短人类阅读、理解与排障的认知路径**。
- **简单 ≠ 行数少**：缩短行数若引入了隐式控制流、动态反射或黑盒状态，属于劣化；线性、显式且跳转少的代码才是真正的简单。
- **服务当前变化**：怀疑一切为假想未来预留的扩展点。当前无第 2 种真实演进需求时，保持单路径实现。
- **重构半径限制**：超出已授权范围，或改变公共契约、并发/事务机制及异常语义时对齐；范围内的调用方同步修改直接完成。

## 2. 四步审查与裁决流程 (Four-Stage Review Flow)

### 步骤 1：追踪理解路径与跳转深度
- 沿着核心业务动作的入口向下追踪，统计读懂一个完整业务行为所需的**函数跳转次数**。
- 若完成一个普通动作需要连续跨越 4 次以上无实质业务计算的转发/改名函数，标记为**高跳转过深调用链**。

### 步骤 2：过滤必要非功能复杂度（安全白名单）
在判定前，必须先剔除以下具备正当工程理由的“必要复杂度”：
1. **性能特化路径**：经过 Benchmark 验证的位运算、无锁设计、对象池或批处理优化；
2. **纵深防御校验**：边界处的防御性输入清洗、安全防注入与权限双重校验；
3. **领域防腐隔离**：防止底层库/外部协议污染核心业务的 DTO/BO/Entity 映射转换；
4. **语言级显式契约**：语言规范要求的显式错误处理与资源释放（如 Go 的 `if err != nil`、`defer`、Rust 的 `Result` 匹配）。

### 步骤 3：对照六大重构靶点确定动作
识别代码中纯粹由于“过度设计”或“历史堆砌”产生的偶发复杂度：

| 复杂度靶点 | 典型症状 (High Value Signal) | 合理例外 (Exclusion) | 推荐最小重构动作 |
| :--- | :--- | :--- | :--- |
| **无效抽象** | 单实现 interface / strategy；仅有一处调用的工厂类。 | 用作 Mock 测试、SDK 开放扩展点或框架 DI 必需规约。 | **内联消除**：移除 Interface，直接调用具体类/函数。 |
| **薄 Wrapper** | 跨层级仅做参数转发，未吸收任何复杂度或转换数据结构。 | 严格符合分层架构（如 Controller-Service-Repo）且职责独立的层。 | **拍平折叠**：调用方直接调用底层真实执行者。 |
| **错误抽象 / Flag 堆砌** | 同一函数/抽象为了适配不同语义，堆砌了大量布尔 Flag、枚举分支和未使用的配置项。 | 各分支处理完全同一业务概念且仅有极小参数差异。 | **拆分解耦**：按不同意图拆分为独立的专用函数。 |
| **隐藏主流程** | 线性业务步骤被大量的 Setup、临时变量转换与过度切碎的私有小方法打散。 | 单个步骤逻辑极其复杂（>50 行）且具备独立纯函数性质。 | **线性收敛**：将碎片化私有小方法内联回主流程，恢复线性阅读感。 |
| **假性复用** | 仅因 3 行代码形态相似就强行提取公共函数，导致处于不同生命周期的业务耦合。 | 稳定出现 3 次以上、语义完全一致且演进方向相同的通用工具函数。 | **解耦复制**：允许各业务分支保留适度重复，解除锁死耦合。 |
| **概念膨胀** | 文件数、类数与名词数量远超问题规模（如仅做 CRUD 却定义了 8 个类）。 | 因业务边界真实独立、各层职责明确而存在的多文件。 | **合并文件**：将强耦合的角色合并至单个文件/模块内。 |

### 步骤 4：严重级判定与单行交付
按排障阻碍程度与重构风险评级：
- **`High`**：严重阻碍排障/阅读，且存在低风险确定性简化路径（如无意义的 3 层转发包装）。
- **`Medium`**：结构失衡，但修改价值取决于该模块未来的变更频率。
- **`Low`**：存在微小冗余但无实质维护负担（严禁因个人代码风格偏好评为 Low）。

## 3. 审查红线（Prohibitions）

- **禁止盲目合并**：禁止仅因局部相似就合并生命周期与演进方向不同的业务逻辑。
- **禁止机械删除**：禁止看到单实现接口或分层转发就无视测试 Mock 或协议约束盲目要求删除。
- **禁止破坏稳定性**：严禁精简经过基准测试的性能路径或安全纵深防御代码。
- **禁止越界重构**：未经用户授权，禁止直接发起跨模块架构重组或破坏向后兼容性。

## 4. 输出交付规范

默认以单行极简格式输出 findings，不输出冗长套话。若无发现，仅输出 `未发现明确的 simplify findings`。

```text
- [High/Medium/Low] <文件路径:行号>: <问题根因说明> → <具体简化动作（内联/删除/拆分/合并/拍平）>
```
