# Simplify Code

缩短阅读、理解与排障路径；行数减少但控制流更隐晦不算简化。默认审查，已授权时实施。公共契约、并发／事务或异常语义改变时先对齐；范围内调用方同步完成。

## 判断顺序

1. 沿业务入口追踪完整行为；超过 4 次无实质计算的转发是检查信号，不是删除依据。
2. 保留有证据的必要复杂度：基准验证的性能特化、边界安全校验、协议与领域转换、语言要求的错误处理及资源释放。
3. 按下表选择最小动作；以当前真实用例为依据。

| 靶点 | 简化动作 | 判断前核对 |
| --- | --- | --- |
| 单实现接口、单调用工厂 | 内联为具体调用 | Mock、SDK 扩展或框架 DI 是否需要该契约 |
| 只转发参数的 Wrapper | 折叠无职责层 | 是否承担独立边界、转换或协议隔离 |
| 不同语义堆在 Flag／配置分支 | 按意图拆分专用函数 | 同一概念的微小参数差异可保留 |
| 主流程被碎片方法与临时转换打散 | 恢复线性流程 | 独立且复杂的计算仍保留函数 |
| 形态相似但生命周期不同的“复用” | 解除耦合，允许局部重复 | 语义与演进方向一致的真实复用保留 |
| 文件、类与概念远超问题规模 | 合并强耦合角色 | 真实独立业务边界保持分离 |

不按个人风格偏好报问题，也不仅因单实现或局部相似删除结构。超范围架构重组不属于局部简化。

## 交付

按维护阻碍和简化风险评级：`High` 表示明显阻碍且有低风险路径；`Medium` 表示价值取决于变更频率；`Low` 表示小但实际的维护负担。

每项一行：`[High/Medium/Low] 文件:行号: 根因 → 最小动作`。无发现时输出 `未发现明确的 simplify findings`。实施后说明保持行为不变的验证结果。
