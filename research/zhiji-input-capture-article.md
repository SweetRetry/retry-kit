# 吱几：AI 个人输入收口应用 — 定位与 MVP 设计

> 本文是围绕「吱几」（AI 个人输入收纳应用）的产品设计讨论的收敛文档。
> 内容涵盖竞品站位、定位决策、MVP 范围与核心分流模型，可作为产品 Spec 直接进入原型与验证。

---

## 一、问题（Problem Statement）

人的碎片输入是散点式的：微信随手一句「明天买牛奶」、刷到一句有启发的、浏览器收藏一个网页、语音里冒出的想法、邮件里一句关键信息……它们散落在不同渠道，且现有工具各占一个「点」：

| 散落点 | 场景 | 现有接盘工具 |
|---|---|---|
| 微信随手一句 | 聊天 | 没有（收藏了也不回流） |
| 刷到有启发的 | 微博/即刻/小红书 | 没有 |
| 收藏一个网页 | 浏览器 | Raindrop/Instapaper，但只收网页 |
| 冒出一个想法 | App/语音 | flomo（但入口只有 flomo） |
| 邮件里一句关键信息 | 邮箱 | 没有 |

用户是**场景驱动**的：不会因为装了 flomo 就只在 flomo 记，也不会因为装了滴答就停止在微信里收藏。于是「全景」缺失——**没有一个地方能看到「我所有的输入」**，而全景恰恰是个人管理与决策的起点：你只有先看到「我到底在想什么」，才知道该做什么。

更关键的是护城河问题：单条输入的意图解析（任务/提醒/想法分流）是**纯模型能力的直接应用，属于公共资产**——滴答、Siri、微信都只差「加一层 AI」就能复制。产品必须在模型能力之外建立**累积性优势**。

## 二、解决方案（Solution）

吱几是一款 **AI 个人输入收口应用**。

- **长期愿景**：全渠道 AI 收口（capture router）——所有碎片输入收进一个入口，AI 自动送到该去的地方（执行/想法/存档），并主动回流。护城河来自渠道汇聚、数据画像复利、时间复利与中立性。
- **MVP**：单一输入表面（Mac 全局热键）+ 完整智能层（三路分流 + 回流闭环）。
- **产品本体是「捕获之后的动作」**：分流 + 回流（每日回顾、关联提醒），而不是「输入更快」。
- **北极星价值**（后续叠加）：AI 复盘引擎——从积累的数据中生成周报、月度复盘、目标偏差提醒、重复模式发现。

一句话定位：

> **把散落在所有渠道的碎片收进一个入口，AI 既帮你行动（任务/提醒），也帮你复盘（周报/月度/目标偏差）——收口是入口，复利是灵魂。**

## 三、用户故事（User Stories）

1. 作为经常临时想到事情的人，我希望能随时随地用一个热键弹出输入框，以便不用打开 App、不用先想分类，把念头直接丢进去。
2. 作为用户，我希望输入后 AI 自动判断它属于任务/提醒/想法/存档，以便我完全不用手动整理。
3. 作为用户，我希望「明天买牛奶」自动出现在明天的待办里，以便到点被提醒、不会被忘。
4. 作为用户，我希望「想做产品 X」进入想法桶，以便之后被定期回看、发展。
5. 作为用户，我希望报价、名言、会议要点等外部信息进入存档，以便需要时能搜到、且平时不打扰我。
6. 作为用户，我希望每日回顾能推送旧想法回来，以便记录的念头产生时间复利。
7. 作为用户，我希望收到关联提醒（「你说过三次要做 XX，要不要现在定个时间？」），以便被自己忽略的念头能升级为行动。
8. 作为用户，我希望在「全部」视图里搜索所有输入（含存档），以便任何丢过的东西都能找回来。
9. 作为用户，我希望 AI 分错时能用长按/滑动轻量纠正，以便错误不积累、我不用忍受错的分类。
10. 作为用户，我希望纠正样本能回流成 AI 的训练数据，以便产品越用越懂我、路由越用越准。
11. 作为用户，我希望存档条目不出现在待办和回顾里，以便想法流不被外部资料污染。
12. 作为用户，我希望多个渠道（微信/浏览器/语音/邮件）的输入最终收进同一个入口，以便能看到自己的「全景总账」。
13. 作为产品，我希望渠道以「插头」形式接入、可插拔，以便不被任何单一平台绑架，核心资产（数据与画像）保持中立。
14. 作为产品，我希望三条桶的回流规则各自不同，以便「分桶」这个动作真正有意义，而不是假的分类。
15. 作为用户，我希望分流结果不弹分类标签提示（除非置信度低），以便保持「零整理」的体感。
16. 作为用户，我希望我的长期记录能生成对「自己」的洞察（复盘、模式发现、目标偏差），以便不只是存档，而是看清自己。

## 四、实现决策（Implementation Decisions）

### 4.1 定位与护城河

- **吱几不是 Mem 的近亲。** Mem 是 knowledge-first（产物是可检索的知识库，服务「回忆」），吱几是 action-first（产物是可执行/可回想的动作，服务「行动」）。判断轴：**AI 整理后的产物是可检索的知识，还是可执行的动作。** 共享的只有「AI 替你整理」的主张。
- **竞品站位**：执行×AI 象限是空白区，但也是「强约束战场」——AI 意图错了等于误事，信任一次崩塌。真正要盯的竞品是 **TickTick**（它往上走一步就是吱几），不是 Mem。
- **护城河不在单条意图解析**，而在四种累积性优势：
  1. **渠道锁死**：接了 8 个渠道后换产品 = 重接 8 个渠道；
  2. **画像复利**：路由与召回基于你的历史，用越久越准，这是通用模型给不了的；
  3. **时间复利**：回流质量依赖历史长度，「三个月前你说要做 XX」的提醒只有积累够久才存在；
  4. **中立性**：微信收藏做不了全渠道（不可能整合微博/小红书），滴答是执行工具接不了灵感/资料——只有中立的独立产品能做全渠道。
- **全渠道是长期愿景，不是 MVP 工作量。** 渠道是「插头」，按 ROI 逐个插入，不是一次性工程。

### 4.2 分流模型（核心）

三路分流，**按「后续动作」分，不按「内容类型」分**。分类太细但处理方式一样 = 假分类；分太粗则不同动作混一起，回流不准。

| 桶 | 定义 | 后续动作 |
|---|---|---|
| **执行** | 有完成动作，任务 + 提醒合并 | 进待办流，可挂时间（时间到即提醒） |
| **想法** | 我的念头/设想/疑问/灵感 | 定期回看、发展 |
| **存档** | 外部资料/事实/引用/信息 | 不回流，需要时检索 |

判定决策树：

```
这条输入，我能不能对它做一个「完成」动作？
├─ 能 → 执行（带时间 → 提醒）
└─ 不能 → 它来自「我的脑子」还是「外部世界」？
    ├─ 我的念头 / 设想 / 疑问 / 灵感 → 想法
    └─ 外部的资料 / 事实 / 引用 / 信息 → 存档
```

边界 case 规则：

| 输入 | 实际去向 | 原因 |
|---|---|---|
| 记住妈妈生日 5月20 | 执行（提醒） | 是时间事件，到点触发，不是留档 |
| 把这份资料发给小王 | 执行 | 有动作「发」 |
| 这句名言我想写进文章 | 想法 | 有发展意图 |
| 想读《XX》 | 想法 | 愿望，无具体动作 |

### 4.2.1 想法是「会生长的桶」

想法是三个桶里唯一有「演化」的：任务是离散的（做完即终），存档是静态的（存好即定），想法从「我想做 XX」到真正成事，中间跨几个月、十几条补充。因此：

- **想法 = 持续累积的线程（thread），不是单次快照。** 每条输入仍独立零摩擦捕获，AI 在后台把语义相关的记录聚合到同一线程。
- **持续留痕**：线程内每条补充带时间 + 来源（人补 / AI 补）+ 类型，点开想法看到的是它的演化史。
- **补充方式**：人主动补（在想法上追加）；AI 自动补（有关联/模式时异步 append 注记）；提到即挂载（新输入说「关于 XX 那个想法…」，AI 识别并挂到对应线程，原记录仍留在时间流）。
- **克制边界**：不要求用户管理线程（聚合全在后台，线程是点开才见的第二层）；AI 注记只在有真信息时发；冷掉的线程仍降级归档（见 4.4）。

### 4.3 界面模型

**页面不展示「三个桶」，展示「三种场景」。** 展示桶 = 让用户在「整理」，违背零整理承诺。用户感知分类的方式是「我丢了东西，它出现在对的地方」，而不是「它被贴了标签」。

| 场景 | 装什么 | 面客逻辑 |
|---|---|---|
| **待办** | 执行桶到期/未完成，按时间排，可勾选 | 「明天买牛奶」→ 出现在明天的待办 |
| **回顾** | 想法桶的每日回流 | 「想做产品 X」→ 过几天被推回来想 |
| **全部** | 所有输入的时间流 + 搜索/筛选 | 存档只在这出现，需要时来找 |

- 分流不弹标签提示（除非置信度低），条目自然落在对的地方。
- 纠正 = 长按/滑动换场景，轻量；纠正样本回流成训练数据。

### 4.4 回流规则

回流规则不同，分桶才有意义。

| 桶 | 回流规则 |
|---|---|
| 执行 | 到点触发 + 待办列表 |
| 想法 | 生命周期驱动（见下） |
| 存档 | **不回流，纯检索** |

存档那一路**故意不做回流**，这正是它存在的理由——避免把外部资料当灵感推给用户。

**想法的生命周期**（想法短暂：克制在「每条」，动作在「跨条」）：

```
捕获（零动作）→ 冷却期 7 天（不回流）→ 观察期（重复检测）
     → 回流（只推跨条有价值的）→ 过期降级（30 天 → 存档，退出回流）
```

- 捕获时刻零动作：不问、不展开、不提醒、不确认分类。
- 回流只推「跨条有价值」的，按优先级：重复出现 ≥2 次 > 过了冷却期仍活跃 > 上下文触发（记录到相关话题时）。不随机推。
- 静默降级：30 天未回看、未重复的想法自动进存档，退出回流。短暂的想法就该让它死掉。

**AI 回应原则**：只做「记得你」的回应，不做「接话」的回应；只异步做，不同步做。

- 捕获时刻不回（输入框清空就是「已收」的确认）。
- 异步回应落进**该想法的线程**（作为 AI 注记），不是往时间流丢孤立新记录。
- 回应必须有真实信息量（关联旧数据 / 模式检测 / 热度变化）；情绪确认、复述、通用建议都是噪音，不做。
- 给想法留「让 AI 展开」的入口，点击才展开——回应频率由用户控制（flomo AI 洞察的成熟模式）。

### 4.5 渠道与冷启动

1. **第一插头：Mac 全局热键**（⌥⌘Space 弹出输入框，200ms 摩擦）。自己就是目标用户，开发即验证。
2. **第二插头：微信输入**。验证「渠道插拔」架构，吃通勤/聊天场景。
3. **后续插头**：浏览器剪藏（网页自动进存档，带「未读」标记即可，不建阅读器）、截图、邮件、微博/即刻。
4. **每加一个渠道都要让用户看到回流**（「你在微信记的 3 条，我整理成了 X」），否则用户会以为只是个收藏夹。

### 4.6 AI 职责

意图识别、实体抽取（时间/人/金额/项目）、去重与关联、语义召回（按意思找，不是按关键词）、主动回流。

**检测管道（向量召回 + LLM 判定）**——关联 / 重复 / 热度的检查机制：

```
新输入 → 异步队列
  → 1. embed（新输入）
  → 2. 向量召回：和所有想法线程的 anchor 算相似度，取 top-k（低阈值、宽召回）
  → 3. LLM 判定（结构化输出）：候选里有没有「同一想法」？
        ├─ 无 → 保持独立
        └─ 有 → 「重复」还是「演化」？
               重复 → 线程计数 +1（触发「你说过 N 次」注记）
               演化 → append 到线程 + 更新 anchor（触发关联注记）
  → 4. 热度：对线程做滑动窗口计数（如 7 天），超阈值触发热度注记
```

- **向量只做召回**（把候选捞出来，任务「别漏掉真关联」）；**LLM 只做判定**（任务「别误合并」）。
- 「说 N 次」是线程计数，「热度上升」是滑动窗口聚合——管道建好后几乎免费。
- **重复 vs 演化**：高相似 + 短间隔 = 重复（值得提醒）；低相似但同想法 = 进展（append 而非计数）。判定交给 LLM。
- 异步批处理：检测不在捕获瞬间跑，攒批后台执行，省成本、不打扰。
- MVP 规模（几千条内）内存 numpy 余弦即可，不必上向量库；但架构按向量召回设计，作为长期底座。
- anchor 懒更新：线程被 append 后不每次全量重 embed，攒几次或只重算摘要。

## 五、测试决策（Testing Decisions）

- **分流准确率**：对历史输入构造测试集（含边界 case 表），回归测试三路判定；记录 AI 默认分对率与纠正率。
- **回流闭环验收（MVP 及格线）**：今天记的，明天被推回来，且用户认为有用、不觉得是垃圾。回流跑通前，加再多渠道都是白费。
- **冷启动指标**：主渠道渗透率、回流推送打开率、周留存。护城河（复利）以「回流有用」为先验，以「用越久越准」为长期指标。
- **边界 case 回归**：本 spec 4.2 中的边界 case 表作为固定回归集。

## 六、范围外（Out of Scope）

- 全平台、多渠道的一次性接入（渠道永远按 ROI 插）。
- 复盘引擎完整版（周报/月度/目标偏差）——北极星价值，需要数据积累后叠加。
- 协作、团队、复杂项目管理功能。
- 富文本编辑器、网页全文收藏、TODO 提醒体系。
- 决策副驾驶（thinking partner）方向——直接撞通用 AI 助手正面战场，当前不值得。

## 七、进一步备注

- **竞品站位图**：五款产品按「产物终点（回忆↔执行）× 整理责任（用户↔AI）」两轴分布——flomo（左下，轻记录+标签）、Reflect（左下，双链知识网）、Mem（左上，AI 组织知识库）、TickTick（右下，NLP 待办）、吱几（右上，执行×AI，空白区）。
- **三款对标产品**：flomo = 极简捕获 + 每日回顾（时间复利）；Mem = AI 自动组织知识库（检索复利）；Reflect = 双链知识网 + 端到端加密（连接复利）。三者都站在「记录/知识」线上（retrieval-first），吱几站在「输入→动作」线上（action-first）。
- **两个必须克制的点**：
  1. 别做成收藏夹——克制存储、强化回访。收藏的体验要弱，回访的推送要强。
  2. 平台依赖——微信接口、剪藏能力随时可能被限，解法是渠道插拔式、智能层中立；丢了任何单一渠道，核心资产（总账 + 画像）仍在自己手里。
