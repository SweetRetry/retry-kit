# Seedance 2.0 与 2.5 视频 prompt 指南核查

- 日期：2026-08-16
- 问题：Seedance 2.0 与 Seedance 2.5 的官方 prompt／输入合同中，哪些差异必须进入 `video-prompt` 的模型 reference，而不能写入通用主文档？
- 来源范围：仅火山引擎官方文档；未使用第三方教程、社区经验或非官方 API 封装。

## 1. 官方来源

- Seedance 2.0：[Prompt Guide](https://docs.volcengine.com/docs/82379/2222480?lang=zh)、[Input Task Tutorial](https://docs.volcengine.com/docs/82379/2291680?lang=zh)。
- Seedance 2.5：[Prompt Guide](https://docs.volcengine.com/docs/82379/2607689?lang=zh)、[Input Task Tutorial](https://docs.volcengine.com/docs/82379/2607688?lang=zh)。
- 共同 API 参数与模型能力：[API Reference](https://docs.volcengine.com/docs/82379/1520757)。

## 2. 事实

### Seedance 2.0

- 单次视频为 4–15 秒；可输入图片、视频、音频和文字，但不能仅以音频发起。API 文档列出的 reference 上限为 9 张图、3 个视频、3 个音频。
- prompt 中以同类型上传顺序的 `图片N`、`视频N`、`音频N` 引用素材，不能以 Asset ID 代替。
- 官方把输入任务分为全模态参考、编辑视频和延长视频。编辑目标要直接写 `<视频N>`，不能写“参考<视频N>”；未说明的编辑部分默认保持不变。延长使用向前／向后延长的意图。
- 官方建议复杂内容按镜头顺序叙述：每镜依次交代运镜／切换、动作与表情、空间变化和音频，并说明精确时间戳控制不稳定。动作应有肢体、幅度、速度与前后承接；一个镜头优先一种主运镜。音乐、音效、台词、字幕分别有 `()`、`<>`、`{}`、`【】` 标记。
- 输入任务教程允许将时长设为 `-1`，由入口在有效范围内自动决定。官方常见问题将 ID 漂移归因于人脸参考与其他参考混用、人脸占比过小等，并建议使用独立清晰的人脸锚点。

### Seedance 2.5

- 单次视频为 4–30 秒或 `-1` 自动时长；最多 30 张图、10 个视频、10 个音频，共 50 个素材。视频、音频单个及各类型总时长不超过 30 秒；支持仅音频发起。
- 模型会由素材和正文识别任务类型。编辑、延长、严格首尾帧是有锁定任务；语义参考、多格分镜和独立关键帧属于无锁定任务。编辑需 adaptive ratio 和 `-1` 时长；延长需 adaptive ratio。
- 多素材使用上传顺序编号绑定身份和职责。多格分镜只提供故事层面的参考，推荐 15 格以下、干净的线稿并用正文补足；独立关键帧更严格对齐，第一句要明确关键帧顺序；首尾帧可通过对应角色获得严格对齐。
- 官方推荐的正文顺序是主体、地点、事件、题材／风格、特殊运镜，再按时间或镜头写动作、摄影机、对白和音效，最后补充全局设定。支持连续的秒级时间范围、时间点与相对时间；过密事件可能导致切镜或遗漏，时间戳不适合控制频次。
- 2.5 教程还列出 text-only、首尾帧和全模态入口的识别条件，以及素材一键成片、两段视频无缝转场和自由组合能力。素材建议包括：图片不超过 4K；主体音视频优先 1–5 个主体、5–10 秒；主体图片优先 1–8 个主体；主体较多时以拆分的单视图替代拼接多视图。

## 3. 推断

- 两个版本共享的叙事、素材职责、连续性、可观察动作与时间线原则可以保留在主文档；素材 token、模式触发词、参数锁定关系、时长和声音标记都是模型合同，必须留在各自 reference。
- 2.0 的“避免精确时间戳”与 2.5 的“支持连续时间范围”相互冲突，不能用统一的强制时间码策略覆盖。
- 2.5 的编辑／延长依赖任务分类和请求参数；仅通过 prompt 文字补救参数冲突不可靠，应让 reference 优先指出冲突。

## 4. 建议

- 维护独立的 `seedance-2.0-prompt.md` 与 `seedance-2.5-prompt.md`，并要求用户在只写“Seedance”且版本差异影响任务时明确版本。
- 主文档不得固化 `图片N`、`<视频N>`、声音符号或 Seedance 的时长；它只要求素材标识符合目标模型的合同。

## 5. 局限

- 本次验证的是公开文档，未在登录后的控制台实际提交请求；账户、区域或灰度发布的限制未纳入。
- API 页面可能更新模型上限或可用任务模式；进入实现或集成阶段前，应以调用时的官方 API schema 为准。
