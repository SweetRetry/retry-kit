# First-Run Experience 端到端示例

**产品背景**：DraftAI — 一款 AI 辅助写作工具。用户输入一段话，AI 帮助扩写成完整段落，并提供多个风格变体供选择。

本示例演示**同一个产品**在两种场景下的完整输出：先从零设计，再审查一个"有问题的初版"。

---

## 场景 A — 设计新 onboarding

### Step 1：判断场景

用户说："我的 AI 写作工具快上线了，想设计用户第一次进来的引导流程。" → **场景 A**

---

### Step 2：定义 aha moment

**初始提案（来自产品方）**："用户理解了 AI 可以帮他写作。"

**验证**：
- 具体？❌ — "理解"是抽象感受，没有可观察的动作或产出
- 可指认？❌ — 用户无法指着"理解"说"我做到了"
- 自主完成？❌ — 无法判断

**修正后的 aha moment**：

> 用户在输入框粘贴或输入一句话，点击"扩写"，看到 AI 生成的 3 个段落变体出现在屏幕上。

验证：
- 具体？✅ — 动作是"点击扩写"，结果是"3 个段落变体出现"
- 可指认？✅ — 用户可以指着屏幕上的内容说"这是我生成的"
- 自主完成？✅ — 无需人工演示

---

### Step 3：路径设计

**原则 1：最小入场成本**

规划中的注册流程（共 5 步）：

| 步骤 | 内容 | 性质 | 判断 |
|------|------|------|------|
| 1 | 填写邮箱 + 密码 | 账户创建必须 | 保留 |
| 2 | 邮箱验证 | 产品方安全需求 | **移后**（aha moment 后再验证） |
| 3 | 填写"你的职业" | 产品方数据收集 | **移后** |
| 4 | 选择"你主要写什么类型内容" | 产品方个性化 | **移后** |
| 5 | 进入编辑器 → 空白输入框 | 用户产出结果必须 | 保留（但有空白问题，见原则 2） |

步骤精简后：注册（1步）→ 进入编辑器（1步）→ 点击扩写（1步）= **3 步**，符合目标。

---

**原则 2：永远不让用户面对空白**

问题：当前设计是空白输入框，新用户进来不知道写什么。

预填充方案：

| 空白类型 | 预填充内容 |
|---------|-----------|
| 输入框 | 预填一句话示例："本次会议决定将项目交付日期延后两周，并调整优先级。" + 灰色提示文字"或输入你自己的内容" |
| 结果区 | 首次进入时展示一个"已生成的示例输出"（3个变体）旁边加标注"这是 AI 可以帮你做的" |

---

**原则 3：操作步骤 ≤ 3 步**

精简后路径：

```
注册填写邮箱+密码
    ↓
进入编辑器（输入框已预填内容）
    ↓
点击"扩写"→ 看到 3 个段落变体
```

3 步，达标。

---

**原则 4：等待期不留黑盒**

AI 生成需要 2-4 秒，设计进度反馈：

```
正在理解你的内容... （0.5s）
正在生成变体...     （1.5s）
即将完成           （0.5s）
✓ 已生成 3 个版本
```

---

### Step 4：留存锚点

**选择路径**：下一步行动

**选择理由**：DraftAI 的价值来自于积累使用习惯（越用越顺手），而不是单次产出一个可带走的文件。保存/分享都不符合——用户需要的是"继续写下一段"的动力。

**文案建议**：

```
✓ 你的第一段已生成！
[复制这段]  [继续写下一段]   ← 默认高亮"继续写"
```

---

### 输出报告

```
## First-Run Experience 设计方案

**产品**：DraftAI — AI 辅助写作工具

**① aha moment 定义**
- 用户动作：在输入框输入/粘贴一句话，点击"扩写"
- 用户看到：屏幕上出现 3 个 AI 生成的段落变体
- 验证方式：用户自主完成，无需任何引导提示

**② 注册 → aha moment 路径**

| 步骤 | 用户目标 | 潜在流失风险 | 是否可移后 |
|------|---------|------------|----------|
| 1 | 创建账户 | 低（必要） | 否 |
| 2 | 进入编辑器（含预填内容） | 低（已有内容可操作） | 否 |
| 3 | 点击扩写，看到结果 | 低（无摩擦） | 否 |

步骤总数：3 步 ✅

已移后：邮箱验证、职业填写、内容类型选择（共 3 步移到 aha moment 后）

**③ 空状态预填充方案**
- 输入框：预填示例文本"本次会议决定将项目交付日期延后两周，并调整优先级。"
- 结果区：首次加载展示示例输出，旁边标注"这是 AI 可以帮你做的"

**④ 留存锚点**
- 选择路径：下一步行动
- 选择理由：产品价值需积累使用习惯，单次产出不可带走
- 文案建议："✓ 你的第一段已生成！" + [复制这段] [继续写下一段]（后者高亮）

**⑤ 反模式排查**
- [x] 无功能导览遮罩
- [x] 注册前无多余信息收集（职业/类型均已移后）
- [x] 第一屏有预填内容可直接操作
- [x] 等待期有三阶段进度反馈
- [x] aha 后有明确"继续写下一段"引导
```

## 场景 B — 审查现有 onboarding（同一产品的"问题初版"）

**背景**：DraftAI 上线了一个版本，激活率只有 18%，产品团队说"用户进来之后不知道怎么用"。

**现有流程描述**：
1. 注册页：填邮箱、密码、姓名、职业、公司规模（5 个字段）
2. 邮箱验证（发送验证邮件，需跳出 App）
3. 欢迎页：播放一个 90 秒产品介绍视频
4. 进入编辑器：空白输入框，顶部有 8 个功能按钮，无任何提示

---

### Step 2：aha moment 确认

询问产品方："你们认为的 aha moment 是什么？"

回答："用户看完视频就应该懂了。"

**判断**：不满足 aha moment 定义——
- 具体？❌ — "看完视频"不是产出结果
- 自主完成？❌ — 被动观看不算独立操作

**修正**：aha moment 应为"用户点击扩写，看到 3 个段落变体出现"（同场景 A）。当前流程在注册完成后需要 3 步（视频 + 空白编辑器 + 摸索找到输入框和扩写按钮）才能到达，且用户面对空白编辑器时极可能已经放弃。

---

### 输出报告

```
## First-Run Experience 审查报告

**产品**：DraftAI（现有版本，激活率 18%）

**① aha moment 清晰度**
- 当前状态：未定义
- 问题：团队将"看完视频"当作 aha moment，但这不是用户的自主产出动作
- 建议：重新定义为"点击扩写 → 看到 3 个段落变体"

**② 路径步骤分析**
- 当前步骤数：注册（5字段）→ 邮件验证 → 看视频 → 空白编辑器 = 至少 6 步才能到达 aha moment
- Gap：超出目标 3 步，多出 3 步

| 步骤 | 类型 | 判断 |
|------|------|------|
| 注册5字段 | 3个字段为产品收集 | 移后：仅保留邮箱+密码 |
| 邮件验证 | 产品安全需求 | 移后：aha moment 后再验证 |
| 90秒视频 | 产品方教育 | 删除：用预填内容替代 |
| 空白编辑器 | 用户产出必须 | 保留，但加预填充 |

**③ 空状态问题**
- 有 空白编辑器问题（严重）
- 具体位置：注册完成后的编辑器首屏
- 修复建议：预填输入框示例文本 + 展示示例输出，具体内容见场景 A 原则 2

**④ 留存锚点**
- 当前状态：无（用户完成操作后无任何引导）
- 建议路径：下一步行动
- 文案："✓ 你的第一段已生成！" + [继续写下一段]（高亮）

**⑤ 反模式命中**

| 反模式 | 命中 | 严重程度 | 修复建议 |
|--------|------|---------|---------|
| 功能导览 | 否 | — | — |
| 注册即收集全部 | 是 | 高 | 注册仅保留邮箱+密码，其余移后 |
| 空状态无引导 | 是 | 高 | 输入框预填示例内容 |
| 视频代替体验 | 是 | 高 | 删除视频，用可操作示例替代 |
| aha 后跳首页 | 是 | 中 | 生成结果后展示"继续写"按钮 |

**⑥ 最高优先级修改建议**
删除欢迎视频页面，将编辑器输入框预填一句示例文本（"本次会议决定将项目交付日期延后两周"），
使用户进入编辑器即可直接点击"扩写"体验核心功能。
预期效果：将用户到达 aha moment 的步骤从 6 步压缩到 3 步，消除最大流失点。
```
