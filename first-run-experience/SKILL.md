# First-Run Experience

## 核心职责

只解决一个问题：

用户第一次进入产品后，怎样在尽可能少的阻力下拿到第一个可感知的价值结果。

不要把它扩展成：

- 通用产品策略
- 泛化转化率优化
- 纯视觉或文案 polish
- 尚未验证产品价值时的方向判断

## 最小输入契约

在开始设计或审查前，先确认至少有以下信息：

- 产品是什么，目标用户是谁
- 当前要做的是“设计新流程”“审查现有流程”还是“判断首次体验是否是激活问题主因”
- 首次体验发生在哪个入口
- 如果已有现有流程：用户拿到第一个结果前，当前有哪些关键步骤
- 如果是从零设计：目标里的 `aha moment` 大致发生在哪一步
- 当前证据是什么
  例如流程描述、截图、录屏、用户反馈、漏斗数据、激活数据
- 已知限制是什么
  例如权限、注册、支付、数据接入、团队协作、合规要求

如果以上信息明显缺失，不要直接输出方案，先补问题。

## Step 1：判断场景

先把请求归到以下场景之一：

| 场景 | 适用情况 | 输出重点 |
|------|---------|---------|
| **A：设计新 onboarding** | 产品还在设计，或用户明确要“从零设计首次体验” | 路径设计 |
| **B：审查现有 onboarding** | 已有流程、截图、描述，或用户明确要找流失问题 | 结构化审查 |
| **C：判断是否属于首次体验问题** | 用户问“激活率低是不是首轮路径的问题” | 归因判断 |

如果用户既没有提供现状，也没有明确要从零设计，先追问，不要假设。

## Step 1.5：证据等级与归因约束

对场景 B / C，不要把猜测写成结论。先把输入证据分成三类：

- **Observed**：截图、录屏、真实流程文本、产品内可见状态
- **Reported**：用户描述、团队口述、总结性说法
- **Inferred**：你基于上述信息推出来的判断

输出时遵守这三条：

1. 没有 `Observed` 时，避免下“确定是首次体验导致”的结论
2. 只有数据下滑、没有路径证据时，只能输出“可能与首次体验相关 / 暂不足以归因”
3. 任何 `Inferred` 结论都要补一句“它依赖哪些已知证据”

如果用户请求是“解释激活率低是否由首轮路径导致”，先判断问题是否发生在第一次价值出现之前：

- 如果问题主要发生在 `aha moment` 之前，优先作为首次体验问题处理
- 如果问题主要发生在 `aha moment` 之后，明确写这更像留存、产品价值或长期机制问题
- 证据不足时，不要硬归因到首次体验

## Step 2：定义 aha moment

在设计或审查任何流程前，必须先定义 `aha moment`。

`aha moment` 不是“用户理解了价值”，而是：

- 用户做了一个具体动作
- 用户看到了一个具体结果
- 用户能说出“这是我刚刚自己做出来的”

用下面的表快速判断：

| 检查项 | 合格标准 |
|------|---------|
| **用户自主动作** | 不是被演示、不是只看视频、不是只读说明 |
| **可见结果** | 屏幕上出现可指认的结果、输出、反馈或状态变化 |
| **首次价值** | 这是用户第一次真正感受到产品价值，而不是完成内部配置 |

如果不满足任一项，停下来补全，不得继续做路径设计。

对 B2B、协作型、数据接入型产品，额外注意：

- 不要把“管理员完成配置”误当成普通用户的 `aha moment`
- 应优先定义为“当前用户第一次独立看到的价值结果”

不合格时，按这个顺序补：

1. 指出不合格点：缺的是动作、结果，还是首次价值
2. 给出一个更具体的候选改写
3. 最多补 2 轮；仍不合格就阻塞

阻塞格式：

```md
## 阻塞说明

当前无法继续，因为 `aha moment` 仍未满足以下条件：
- <未满足项>

请先补充：
- 用户完成的具体动作
- 用户看到的直接结果
- 为什么这是用户自主拿到的第一次价值
```

## Step 3：路径设计四项原则

先统一分类术语：

- **用户产出必须**：这一步直接决定用户能否拿到第一个结果
- **产品方收集**：这一步主要服务于注册、画像、营销、权限、内部管理
- **可移后**：当前发生在 `aha moment` 之前，但判断为 `产品方收集`

### 原则 1：最小入场成本

在 `aha moment` 之前，只保留 `用户产出必须` 的步骤。

检查问题：

- 这一步是不是直接决定用户能否拿到第一个结果
- 如果删掉它，用户是否仍能完成 `aha moment`

如果答案是“能”，就把它判为 `可移后`。

### 原则 2：不让用户面对空白

首次体验里最危险的时刻通常不是失败，而是空白。

优先用预填充消除空白：

| 空白类型 | 默认解法 |
|---------|---------|
| 输入框 | 预填一个高质量示例，允许直接执行 |
| 画布/工作区 | 预置接近真实场景的示例内容 |
| 列表/数据 | 预置 2-3 条示例数据，展示“完成后长什么样” |

### 原则 3：从进入到首次结果，操作尽量不超过 3 步

超过 3 步时，不是直接指责“步骤太多”，而是逐步问：

- 这一步是 `用户产出必须` 吗
- 如果不是，为什么还在 `aha moment` 之前

### 原则 4：等待期不留黑盒

如果存在生成、加载、分析、处理等等待阶段，必须告诉用户：

- 正在发生什么
- 当前推进到哪一步
- 还差多少

不要只放 spinner。

## Step 4：aha moment 后的留存锚点

`aha moment` 发生后的短时间内，只选一个最合适的留存路径，不要三个都给。

可选路径：

- **保存/带走**
- **分享**
- **下一步行动**

选择顺序：

1. 如果结果离开产品后仍能独立产生价值，优先 `保存/带走`
2. 如果结果的价值主要来自传播、协作或展示，优先 `分享`
3. 如果当前结果只是第一步，真正价值依赖连续使用或积累，优先 `下一步行动`
4. 仍打平时，默认选更能把用户留在产品里继续前进的一项，并说明放弃另一项的理由

禁止把用户送回空白首页。

## 反模式速查

| 反模式 | 典型症状 | 优先诊断问题 |
|--------|---------|-------------|
| 功能导览代替体验 | 用户先看遮罩、提示、教学，再开始操作 | 用户几步之后才拿到结果？ |
| 注册即收集全部 | 一开始就要补全资料、验证邮箱、填画像 | `aha moment` 之前有几个 `产品方收集` 步骤？ |
| 空状态无引导 | 首屏是空白列表、空白画布、空输入框 | 第一屏是否有可直接操作内容？ |
| 视频代替体验 | 产品要求先看教程 | 用户能否在 3 步内自主产出结果？ |
| aha 后跳回首页 | 用户做完第一次成功后没有明确下一步 | `aha moment` 后是否只有空白首页或弱 CTA？ |

## 最小校准示例

只保留一个极短例子，避免模型照抄：

- 不合格的 `aha moment`：
  - “用户理解了产品价值”
- 合格的 `aha moment`：
  - “用户输入一句话，点击扩写，看到 3 个可用段落变体出现在结果区”

## 使用提醒

- `aha moment` 不合格时，先阻塞，不输出方案
- 优先做删减，而不是在首轮路径里继续加步骤
- 审查现有流程时，优先写“为什么这一步应该移后”
- 不要把这个 skill 用成通用增长诊断或产品定位分析
