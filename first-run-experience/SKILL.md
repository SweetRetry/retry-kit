# First-Run Experience

## 工作流总览

```
1. 判断场景   → 区分「设计新流程」还是「审查现有流程」
2. 定义锚点   → 明确 aha moment（跳过此步不得输出任何方案）
3. 分析/设计  → 按路径设计四项原则逐一处理
4. 输出报告   → 按场景选择对应的输出格式模板
```

每一步完成后再进入下一步。**不得在 aha moment 未定义的情况下跳到路径设计。**

---

## Step 1：判断场景

根据用户输入，判断属于以下哪种场景，后续输出格式不同：

| 场景 | 触发信号 | 输出格式 |
|------|---------|---------|
| **A — 设计新 onboarding** | "帮我设计引导流程"、"用户第一次进来应该看到什么"、产品处于设计阶段 | 结构化路径设计方案 |
| **B — 审查现有 onboarding** | "帮我看看这个引导"、"为什么用户流失"、提供了现有截图/流程描述 | 结构化审查报告 |

若输入模糊，直接询问："你是要设计一个新的引导流程，还是审查已有的流程？"

---

## Step 2：定义 aha moment（必做）

**在设计或审查任何流程之前，必须先确认 aha moment。**

> aha moment = 用户做了什么、看到了什么，会说"原来这个产品是干这个的，我需要它"

验证标准——aha moment 必须同时满足：

- **具体**：是一个可观察的用户动作或产出结果，不是"理解了功能"这种抽象感受
- **可指认**：用户可以指着它说"我做到了"
- **自主完成**：发生在用户独立操作之后，不是被演示之后

**如果 aha moment 不满足以上三条，停下来补全，不得继续输出路径设计。**

补全规则：

1. 先指出不合格点：是“不具体 / 不可指认 / 非用户自主完成”中的哪一项不成立。
2. 最多补全 2 轮；每轮都要给出一个更具体的改写候选，要求用户确认。
3. 若 2 轮后仍无法得到合格的 aha moment，停止设计或审查，输出：

```md
## 阻塞说明

当前无法继续，因为 `aha moment` 仍未满足以下条件：[具体列出未满足项]

请先补充：
- 用户完成的具体动作
- 用户看到的直接结果
- 如何确认这是用户独立完成而非被演示

在以上信息明确前，不输出 onboarding 方案或审查结论。
```

示例对比：

| 不合格（太抽象） | 合格（具体可验证） |
|----------------|-----------------|
| "用户理解了产品价值" | "用户点击生成，看到第一张 AI 图片出现在画布上" |
| "用户感受到了效率提升" | "用户将 5 个文件拖入，看到合并后的报告自动下载" |
| "用户知道怎么用了" | "用户发出第一条消息，收到了 AI 的第一个回复" |

## Step 3：路径设计四项原则

对场景 A（设计）按此清单逐项决策；对场景 B（审查）按此清单逐项比对现状，标出差距。

步骤分类术语统一如下，后文不得换词：

- **用户产出必须**：这一步直接服务于用户拿到第一个有意义结果，删掉后用户无法完成 aha moment。
- **产品方收集**：这一步主要服务于注册、画像、营销、权限合规或产品内部管理，不直接决定用户是否能拿到第一个结果。
- **可移后**：当前发生在 aha moment 之前，但判断为“产品方收集”，应移到 aha moment 之后。

### 原则 1：最小入场成本

注册信息能延后收集的就延后——邮箱验证、完善资料、付款信息，都可以在 aha moment 之后再要。

检查标准：用户在感受到价值之前，是否存在任何「产品方收集、对用户拿到首个结果无必要」的步骤？有则标记为「可移后」。

### 原则 2：永远不让用户面对空白

空白输入框、空白画布、空白列表是流失率最高的时刻。解法：预填充。

| 空白类型 | 预填充策略 |
|---------|-----------|
| 输入框 | 预填一个高质量示例，用户可直接提交体验结果 |
| 画布/工作区 | 预置一个接近真实场景的示例内容 |
| 列表/数据 | 预置 2-3 条示例数据，展示填满后的样子 |

### 原则 3：操作步骤 ≤ 3 步

从进入产品到产出第一个有意义的结果，操作不超过 3 步。

超出时，对每一个多余步骤问：**"这步是用户产出必须，还是产品方收集？"** 后者全部移到 aha moment 之后。

### 原则 4：等待期不留黑盒

任何需要等待的操作（生成、加载、处理），必须让用户感知到"在发生什么、还要多久"。

不只是 spinner——拆成阶段，让用户看到进度在推进（如"正在分析 → 正在生成 → 即将完成"）。

---

## Step 4：aha moment 后的留存锚定

aha moment 发生后的 10 秒是留存决策的关键窗口。

**选择最符合产品性质的一个路径，不要全给：**

| 路径 | 选择标准 | 示例文案 |
|------|---------|---------|
| **保存/带走** | 结果有实体价值，用户想复用 | "保存到你的库" / "下载结果" |
| **分享** | 结果适合对外展示或协作 | "分享给朋友" / "复制链接" |
| **下一步行动** | 产品价值需要积累、用户需要建立习惯 | "创建你的第一个项目" / "继续探索" |

选择依据：

- 结果是文件/图片/报告 → 保存/带走
- 结果是社交内容/作品 → 分享
- 产品是工具/工作流/数据积累型 → 下一步行动

若同时命中多个路径，使用以下裁定顺序，只输出优先级最高的一个：

1. 先看 **用户的下一次核心行为** 是“带走结果”还是“继续积累价值”。
2. 若结果离开产品后仍能独立产生价值，优先 `保存/带走`。
3. 若结果的价值主要来自传播、协作或外部展示，优先 `分享`。
4. 若结果只是第一步，真正价值依赖后续连续使用、配置或数据积累，优先 `下一步行动`。
5. 若仍打平，默认选 **更能把用户留在产品内继续前进** 的路径，并说明放弃另一路径的理由。

**不要在这个时刻让用户回到空白首页。**

## 反模式速查

| 反模式 | 症状 | 诊断问题 |
|--------|------|---------|
| 功能导览 | 用 tooltip 遮罩逐个介绍界面，用户还没操作就在"学习" | 用户完成了几步操作才看到结果？ |
| 注册即收集全部信息 | 第一步就要填完整资料、验证邮箱 | aha moment 之前有几个「仅为产品方」的步骤？ |
| 空状态无引导 | 用户进来看到空白，不知道从哪里开始 | 新用户第一屏有无可直接操作的内容？ |
| 视频教程代替体验 | 产品首屏放教程视频让用户先看 | 用户几步之内能自主产出结果？ |
| aha moment 后跳回首页 | 用户完成第一个操作后不知道下一步 | aha moment 后有无明确的下一步引导？ |

## 输出格式

### 场景 A — 设计新 onboarding

```
## First-Run Experience 设计方案

**产品**：[产品名称/描述]

**输出长度**：目标 300-500 字；只保留能直接指导设计落地的信息。

**① aha moment 定义**
- 用户动作：[具体动作]
- 用户看到：[具体结果]
- 验证方式：[如何确认用户独立完成]

**② 注册 → aha moment 路径**

| 步骤 | 用户目标 | 潜在流失风险 | 是否可移后 |
|------|---------|------------|----------|
| 1    | ...     | ...        | 否       |
| 2    | ...     | ...        | 是（移到 aha 后）|
| 3    | ...     | ...        | 否       |

步骤总数：X 步（目标 ≤ 3）

**③ 空状态预填充方案**
- [具体空状态类型]：[具体预填充内容]

**④ 留存锚点**
- 选择路径：[保存/带走 | 分享 | 下一步行动]
- 选择理由：[一句话]
- 文案建议：[具体按钮/提示文案]

**⑤ 反模式排查**
- [ ] 无功能导览遮罩
- [ ] 注册前无多余信息收集
- [ ] 第一屏有可操作内容
- [ ] 等待期有进度反馈
- [ ] aha 后有明确下一步
```

### 场景 B — 审查现有 onboarding

```
## First-Run Experience 审查报告

**产品**：[产品名称/描述]

**输出长度**：目标 350-600 字；优先写清楚问题、证据和单条最高优先修改建议。

**① aha moment 清晰度**
- 当前状态：[清晰 / 模糊 / 未定义]
- 问题：[如有]
- 建议：[如有]

**② 路径步骤分析**
- 当前步骤数：X 步（目标 ≤ 3）
- Gap：[超出几步，哪些步骤可移后]

| 步骤 | 类型 | 对应原则 | 判断 | 说明 |
|------|------|---------|------|------|
| 1    | 用户产出必须 / 产品方收集 | 最小入场成本 / ≤3步 / 不留空白 / 等待期不黑盒 | 保留 / 移后 | 为什么 |
| ...  | ... | ... | ... | ... |

**③ 空状态问题**
- [有/无] 空白首屏问题

- 修复建议：[具体预填充方案]

**④ 留存锚点**
- 当前状态：[有/无/不当]
- 问题：[如有]
- 建议路径：[保存/带走 | 分享 | 下一步行动] + 理由

**⑤ 反模式命中**
| 反模式 | 命中 | 严重程度 | 修复建议 |

| 功能导览 | 是/否 | 高/中/低 | ... |

| 空状态无引导 | 是/否 | ... | ... |
| 视频代替体验 | 是/否 | ... | ... |
| aha 后跳首页 | 是/否 | ... | ... |

**⑥ 最高优先级修改建议**
[单条，附具体改法：改什么、在哪里改、改成什么样]
```

## 参考示例（内联）

完整校准样例 1（AI 写作工具 DraftAI）：

### 场景 A：从零设计

1. `aha moment` 定义修正：
   - 错误定义："用户理解了产品价值"（抽象，不可验证）。
   - 正确定义："输入一句话 -> 点击扩写 -> 屏幕出现 3 个可用段落变体"（具体、可指认、可自主完成）。
2. 路径压缩（最小入场成本）：
   - Before：邮箱+密码+姓名+职业+公司规模 -> 邮箱验证 -> 欢迎视频 -> 空白编辑器（6+ 步）。
   - After：邮箱+密码 -> 进入预填编辑器 -> 点击扩写（3 步）。
   - 处理：职业/公司规模/内容偏好全部移到 aha 之后。
3. 空状态修复：
   - 输入框预填真实示例文本，允许一键直接执行。
   - 结果区预置示例输出并标注「这就是你将得到的结果」。
4. 等待反馈：
   - 生成过程拆为可感知阶段（理解内容 -> 生成中 -> 即将完成），避免黑盒等待。
5. 留存锚点：
   - 首次成功后默认高亮「继续写下一段」，而不是把用户送回首页或仅提供“完成”。

### 场景 B：审查现有 onboarding

1. 问题流程：
   - 注册 5 字段 + 邮箱验证 + 90 秒视频 + 空白编辑器 + 8 个并列按钮。
2. 关键诊断：
   - 命中反模式：`注册即收集全部`、`视频代替体验`、`空状态无引导`。
   - 实际后果：用户在到达核心价值前流失，激活率长期偏低。
3. 优先改法（单条最高优先）：
   - 删除欢迎视频页；首屏改为预填编辑器；用户进入即能点击“扩写”。
4. 验收标准：
   - 到达 `aha moment` 步骤数 `<= 3`；
   - 首屏无空白死区；
   - 首次成功后有明确下一步行为锚点。

完整校准样例 2（SaaS 数据看板 PulseBoard）：

### 场景 A：从零设计

1. `aha moment` 定义：
   - 合格定义："用户连接一个示例数据源后，看到今日核心指标和异常波动卡片自动生成。"
2. 路径压缩：
   - Before：注册 -> 公司信息 -> 邀请团队 -> 绑定真实数据库 -> 配置权限 -> 空白看板。
   - After：注册 -> 进入带示例数据的预置看板 -> 点击切换一个时间维度查看变化。
   - 处理：公司信息、团队邀请、真实数据接入全部移到 aha 之后。
3. 空状态修复：
   - 首屏不是空白看板，而是预置完整示例图表，并明确标注「连接你的数据后会替换这些示例」。
4. 留存锚点：
   - 选择 `下一步行动`，引导用户“连接你的真实数据源”，因为核心价值依赖持续接入与后续监测。

### 场景 B：审查现有 onboarding

1. 问题流程：
   - 注册 -> 填公司规模 -> 邀请同事 -> 选择部门 -> 空白看板 -> 教程视频。
2. 关键诊断：
   - `公司规模 / 邀请同事 / 选择部门` 都属于 `产品方收集`，违反 `最小入场成本`。
   - `空白看板` 违反 `永远不让用户面对空白`。
   - 到达首个可感知结果超过 3 步，违反 `操作步骤 ≤ 3 步`。
3. 优先改法（单条最高优先）：
   - 首屏直接改成带示例数据的预置看板，用户无需配置即可先看到趋势图和异常提醒。

完整校准样例 3（任务管理 App FocusFlow）：

### 场景 A：从零设计

1. `aha moment` 定义：
   - 合格定义："用户点击示例任务上的开始专注，看到 25 分钟计时启动并在结束后自动记录一条完成记录。"
2. 路径压缩：
   - Before：注册 -> 选择职业 -> 选择目标 -> 创建项目 -> 创建任务 -> 才能开始计时。
   - After：进入应用 -> 使用预置示例任务 -> 点击开始专注。
3. 留存锚点：
   - 选择 `下一步行动`，引导用户“创建你的第一个真实任务”，因为价值来自持续使用与习惯形成。

### 场景 B：审查现有 onboarding

1. 问题流程：
   - 首屏要求先建项目，页面为空，且必须开通知权限后才能继续。
2. 关键诊断：
   - `建项目` 若不是立即开跑计时所必需，则属于可移后的 `产品方收集`。
   - 空白任务列表违反 `永远不让用户面对空白`。
   - 通知权限若不是计时启动前必需，应改为首次完成后再申请。
3. 优先改法（单条最高优先）：
   - 首屏预置 3 个示例任务，用户点击即可直接开始一次专注，再在完成后引导创建自己的任务。

如果方案在以上任一项不达标，先按 Step 2 的阻塞规则处理；只有 `aha moment` 合格后，才能回到路径设计与审查。
