# Architecture

## 基线

- Turborepo + pnpm workspace。
- `apps/*` 是可独立运行和部署的进程，`packages/*` 是被多个应用共同消费的能力与契约。
- TypeScript 全栈，前后端共享契约包，不共享有副作用的初始化。

## 归属规则

- `apps/*` 拥有进程入口、部署适配、切面装配和应用专属业务模块。鉴权、数据库 schema 与 migration 属于 server 应用。
- `packages/*` 只在已经存在多个消费者时才建立，不以潜在复用性拆包。代码在出现真实的跨边界消费者之前留在所属应用。
- 应用只经 package 的公开 exports 使用能力，不导入 package 内部文件。
- package 不启动进程级资源，也不聚合跨 runtime 的配置。环境变量由所属应用校验，SDK 的构造与启停留在应用。
- 本地开发通过 package 的 `development` export 直接消费 TypeScript 源码，发布构建使用编译后的 default export。

## Composition root

每个应用的 `src/index.ts` 是进程入口。它读取并校验自身环境变量，装配资源，注册关停流程。跨切面行为在这里显式组装，不由公共模块隐式启动。

新增应用需要同类装配时复制这段代码，不提取成公共启动函数。几十行的重复换来的是服务名、环境变量来源和关停时机在应用内可读。

## 新增抽象

- 先用一条完整纵切验证需求，再决定要不要抽象。
- 自行实现前先查现有依赖的文档、类型与扩展点，优先维护活跃、经过生产验证的成熟库。
- 目录名承担分组与语义前缀。目录已表达领域时，文件名只写目录内的具体职责，如 `canvas-commands/generation-handlers.ts`。

## 资料落点

| 内容 | 位置 |
| --- | --- |
| 长期架构取舍与备选方案 | `docs/adr/`，命名 `NNNN-slug.md`，推翻时新增取代关系而不改历史 |
| 外部资料调研 | `docs/research/` |
| 未定型或时机未到的计划 | `docs/future/`，每份写明问题、候选方案与触发推进的条件 |
| 系统说明与使用知识 | `docs/` |
| 强制工程约束 | `rules/` |
| 构建、seed 与 Agent 自定义工具 | `scripts/` |
| 项目术语 | `CONTEXT.md`，只存当前有效的定义，有易混用词时用 `_Avoid_` 列出 |

ADR 只记录会长期约束架构、存在重要取舍且无法从代码还原的决策。工具用法、依赖清单和可局部调整的约定写在 README、`AGENTS.md` 或代码里。

## 规则的写法

- 每条规则都应能据此做出一个决定，写清适用边界和必要例外。
- 取值离散的领域列出全部可选值及其用途，并配越界禁令。只有表没有禁令的规则会退化成参考手册。
- 同一约束只说一次。依赖 API 查文档与类型，不复制能力清单。
- 能写成测试或类型的不变量优先写成测试或类型。源码正则扫描只在边界明确且误报率低时引入。
