# Visual System

## 字体与数字

- 从阅读角色选择项目既有字阶与字重：正文、结构标题、核心焦点彼此可辨；不把列表每行都升级为标题，不大面积加粗正文。
- 消费项目发布的字体与字号 token。现有档位不足时明确缺口，在其扩展机制内处理；不在调用点另造字体体系。
- 金额与统计列用等宽数字、统一对齐基准，表头同步对齐；动态数字必要时预留宽度。仅需数字等宽时不把整段内容设为等宽字体。

## 色彩、表面与主题

- UI 添加的高显著色承担状态、分类或主操作职责。语义在全应用一致，状态同时有文字或形状依据。
- 主体、辅助结构与焦点的视觉重量可区分。编辑器或高彩度内容界面让框架退位；品牌页与数据分类按真实用途用色，不机械套统一面积比例。
- 先判断基底、持久分区、抬升内容或临时浮层，再选择对应语义 token；不以“更暗”“嵌套”或 `accent` 代替表面职责。
- 验证亮暗主题中相邻表面、文字、边界与焦点可辨；强制颜色模式沿用系统颜色。改 token 时在其权威定义处修改，不在业务调用点硬编码覆盖。

## 圆角与形态

- 选择与组件角色一致的圆角档位；固定高度控件明确采用圆角矩形或胶囊，避免同类控件形态漂移。
- 对齐的嵌套轮廓按外圆角减去间距与边框推导内圆角，再映射到项目阶梯；间隙超过外圆角时不机械保留内圆角。
- 光学补偿只在有可见偏差的局部处理，不传播为全局特例。增强形态只在目标浏览器支持时使用，保持项目要求的基础表现。

## 判断完成

检查字阶与焦点、数字对齐、状态语义、主题对比和嵌套轮廓。单一外观问题只核对相关部分；统一风格不以覆盖组件变体或修改无关全局 token 为代价。
