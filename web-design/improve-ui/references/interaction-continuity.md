# Interaction Continuity

沿用户操作的时间轴，同时检查实际状态转换与用户感知。输入能得到最终输出，不代表中间过程可理解、可控制。

## 按实际状态追踪

| 阶段 | 判断门槛 |
| --- | --- |
| 触发前 | 操作文案说明具体动作；禁用时就近说明前置条件。 |
| 受理 | 按下时提供本地反馈。重复触发会重复扣款、创建或写冲突时检查防重；可安全重复或持续输入的操作不一律禁用。 |
| 执行中 | 按耗时与真实状态提供反馈，见下文。 |
| 成功或失败 | 结果本身清楚可见时无需额外 Toast。失败说明已知原因与可用恢复方式；原因未知或无法恢复时说明限制。 |
| 恢复与清理 | 提交、校验或网络失败时保留已填内容与选项。需播报的动态变化通过 `aria-live` 传达；涉及浮层焦点时读取 [overlays-and-navigation.md](overlays-and-navigation.md)。 |

### 等待反馈

- **小于 100ms**：直接完成，无需加载器。
- **100ms–1s**：局部反馈，避免全屏遮蔽上下文。
- **1s–10s**：反馈已知执行状态；进度与步骤须有真实来源。
- **超过 10s 或持续数据流**：用户需要停止且机制支持时检查取消契约，区分停止客户端等待与取消服务端工作。已支持后台运行或用户需要离开后跟踪时检查重入入口；新增取消、后台执行或持久进度须在授权范围内。

### 反馈形态

- 需要修正具体输入时，错误放在对应字段或输入区旁，关联错误说明；通知消失不应使修正依据消失。
- 无需修改输入的操作结果，可用短通知；结果本身清楚可见时不重复确认。同一动作避免原地错误与通知重复播报。
- 空数据、连接异常或页面失败等持续状态留在对应上下文，不能只靠会消失的通知。
- 局部等待由触发控件承载；跨页后仍需跟踪的任务才使用全局通知，并复用任务实例，完成或恢复时更新或移除，不叠加旧提示。
- 成功反馈不使用阻断模态；批量部分失败区分成功与失败数量，未知结果明确标出。

### 跨状态约束

- 快速切换、分页或筛选时，核对响应是否仍属于最新用户意图，避免旧请求覆盖新结果。
- 乐观更新失败时恢复真实状态并就近解释；仅在安全且已有能力时提供重试，不以刷新重置代替恢复。
- 不可逆高风险操作须在不可逆时点前确认影响范围，或提供有效撤销机制。
