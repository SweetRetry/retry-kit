# Information Design

判断当前用户需要哪些信息，以及何时、在哪里看到。以区块、字段或单句为单位；本 reference 决定信息取舍与披露，构图和措辞由对应专项规则处理。

## 1. 确定信息必要性

逐条问：“用户此刻缺这一条，会做错哪个判断或无法完成哪个操作？”

- 答不出具体后果时删除；不改为更委婉的解释。
- 用户已从当前任务、同屏或上一屏获得的信息无需重复。作者掌握的领域模型、权限与实现细节不构成呈现理由。
- 当前决定依赖的信息进入主视图。仅开票、仲裁、对账等下游任务需要的信息移到对应操作流或详情；不照搬数据库字段。

## 2. 检查判断缺口

按当前任务检查下列信息，不要求每个区块凑齐：

| 信息 | 判断门槛 |
| --- | --- |
| 对象与状态 | 能辨认当前对象、生命周期；环境或版本会改变判断时须可见。 |
| 代价与限制 | 扣费、配额、不可逆后果及阻断条件须在决定前可见。禁用原因就近说明。耗时仅在有依据且影响判断时提供。 |
| 原因 | 异常状态、数值或报错影响判断时，给出已知原因；未知时明确说明，不补造诊断。 |
| 后续结果 | 立即生效、异步处理或人工审批有区别时，说明落点及已知通知、耗时。 |

数值仅补充当前判断所需的单位、口径、周期、基准与因果。比较前确认口径和周期可比，区分百分比与百分点。新增事实须有材料、已确认规则或可复核计算；缺依据时指出来源缺口，将建议与事实分开。

空状态说明与任务有关的原因；仅在需要理解用途或存在下一步时补充价值说明与操作入口。已知临界状态影响操作时提前提示；新增监测或恢复能力作为建议交付。

## 3. 安排披露层级

以当前任务所需的信息集合为单位，同页可组合两种模式：

- **直接呈现**：遗漏会改变风险判断、展开会延误判断、任务要求穷尽核对，或多个变量须同时权衡。必要维度全量呈现，用分组与对齐支持比较和辨识异常。
- **按需展开**：可见信息已足够判断，其余信息仅供追溯或后续任务。入口与内容关联。

结论、对象与状态形成扫视锚点；支撑判断的依据与限制就近呈现；其余详情按需展开。Tooltip 只承载补充解释，不隐藏决定前必须知道的限制。
