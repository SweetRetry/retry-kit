# Overlays and Navigation

## 从任务选择载体

先确定内容是否需要直接可见；尚未确定时读取 [information-design.md](information-design.md)，再选择展开方式：

| 内容属性 | 载体方向 |
| --- | --- |
| 保留上下文、临时查看或操作 | 就地展开或锚定浮层 |
| 保留上下文、持续使用 | 内容流、折叠区、侧栏；互斥视图用切换 |
| 需要集中完成独立任务 | 模态或独立页 |
| 需要深链、分享或独立返回 | 独立路由 |
| 含输入或选择 | 可聚焦、支持键盘的载体，不能只用悬停提示 |

仅有一两个次要操作且直接展示更易懂时，无需增加收纳入口。同类任务沿用一致处理方式；高频主操作保持可达，不为简洁增加反复展开。

简单修改优先就地完成；认证、不可逆变更与复杂向导保留必要隔离。避免模态套模态，二级内容优先使用内部步骤、就地展开或符合组件契约的锚定浮层。

## 层叠与焦点

- 遮挡时先检查祖先层叠上下文、overflow、Portal 目标与挂载顺序，再调整项目层级 token；不靠任意增大 z-index 竞争。
- 局部重叠在容器内隔离；临时浮层按组件契约挂载。Tabs、折叠区与 Sticky 内容保持在所属内容流或滚动容器中。
- 固定导航、浮层、通知与遮罩按职责分层；可见浮层及其操作不得被裁切。通知使用应用规定的根挂载位置。
- 收纳入口有可识别名称；展开后键盘能到达内容。模态按组件契约管理焦点，关闭后返回触发点或其合理替代位置。
- 代价、不可逆后果、禁用原因与错误不能仅悬停可见。展开后的内容不推翻用户在收起态下作出的判断。

## 判断完成

同时检查收起与展开、键盘路径、窄屏、关闭返回及滚动后的遮挡。确认操作路径缩短后，关键限制、失败反馈与原有恢复能力仍可达。
