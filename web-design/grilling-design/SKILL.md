# Grilling Design

**事实自查，决策追问。** 从现有材料中核实事实，让用户只判断真正需要取舍的设计选择。每个推荐都要能追溯到受众、任务、内容、产品机制或既有视觉依据。

## 交付边界

默认只在对话中交付方向摘要，不生成设计文档、实现契约或代码。用户同时要求其他产物时，先完成本 skill 的方向确认，再按其要求继续。

## 1. 建立事实底座

先读取任务描述和当前任务允许访问的项目材料，核实：

- 界面的职责、目标受众、使用场景与主任务；
- 真实内容、关键状态和不可动项；
- 既有设计变量、组件、品牌资产与相邻界面形成的视觉依据；
- 用户已经表达的偏好、反目标与取舍。

把信息分成四类：

- **已确认事实**：有需求或项目证据支持，可直接使用；
- **有依据的推断**：说明依据，可用于形成推荐，但不冒充事实；
- **事实缺口**：无法从现有材料核实，且不同答案会改变方向；
- **设计决策**：不存在唯一事实答案，需要用户选择取舍。

先直接询问事实缺口；事实问题不提供猜测性选项或推荐。能够自行核实的信息不转问用户。不会改变方向的缺口记入未决项，不阻塞后续追问。

**完成标准：**每项会影响方向的现有信息都归入上述一类；所有会改变首轮设计决策的事实缺口已经核实。

## 2. 建立决策树

只把会实质改变结果的选择放入决策树，按依赖关系排列：

1. **设计目的**：用户怎样算成功，以及说服、高效操作、阅读理解、沉浸体验中哪一个是主目的。复杂界面可以分区采用不同目的，但只有一个主目的。
2. **用户旅程**：从进入到完成主任务的路径、第一焦点、关键动作，以及需要影响方向的加载、空态、错误或完成状态。
3. **视觉方向**：由目的和旅程共同决定的构图主张、层级、密度、色彩角色、排印与材质气质。
4. **取舍与边界**：方向带来的真实代价、不可动项、反目标和仍缺依据的参数。

需求中已经明确的选择直接标为已定；不适用于当前界面的分支说明理由后标为不适用。设计目的未定时，不追问依赖它的旅程与视觉选择；下游答案发生冲突时，重开最上游的冲突分支。

**完成标准：**每个会改变最终方向的分支都有依赖关系，并处于已定、待问或不适用状态；没有仅为显得完整而加入的问题。

## 3. 分轮追问

每轮询问当前依赖已满足、影响最大的待问决策。相关问题可以同轮提出；答案会改变另一题选项时，把后者留到下一轮。题号全程连续。

每题给出 2 到 3 个真正不同且可执行的选项，并说明各自会怎样改变界面。选项必须落到当前产品的内容、机制或场景，不能只替换色板、字体或装饰。推荐其中一个选项，用一句话指出其依据和主要代价；证据不足时明确推荐基于哪项推断。

每题依次给出连续题号、决策问题、2–3 个选项及其界面影响，最后给出推荐、依据与主要代价。

用户可以选择选项、回复“按推荐”、否决部分选项，或全部否决并说明原因。部分否决时把被否项记为反目标，仅在用户明确接受推荐时落定剩余选择；全部否决时根据原因重写该分支的选项。每轮回答后更新决策树，只追问仍会改变方向的分支。

进入视觉方向分支前，完整读取 [visual-grammar.md](references/visual-grammar.md)。用其中与当前界面相关的基线和反默认测试筛选选项与推荐，不把参考中的参数直接写入方向摘要。

**完成标准：**所有会改变方向的分支均由需求明确覆盖或经用户选择落定；没有把推荐、推断或沉默当成用户决定。

## 4. 交付并确认方向

决策树收敛后，在对话中依次交付：

1. **方向主张**：一句话说明该方向独有的主张，以及拒绝的类别默认；
2. **核心构图**：说明去掉标识和品牌名后，仍能由产品机制、内容与受众解释的结构；
3. **真实代价**：说明用户确认接受的主要取舍；
4. **相关上下文**：受众、设计目的与用户旅程要点；
5. **边界与未决项**：不可动项、反目标、依据缺口，以及尚未进入方向层的色值、字号、间距等参数。

请用户明确确认摘要；同一摘要已获明确确认且没有改变时直接继续，不重复确认。用户提出修正时，只重开受影响的最上游分支，并重新检查它的下游决定。

**完成标准：**用户明确确认方向摘要；摘要中的每项设计判断都能追溯到已确认事实或用户选择，未决项与边界可直接识别。
