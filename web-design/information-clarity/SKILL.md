# Information Clarity

判断当前呈现是否让指定用户在当前状态下识别对象、理解关系并作出正确判断。问题只在后续 action、反馈、时序、状态转换或恢复中成立时，不属于本 skill；信息结构导致用户错误预测 action 时，信息结构仍是根因。

默认只读。用户明确要求设计、重构或实现时，先固定 findings、展示模型与验收标准，再修改对应范围。

## 建立信息 contract

明确 actor、情境、目标、信息载体与当前状态。列出用户此刻必须回答的问题，以及答错、漏答或回答过晚的可观察后果。问题应落到对象身份与状态、对象关系、影响判断的条件、入口价值或作出决定所需的依据。

反向检查每个现有信息单元：它是否独立改变判断、解释异常、建立必要信任或支持下一步？没有独立责任或重复其他位置含义的内容是 noise candidate。

## 重建展示模型与获取路径

从用户问题确定持续存在的对象、对象关系、状态、范围、权限、时效、来源与结果。为每个信息单元指定用户语义、生命周期、authority 和呈现责任，再映射到技术数据；组件和存储结构不自动成为用户理解边界。

同一事实只有一个权威位置。其他位置只有在回答不同即时问题时才作为摘要、引用或历史快照保留。

对每个用户问题追踪：

**当前线索 → 预期价值与成本 → 入口或分组 → 到达内容 → 能否回答问题或判断是否继续深入**。

渐进披露只延后细节，不延后对象身份、核心含义、相关性和深入价值。

## 检查 invariant

| invariant | 成立条件 |
| --- | --- |
| **完备** | 当前判断需要的对象、关系、条件和依据都存在 |
| **可发现与定向** | 信息在需要时可察觉，入口、范围、位置和深入价值可预测 |
| **可区分与解释** | 对象、状态、来源、单位和术语不会被误认或要求猜测 |
| **关系与顺序** | 分组、邻近、层级和阅读顺序准确表达真实关系 |
| **信噪与优先** | 首要问题先得到回答，次要信息承担独立责任且不竞争注意力 |
| **一致与权威** | 命名稳定，事实来源和时效明确，不同位置不竞争真相 |
| **模态等价** | 在线性、窄屏或辅助技术呈现中，身份、关系和顺序仍成立 |

字数、元素数量、层级深度和组件选择只是线索。只有呈现实际缺失、遮蔽、分裂、冲突或误导必要信息时才构成问题；风险、资格、成本、合规和关键例外即使增加长度也可能是必要复杂度。

对 noise candidate 选择最小处置：无责任则删除；同义则合并；责任成立但展开过度则压缩；只对部分情境有用则延后；独立改变判断则保留。

## 验证与定级

根据根因选择最小证据：真实内容与任务、content audit、分类或导航测试、任务观察、日志、反馈或跨模态检查。主动寻找替代入口、用户已有知识、合法约束和其他能推翻候选项的证据。

每个 finding 形成：

**actor 与问题 → 所需信息 → 当前呈现 → 用户可得到的解释 → 后果 → 最高根因 → 证据**。

- **P0**：核心用户普遍无法作出必要判断，或被系统性诱导出高后果且不可恢复的错误判断。
- **P1**：核心问题无法回答、被误导或只能经高成本试探回答。
- **P2**：次要或条件性问题增加查找、比较、记忆或核验成本，但存在可靠恢复路径。

相同根因与最终后果只保留一条 finding。严重度由错误判断的后果、影响范围和恢复成本决定，不由字段、组件、点击或字数机械决定。

## 设计或实现

按 findings 先确定信息的保留、合并、压缩、延后与删除，再修正 authority、关系、分组、命名、顺序和默认层／详情层职责。用用户语义映射源数据后再选择组件；实现后用原用户问题与真实内容回归。

## 输出

先给出 `信息清晰度存在问题 / 信息清晰度成立 / 证据不足`，说明 actor、当前状态和首要用户问题。审查时按 P0 → P2 输出最影响判断的 findings；每项包含所需信息、当前呈现、后果、根因、处置、严重度与证据。最后列出已复核路径和会改变结论的未知项。用户明确要求建议、设计或实现时，再交付对应展示模型、源数据映射与可验证验收标准。
