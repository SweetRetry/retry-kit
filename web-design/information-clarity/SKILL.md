# Information Clarity

## 1. 核心心智模型 (Mental Model)

界面信息呈现的本质是**认知负荷管理与决策支持系统**。
界面的信息信噪比（Signal-to-Noise Ratio）决定了用户的理解速度与操作准确率：
- **两极分化陷阱**：
  - **盲目极简省略 (Under-informing)**：为了所谓的“视觉极简”，把关键代价、耗时、时效、限制、单位、原因或下一步隐藏省略，迫使用户靠猜或盲目试错。
  - **原始数据倾倒 (Data Dumping)**：把数据库字段、低频调试参数、长篇大论的背景说明不做任何提炼全倒在页面上，造成严重的认知过载与视觉混乱。
- **认知负荷三元控制**：
  - **外在负荷 (Extraneous Load) ➔ 坚决归零**：消除视觉杂音、低对比度装饰、无独立价值的占位符；
  - **内在负荷 (Intrinsic Load) ➔ 结构化解构**：复杂业务逻辑通过对齐用户心理模型分解为易读单元；
  - **相关负荷 (Germane Load) ➔ 有效赋能**：提供基准对比、趋势箭头、状态语义色与直接因果，帮助用户快速建立认知模型。

## 2. 数据升维语法：从原始数据到决策信息 (Data to Insight)

单纯的数字不是信息，只有具备上下文的数字才能支持决策：

| 原始数据 (Raw Data) | 决策维度缺失 | 升维后的有效信息 (Groundable Insight) |
| :--- | :--- | :--- |
| `82 ms` | 无基准，用户不知道好还是坏。 | `82 ms` `(P99 · 优于 SLA 200ms 阈值)` |
| `¥ 1,280` | 无明细与归属周期。 | `¥ 1,280 / 月` `(含 3 项核心服务 · 下期 10/15 自动续费)` |
| `转化率 1.2%` | 无历史参照与波动方向。 | `转化率 1.2%` `(较上周 ↑0.4% · 跑赢大盘均值)` |
| `提交失败` | 无原因与修复路径。 | `提交失败：文件大小超限（当前 15MB · 最大支持 10MB） · 点击重新选择` |

## 3. 用户“应该知道什么”：四维必要信息矩阵

按当前区块的任务，检查以下信息中哪些会影响用户判断；不要求每个区块重复提供四类信息。审查交付证据与建议，已授权设计或实现时才调整对应内容。

### 1. 身份与当前真实状态 (Identity & State)
- 我当前操作的对象是谁？处于什么明确生命周期（草稿/就绪/执行中/已归档）？
- 当前生效的环境与版本（测试/生产/最新发布/历史回滚）？

### 2. 代价、耗时与硬性限制 (Cost, Time & Constraints)
- **决策前呈现关键约束**：扣费、配额、不可逆后果及会阻断当前操作的限制，应在用户作决定前可见；其他细节按相关性渐进披露。预计耗时仅在有依据且影响判断时提供。
- 为什么按钮不可用？必须在禁用元素附近就近说明“缺少什么前置条件（如：需先绑定支付方式）”。

### 3. 因果解释：为什么是这个结果？ (Causal Explanation)
- 状态变更、数值异常或报错时，禁止只给孤立标签。
- 给出已知且人类可理解的原因与上下文；原因未知时明确说明未知，不补造诊断信息。

### 4. 预期落点：接下来会发生什么？ (Next Step & Consequences)
- 点击后是立即生效、进入异步队列还是等待人工审批？多久能完成？后续谁会收到通知？

## 4. 三层渐进披露与自适应密度 (Progressive Disclosure & Density)

| 层级 | 职责与呈现内容 | 呈现载体与交互 |
| :--- | :--- | :--- |
| **L1 核心锚点层 (Anchor & Verdict)** | 首要结论、对象身份、核心状态标签。 | 主视觉焦点（大字号、高对比度、语义色彩）。1 秒扫视即懂。 |
| **L2 支撑依据层 (Supporting Evidence)** | 支撑 L1 结论的核心参数、直接因果、限制条件、计算口径与时效。 | 次级文字、就近行内标签、轻量 Tooltip 微提示。3 秒理解因果。 |
| **L3 渐进深度层 (Progressive Detail)** | 完整历史快照、底层审计日志、高阶技术参数、原始 JSON 数据。 | 折叠面板、抽屉（Drawer）、模态详情。仅在用户主动钻取时呈现。 |

## 5. 临界态与空状态信息设计 (Edge & Zero States)

- **空状态 (Zero / Empty State)**：
  - 严禁留白板或只写“暂无数据”；
  - 说明与当前任务有关的空白原因；仅在用户需要理解用途或存在可执行下一步时补充价值说明与 CTA。
- **临界与预警态 (Degraded & Quota-Warning States)**：
  - 已知状态将影响当前操作时，在决策前提示相关限制；新增监测、预警阈值或恢复能力作为建议，仅在授权范围内实现。

## 6. 审查与输出交付规范

审查界面信息呈现时，按以下格式输出 findings：

```text
- [P0/P1/P2] [过分省略 / 数据倾倒 / 语义模糊 / 缺乏依据]: [简明问题描述]
  - 界面位置：[具体页面、卡片或组件]
  - 缺失或冗余信息：[指出省略了什么关键代价/状态，或堆砌了什么无用噪音]
  - 认知阻碍与后果：[用户在此处会产生何种误解、盲区、决策延误或误操作]
  - 升维与重构方案：[给出符合 L1/L2/L3 分层、带基准与因果的具体文案与布局设计]
```
