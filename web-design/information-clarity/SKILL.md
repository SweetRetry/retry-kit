# Information Clarity

## 1. 意图与阶段匹配门槛 (Intent-Task Stage Fit)

判定对象分两级，共用同一门槛：**区块级**（视窗、字段组，管堆砌与缺失）与**句子级**（标签、说明句、备注、空态文案，管多余解释）。后续各节对两级同样适用，只是比较单位从区块缩到单句。

界面上每一条信息进入主界面前，必须通过**即时决策相关性校验 (Decision Relevance Test)**：
- **核心判定标准**：“用户在此刻缺这一条，会做错哪个判断或无法完成哪个操作？”答不出具体判断或操作时删除，不改写为更弱或更委婉的表述。
- **作者已知不构成理由**：用户已从当前任务、同屏其他信息或上一屏获得的内容无需重复；作者上下文中的领域模型、角色权限与实现细节，不是用户需要它的依据。
- **处理策略**：
  - **当前主任务直接依赖**（如核对订单金额、查看履约状态、确认服务到期日）：进入主视窗直接呈现。
  - **仅下游/低频特异任务需要**（如开具发票、仲裁纠纷、底层对账）：**坚决移出通用主视图**。禁止按数据库字段惰性搬运；应延后至专属操作流（如“去开票”详情）、详情抽屉或按需自定义列。

## 2. 四维必要信息矩阵 (Decision-Critical Matrix)

通过意图校验后，按当前区块的任务检查以下信息中哪些会影响用户判断；不要求每个区块重复提供四类信息。审查交付证据与建议，已授权设计或实现时才调整对应内容：

### 1. 身份与当前真实状态 (Identity & State)
- 我当前操作的对象是谁？处于什么明确生命周期（草稿/就绪/执行中/已归档）？
- 当前生效的环境与版本（测试/生产/最新发布/历史回滚）？

### 2. 代价、耗时与硬性限制 (Cost, Time & Constraints)
- **决策前呈现关键约束**：扣费、配额、不可逆后果及会阻断当前操作的限制，应在用户作决定前可见；其他细节按相关性渐进披露。预计耗时仅在有依据且影响判断时提供。
- 为什么按钮不可用？必须在禁用元素附近就近说明“缺少什么前置条件（如：需先绑定支付方式）”。

### 3. 因果解释：为什么是这个结果？ (Causal Explanation)
- 状态变更、数值异常或报错时，禁止只给孤立标签。
- 给出已知且人类可理解的原因与上下文；原因未知时明确说明未知，不补造诊断信息。

### 4. 预期落点：接下来会发生什么？ (Next Step & Consequences)
- 点击后是立即生效、进入异步队列还是等待人工审批？多久能完成？后续谁会收到通知？

## 3. 数据升维语法：从原始数据到决策信息 (Data to Insight)

仅在缺少上下文会影响当前判断时，补充单位、统计口径、周期、基准或因果；已有信息足以支持判断时保持简洁。

新增事实须来自任务材料、已确认的业务规则或可复核的计算。依据不足时，指出缺少的来源或数据；建议补充的信息与已知事实分开呈现。

比较数值时确认口径与周期可比，并区分百分比与百分点。例如，同口径转化率从上周 0.8% 变为本周 1.2%，增加的是 0.4 个百分点，相对增幅为 50%；按当前判断需要选择表述。

## 4. 呈现架构决策：直接呈现与渐进披露 (Full Exposure & Progressive Disclosure)

以当前任务所需的信息集合为判定单位，同页可以组合直接呈现与按需展开。先确定哪些信息必须在决策前可见、哪些必须同时比较，再安排其余细节：

### 1. 呈现模式判定矩阵

| 模式 | 判定依据 | 呈现准则 |
| :--- | :--- | :--- |
| **直接呈现 (Full Exposure)** | 遗漏会改变风险判断；展开会延误即时判断；任务要求穷尽核对；或多个变量必须同时权衡。 | 直接呈现满足该条件的信息集合。通过分组、对齐与主次区分支持比较，使异常可辨识；全部维度均必要时全量呈现。 |
| **渐进披露 (Progressive Disclosure)** | 当前可见信息已足以支持判断，其余信息只在追溯、解释或后续任务中需要。 | 将这些补充信息放入按需展开的详情，并使入口与对应内容关联。 |

### 2. 信息层级与载体选择

以下是信息职责，按任务选用或合并，层数与样式沿用适合当前界面的结构。影响当前决定的限制直接可见；Tooltip 仅承载补充解释。

| 层级 | 职责与呈现内容 | 呈现载体与交互 |
| :--- | :--- | :--- |
| **核心结论 (Anchor & Verdict)** | 首要结论、对象身份、核心状态。 | 扫视时可识别当前对象与状态。 |
| **支撑依据 (Supporting Evidence)** | 当前判断依赖的参数、因果、限制、计算口径与时效。 | 与对应结论就近呈现，便于核对与比较。 |
| **补充详情 (Progressive Detail)** | 当前判断不依赖、仅用于进一步追溯的信息。 | 按需使用折叠面板、抽屉或详情页等载体。 |

## 5. 临界态与空状态信息设计 (Edge & Zero States)

- **空状态 (Zero / Empty State)**：
  - 严禁留白板或只写“暂无数据”；
  - 说明与当前任务有关的空白原因；仅在用户需要理解用途或存在可执行下一步时补充价值说明与 CTA。
- **临界与预警态 (Degraded & Quota-Warning States)**：
  - 已知状态将影响当前操作时，在决策前提示相关限制；新增监测、预警阈值或恢复能力作为建议，仅在授权范围内实现。

## 6. 审查与输出交付规范

审查界面信息呈现时，按以下格式输出 findings：

```text
- [P0/P1/P2] [过分省略 / 意图错位 / 数据倾倒 / 过度解释 / 盲目折叠 / 语义模糊 / 缺乏依据]: [简明问题描述]
  - 界面位置：[具体页面、卡片或组件]
  - 缺失、错位或冗余信息：[指出省略了什么关键代价/状态、错位暴露了什么无关字段、堆砌了什么无用噪音，或何处不当折叠导致漏检]
  - 认知阻碍与后果：[用户在此处会产生何种误解、盲区、决策延误或视觉杂音]
  - 调整方案：[指出哪些信息直接呈现、按需展开或移至对应任务，给出有依据的文案与布局建议]
```
