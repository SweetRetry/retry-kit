# Video Prompt

## 交付合同

一份 prompt 对应目标入口的一次 **generation**。一次 generation 可以是连续镜头或多镜序列；需要多次 generation 时，分别交付自包含 prompt，并在相邻段重复必要的承接状态。

本 skill 只使用当前任务附带或明确允许读取的意图、文字、图片、视频、音频与命名素材。视频媒介必须已由用户或当前任务确定；是否应使用 background video 属于另一个决策问题。

先确认目标模型和版本，再读取对应 reference；模型缺失且会改变素材模式、时长或写法时，先要求确认。

| 目标模型 | reference |
| --- | --- |
| Seedance 2.0 | [Seedance 2.0](references/seedance-2.0-prompt.md) |
| Seedance 2.5 | [Seedance 2.5](references/seedance-2.5-prompt.md) |
| MiniMax-H3 | [MiniMax H3](references/minimax-h3-prompt.md) |

reference 决定模型专属的素材 token、可用性、任务模式、时间写法、声音／文字标记与排版。它与主文档冲突时，reference 优先；不把任一模型的语法迁移到其他入口。

输入可执行时，最终回复只包含可直接粘贴的 prompt。输入存在素材、时长、时间线或职责冲突时，只返回具体冲突与需要补充的信息。

## 1. 定界 generation

- 先确定每次 generation 要表达的起点、主要变化和结束状态。
- 用户给出生成段或时间线时，保留其叙事划分；时间编码只采用目标 reference 支持的方式。不得为方便排版发明秒级时间戳。
- 内容超过单次可读时长时，在因果或场景断点拆分；每段必须能独立理解，并为下一段留下可继承的结束状态。
- 相邻 generation 承接时，重复身份、持物、位置、速度、屏幕方向、光线和声音等必要锚点。

## 2. 映射素材职责

先用“主体 + 动作或事件”确定内容基础，再只保留会直接改变成片的场景、道具、风格、构图、运镜、节奏和声音约束。按 reference 的 token 引用每份命名素材，写清其控制职责、必须保留的锚点、允许变化与作用范围。

- 角色素材默认控制身份与稳定外观；场景素材控制空间结构与主光；风格素材控制材质、色彩和影像气质。
- 动作／运镜视频只继承明确指定的动作路径、节奏或摄影机行为；音频只继承指定的音色、旋律、节拍、对白或环境质感。
- 多张素材定义同一对象时，写清各自视角与同一身份；对象数量由当前故事决定，不由参考图数量推断。
- 每个控制维度指定一个主来源。发生冲突时，优先服从用户对成片的明确要求、主体与关键物体身份、当前动作与空间逻辑，再是场景和风格。
- 风格参考转译为当前视频的光影、色彩、构图、镜头行为与运动节奏；不要只追加风格名称，也不复刻参考作品的现成调度。

## 3. 确定全局稳定设定

在叙事节拍前，先确定只需写一次的稳定语义：整体意图与情绪、主体身份与不能漂移的外观或关系、场景空间与主光、统一的视觉语言，以及贯穿全片的运动、声音和连续性锚点。

后续只写发生的变化；只在叙事断点或新 generation 的开头重申会影响理解或稳定性的锚点。全局设定与时间内变化可以按目标 reference 的写法合并呈现，但不能混淆其职责。

## 4. 组织叙事与镜头

先列观众必须理解的节拍，再决定单镜还是多镜。每个新目标、规则、地点或道具功能都要有“建立 → 可见验证 → 结果停留”的可读时间；时间不足时删除或合并次要概念。

- 相邻节拍能在同一机位、空间和连续运动中完成时使用单镜；机位、时空、视点或观看任务明确切换时才切镜或转场。
- 按目标模型允许的时间或镜头组织方式，顺序写少量关键变化。每一段只承担一个主要观看任务和一条连续因果动作链。
- 多镜或多段交接时，前一段的结束状态就是后一段的起始状态。动作、持物、位置、受力、道具、空间关系和声音变化都要有可见原因。

## 5. 写成可观察的状态变化

按发生顺序描述主体、摄影机、空间、光色、声音和与前后段的承接。以下是必须判断的语义覆盖项，不是要照抄给模型的固定字段：

1. 主体从什么状态开始，如何行动、反应并到达什么状态。
2. 摄影机从何处观察，如何移动，最终形成什么构图。
3. 环境、光色与焦点如何响应动作、空间或情绪。
4. 对白、环境声、Foley 和音乐在何时出现、增强或停止。
5. 上一状态如何自然延续，或为何能合理地转场到下一状态。

动作写位移、转身、接触、持物、速度、幅度和结果；情绪外化为表情、姿态、节奏、镜头或声音。静止画面也明确稳定项与必要微动。使用肯定、可见或可听的目标状态；无法转成正向状态的 hard exclusion，保留在最相关的句子中。

需求开放时，为次要微动作和背景填充保留空间；需求明确时，完整保留动作阶段、节奏、机位与素材职责。细节只在它会改变身份、连续性、主动作、关键空间关系、镜头、光色或声音时保留。

## 6. 渲染与检查

- 按目标 reference 的素材 token、任务触发词、声音／文字标记、时间写法和自然语言模板输出；没有模型专属模板时，按“素材映射 → 全局稳定设定 → 顺序状态变化”写简洁多行 prompt。
- 不强制 Markdown 标题、固定字段或固定字数；排版只服务于目标模型的可读性。
- 检查每份素材可用且职责清楚，稳定设定与状态变化没有混写，故事顺序与参考范围一致，关键状态能交接，镜头切换有叙事理由，声音与文字绑定到对应时段或动作。
- 最终 prompt 只保留会改变生成结果的内容，不附加解释、API 参数或另一模型的语法。
- 需要压缩时，先删修饰语、重复的风格描述和次要环境细节；不得删去素材职责、主体身份、稳定锚点、主要状态变化、镜头关系或连续性来换取更短的 prompt。
