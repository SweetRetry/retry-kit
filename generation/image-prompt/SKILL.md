# Image Prompt

把意图转为单张画面的视觉指令。先判断图像如何成立，再描述主体；摄影只是其中一种表现方式。

## 1. 确定交付物与视觉语言

先从请求、参考和使用场景确定三件事：

- **交付物**：成片、海报、角色设定、游戏截图、独立资产等。它决定信息组织与验收重点。
- **表现方式**：摄影、绘画、像素、渲染或混合媒介。它决定造型、空间、明暗与表面如何表达。
- **控制范围**：新建整张图，还是保留身份、改背景、换画法等局部编辑。

按实际任务读取 reference，不默认全部加载：

这些是判断入口，不是互斥分类。游戏美术先读游戏规则，再按其分支补媒介规则；海报中的照片可组合设计与摄影。混合时明确各规则控制哪部分，避免整张图同时套用全部风格。

“写实”可能指真实照片、写实绘画或写实 CG；“游戏风格”也不能确定资产类型。已有上下文时直接判断。缺失信息会改变交付物或视觉语言时，先确认影响最大的选择。

未覆盖的媒介，先识别它的造型、明暗和制作机制，再使用相关专业语言。有具体术语却无法确认含义时核对来源，不把它硬归入摄影或最近分类。

## 2. 组织画面约束

从影响当前结果的维度组织内容，采用 reference 的决策顺序：

- **主体与识别**：外形、比例、穿戴、道具、姿态、表情与视线。设定图锁定复用不变量；成片突出当前瞬间。
- **空间与构图**：景别、视点、透视或平面组织、遮挡、留白与阅读路径。多主体写清关系。
- **造型与表现**：轮廓、边缘、线条、笔触、像素或几何。决定细节采用哪种视觉机制。
- **明暗与色彩**：明度组织、固有色、冷暖、重点与背景区分。摄影布光、绘画色块和着色器各按其媒介表达。
- **表面与制作痕迹**：仅保留当前尺度可见的材质或工艺特征；平涂画面不自动补物理微纹理。

专业术语用于压缩准确概念，每个术语都应改变可见结果或交付结构。通过 reference 判断其使用条件，再用具体特征锁定重要效果。引擎、游戏、流派或作者名称可作为风格锚点，但不能替代画面约束。

把“史诗”“高级”“可爱”等倾向落实为比例、形状、色彩或构图。删除只赞美结果的词；保留有明确含义的流派与技法名称。自然语言不等于把专业词改成泛泛描述。

## 3. 使用参考与处理编辑

- **身份参考**锁定五官、体型与服饰识别；**结构参考**锁定构图、视角与动作；**风格参考**锁定表现语言。多参考分别说明职责，不能让风格图替换主体身份。
- 换媒介时按输出媒介选择规则。输入照片仅提供身份或构图时，不因此加载摄影 reference 或保留摄影成像效果。
- 草图通常能交代位置和轮廓，未必能交代材质、画法或色彩。仅省略当前输入方式能可靠承载的信息，不因有参考就一律极简。
- 编辑先确定修改区域、目标变化与保留项，再补目标媒介的表现要求。换画法时说明哪些身份或空间关系继续保留。
- 图中必须出现的文字逐字保留，说明文字层级与位置。精确尺寸、透明度、图块接缝或资产一致性属于交付要求，不能用“高质量”替代。

## 4. 核验与交付

交付前检查：

1. 交付物是否一致：游戏截图没有被写成宣传原画；海报没有退化成单张插画。
2. 专业词是否准确：像素尺度、等距视图、PBR 等含义正确，且有当前用途。
3. 表现机制是否一致：冲突词已删除；有意混合的作用范围明确。
4. 关键约束是否可见：参考保留项、文字、主体关系与资产结构没有被次要细节淹没。

需求明确时，交付可直接粘贴的自然语言 Prompt，使用用户指定或目标入口适用的语言。不固定词序、标签数量或模型专用语法；目标模型有要求时再适配。

排除项使用当前入口支持的方式。没有单独负向字段时，将必要限制写入自然语言。不要承诺 Prompt 能保证精确文字、透明通道或可用游戏资产；要求最终文件时另行验证。
