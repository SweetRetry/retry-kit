# Image Prompt

把意图转为单张画面的视觉指令。先判断图像如何成立，再描述主体；摄影只是其中一种表现方式。

## 1. 确定交付物与视觉语言

先从请求、参考和使用场景确定三件事：

- **交付物**：成片、海报、角色设定、游戏截图、独立资产等。它决定信息组织与验收重点。
- **表现方式**：摄影、绘画、像素、渲染或混合媒介。它决定造型、空间、明暗与表面如何表达。
- **控制范围**：新建整张图，还是保留身份、改背景、换画法等局部编辑。

“写实”可能指真实照片、写实绘画或写实 CG；“游戏风格”也不能确定资产类型。已有上下文时直接判断。缺失信息会改变交付物或视觉语言时，先确认影响最大的选择。

混合媒介时明确每种视觉语言控制哪部分，例如海报的版式与其中的照片分别处理。

## 2. 检索专业视觉语言

术语与决策顺序按当前任务检索，不套用记忆中的通用词表。检索回答两个问题，证据来源不同：

- **领域是否正确**：术语含义、使用条件与从业者的决策顺序。证据来自定义或生产该对象的一方。
- **模型能否执行**：目标模型如何理解这些写法，有哪些已知局限。证据来自模型提供方文档。

**范围**：是否检索取决于内容是否写入 prompt，不取决于对它的熟悉程度。

- 写入 prompt 的每个专业术语，即需要领域知识才能正确使用的词。同一领域的多个术语合并检索。
- 用户点名的艺术家、作品、游戏、工作室、技法或材料。先确认可见特征，再拆成画面约束。
- 目标模型的 prompt 规范与已知局限：语法、负向字段、文字渲染与参考图能力。目标模型未知时跳过。

颜色、表情、天气、基础构图等通用描述直接写。用户提供参考图时，参考图就是该风格的依据，直接描述其可见特征。

**来源**：一手来源是定义或生产该对象的一方，例如引擎术语对应引擎文档，颜料与纸张对应厂商技术资料，流派与作品对应博物馆藏品页，游戏与动画生产对应开发商或工作室的制作分享，目标模型对应提供方文档。没有机构定义的手艺，以长期被从业者引用的教程与作者为一手来源；工具文档只证明软件功能，不证明手艺规范。

维基百科与一般教程只用于定位一手来源或补充示例；仅有二手来源时，两个独立来源一致才采用。prompt 合集、SEO 列表文、零散问答帖和 AI 生成的术语表只作关键词线索。

**查询**：

1. 先确定一手来源是谁及其官方域名，再用 `site:` 或域名过滤在其中检索。泛查询通常只返回论坛与教程。
2. 领域问题只用领域词，不加 prompt、AI 或模型名；这些词会把结果导向 prompt 合集与外包页面。查目标模型规范时才带模型名。
3. 用术语起源的语言检索；日本动画、漫画术语同时查日文原词。
4. 能查看图片时，用一手来源的示例图核对视觉术语的可见效果。
5. 模型规范以当前版本文档为准，核对版本号或更新日期。本会话已核对的内容直接复用。

**处理结果**：

- 同一术语在不同引擎、软件或流派中定义不同时，按用户的生产环境选定义。环境未知且差异会改变交付结构时，先确认；否则改写为可见特征。
- 来源冲突时以一手来源为准，并在 prompt 中避开争议用法。无法确认的术语改写为具体可见特征。
- 领域正确但目标模型无法可靠执行的效果，改用模型支持的写法，并告知用户需要后期处理或验证。

完成标准：写入 prompt 的每个专业术语，都能说出它改变的可见结果与一手来源。没有检索工具时，告知用户术语未核验，只使用能确定含义的描述。

## 3. 组织画面约束

从影响当前结果的维度组织内容，采用检索所得的决策顺序：

- **主体与识别**：外形、比例、穿戴、道具、姿态、表情与视线。设定图锁定复用不变量；成片突出当前瞬间。
- **空间与构图**：景别、视点、透视或平面组织、遮挡、留白与阅读路径。多主体写清关系。
- **造型与表现**：轮廓、边缘、线条、笔触、像素或几何。决定细节采用哪种视觉机制。
- **明暗与色彩**：明度组织、固有色、冷暖、重点与背景区分。摄影布光、绘画色块和着色器各按其媒介表达。
- **表面与制作痕迹**：仅保留当前尺度可见的材质或工艺特征；平涂画面不自动补物理微纹理。

专业术语用于压缩准确概念，每个术语都应改变可见结果或交付结构。按检索确认的使用条件选用，再用具体特征锁定重要效果。引擎、游戏、流派或作者名称可作为风格锚点，但不能替代画面约束。

把“史诗”“高级”“可爱”等倾向落实为比例、形状、色彩或构图。删除只赞美结果的词；保留有明确含义的流派与技法名称。自然语言不等于把专业词改成泛泛描述。

## 4. 使用参考与处理编辑

- **身份参考**锁定五官、体型与服饰识别；**结构参考**锁定构图、视角与动作；**风格参考**锁定表现语言。多参考分别说明职责，不能让风格图替换主体身份。
- 换媒介时按输出媒介选择规则。输入照片仅提供身份或构图时，按输出媒介检索，也不保留摄影成像效果。
- 草图通常能交代位置和轮廓，未必能交代材质、画法或色彩。仅省略当前输入方式能可靠承载的信息，不因有参考就一律极简。
- 编辑先确定修改区域、目标变化与保留项，再补目标媒介的表现要求。换画法时说明哪些身份或空间关系继续保留。
- 图中必须出现的文字逐字保留，说明文字层级与位置。精确尺寸、透明度、图块接缝或资产一致性属于交付要求，不能用“高质量”替代。

## 5. 核验与交付

交付前检查：

1. 交付物是否一致：游戏截图没有被写成宣传原画；海报没有退化成单张插画。
2. 专业词是否准确：像素尺度、等距视图、PBR 等含义正确，且有当前用途。
3. 表现机制是否一致：冲突词已删除；有意混合的作用范围明确。
4. 关键约束是否可见：参考保留项、文字、主体关系与资产结构没有被次要细节淹没。

需求明确时，交付可直接粘贴的自然语言 Prompt，使用用户指定或目标入口适用的语言。Prompt 后附上关键术语的来源链接。不固定词序、标签数量或模型专用语法；目标模型有要求时再适配。

排除项使用当前入口支持的方式。没有单独负向字段时，将必要限制写入自然语言。不要承诺 Prompt 能保证精确文字、透明通道或可用游戏资产；要求最终文件时另行验证。
