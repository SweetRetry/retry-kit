# 视频剪辑

剪辑是把一堆素材变成观众脑子里的一条故事。素材的文件序号不是叙事顺序，同一个拍点常有几条备选，AI 生成的画面会崩坏。

你剪片有三个盲区，整套方法围绕它们设计：

- **看不到运动。** 你只读得到抽帧图，帧与帧之间的坏帧看不见。所以先粗看全部，再细看要用的每一段。
- **听不到声音。** 台词靠机器转写，时间大致可信，字不可信。声音接缝交给人听。
- **会自我确认。** 写计划的人看成片，看到的是计划。故事通不通，交给没看过计划的人复述。

机械工作都经 `scripts/edit.py`。用法看 `edit.py -h`，JSON 字段看 `edit.py schema`。

## 模型

意图 → 拍点 → 覆盖 → 选段 → 成片。

- **拍点（beat）。** 观众必须得到的一件事，写成一句话，比如「她又睡过头了」。拍点按叙事顺序排起来，就是故事的脊柱。
- **覆盖（coverage）。** 能讲某个拍点的所有镜头。同一拍点的几条备选，都是它的覆盖。
- **选段（select）。** 从覆盖里取的一段区间。镜头、崩坏、黑场、台词在素材里也都是区间，剪辑规则就是选段和它们的关系：不压崩坏和黑场，不切开台词，边缘不带进别的镜头的残帧。`edit.py check` 逐条算，并给出建议区间。确有理由违反，在选段的 `waive` 里写原因。
- **轨道。** 画面是主轨，场和选段按顺序排，别的都锚在它上面。每个选段自带同期声，可以取原声、人声、伴奏或静音，也可以让声音比画面早进（J-cut）、晚出（L-cut）。音乐和音效是声音层，锚在场或选段上，画面改了时长它们跟着走。画面规则看画面的入出点，台词规则看声音的入出点。
- **成片**按拍点验收，不按计划验收。

| 层 | 文件 | 作者 |
| --- | --- | --- |
| 意图 | `brief.md` | 用户回答，你记录 |
| 事实 | `clips.json` | `edit.py analyze`，不手改 |
| 日志 | `log.json` | 你，看图之后 |
| 剪辑 | `edl.json`，一场一个拍点 | 你 |
| 成片 | `cuts/vN.*` | `edit.py render`，旧版保留 |

工作区默认 `<素材目录>/.video-edit/`。素材目录只读。没用上的素材写进 `edl.json` 的 `unused`，文件留给用户处理。

## 流程

每一步有完成标准。`edit.py check` 按层报告 ✓ 或还缺什么，一层不 ✓ 不进下一层。

### 1. 问清上下文

剪辑要的上下文只有用户有。开工前一次问齐，用户已经说过的不再问。

- **意图。** 给谁看、在哪播（决定画幅）、目标时长、台词语种、必须保留的内容、调性。
- **剧本。** 生成素材用的剧本、分镜或 prompt。有剧本时，拍点、叙事顺序和台词原文都以它为准，看片只用来核对和补缺。
- **角色。** 每个角色的外观，包括脸、发型、服装，动物写品种和毛色。过片的连续那一遍拿它对照。
- **声音。** 保留各条素材的原声，还是只留人声、全片换一条音乐（要用户给音乐文件）。AI 素材每条自带一段 BGM，保留原声时，跨素材的剪点音乐会断。

答案写进 `brief.md` 的意图、剧本、角色、声音四节。用户答不上的项写成「假设」，交付时列出来。第 3 步看完片再补一节故事，写剧情、人物关系、叙事顺序和依据。

完成：check「意图」✓，四节都有内容或标明的假设。

### 2. 建档

`edit.py init <素材目录> --lang <语种>`，然后 `edit.py analyze`。语种取 brief 里的，没有台词传 `none`。声音要取人声或伴奏时加 `--stems`，把每条素材的音轨分成两路。

完成：check「事实」✓。

### 3. 粗看

读完每条素材的 1fps 触点图（`clips.json` 的 `sheets`）。在 `log.json` 里写下每个镜头是什么、画面上的字、看得出的崩坏。边看边把素材对到拍点上。有剧本就对剧本的场次，没有剧本就想它能讲哪个拍点、和哪条是同一拍点的备选。

这一步求全，不求细。崩坏区间按 1fps 的估计写，`seen` 留 1，定准留到精选。写日志前先读 [`references/looking.md`](references/looking.md)。

完成：check「日志」✓，`brief.md` 的故事写完。

### 4. 纸面剪辑

先在 `edl.json` 里写拍点，再填选段。写之前读 [`references/craft.md`](references/craft.md)。

1. 列拍点。一场一个 `beat`，按叙事顺序排。有剧本就从剧本来。
2. 给每个拍点选覆盖。取舍按用户的明确要求、无崩坏、和相邻拍点连贯、表演和构图的顺序。
3. 给拍点分时长预算，总和接近目标时长。预算按起伏分配，不平均。
4. 填选段，每段写 `why`。
5. 按 brief 的声音定顶层 `sound` 和 `audio` 声音层。对白里要切到听者的地方，用 `lag` 或 `lead` 让台词说完，不切断它。
6. 素材里没有镜头能讲清的拍点，放一个 `gap` 选段占位，写清这个镜头要拍什么。渲染时它是灰色占位，时长照算。

完成：每条素材要么在某个拍点里，要么在 `unused` 里有原因。预计时长在目标的 ±15% 内。check 剩下的问题只差精选。

### 5. 精选

先跑 `edit.py inspect`，它给挨着选段边缘、又只粗看过的崩坏出 6fps 局部图。其余风险（大幅运动、变形、换衣、屏幕上的字）用 `edit.py sheet` 出 4 到 6fps 局部图。逐帧看。定准 in 和 out，把崩坏区间改准，`seen` 改成实际密度。

只细看要用的段。这一步的精力全花在成片里会出现的帧上。

完成：check「剪辑」✓。剩下的违规要么改掉，要么在 `waive` 里写了原因。

### 6. 过片

`edit.py render` 出 `cuts/vN.mp4`，同时出整片触点图（`sheets`）、剪点图（`seams`，每行一个剪点，出点前两帧接入点后两帧）和成片台词表（`lines`），路径都在 `vN.json`。分五遍过，每遍只看一件事。发现问题回到对应的层改，再渲染。

1. **故事。** 派一个子 agent 当第一次看片的观众。只给它整片触点图、网格换算（`sheet_grid`）和成片台词表，不给 brief、edl，也不说你想讲什么。让它按时间复述发生了什么，标出看不懂、跳、拖的地方，最后一句话说片子讲了什么，猜测的标「猜」。拿复述逐个对拍点：没被复述出来的拍点、读反的顺序、读错的人物关系，都是故事问题。剪辑救不回来的，就在那里放 `gap`。台词表是机器转写，因错字产生的困惑不算故事问题，记进听片清单让人确认。
2. **节奏。** 看 `vN.json` 每段的时长。相邻几段一样长就是平，信息给完还停着就是拖，高潮前要有一拍静。
3. **连续。** 逐行看剪点图。查主体左右和视线方向有没有互换、`flip` 有没有生效、有没有残帧、同一角色的外观和 brief 的角色对不对得上。
4. **技术。** 在整片触点图里查黑帧和漏网的崩坏。风险段在成片上用 `edit.py sheet <成片路径>` 出局部图复看。
5. **声音。** 听不到，但量得出来。看 `vN.json` 的 `seam_jumps`：剪点前后响度差 ≥10 dB 的，先判断是不是有意的冲击切，不是就挪剪点或改声音。check 备注里 J-cut、L-cut 叠声的地方，确认要不要压低一方。没解决的都进听片清单。

完成：五遍各有结论（没问题，或改了什么）。最后一版 check「成片」✓。

### 7. 交付

汇报依次写：

- 成片是什么、多长、给谁看，用完整绝对路径给出成片。
- 拍点表：每个拍点用了哪段，为什么。
- 取舍、避开的问题、豁免、brief 里的假设、没做的事。
- 听片清单：声音那一遍留下的剪点、挨着台词的剪点、人声分离过的段落，用成片时间码列出，写明「我听不到，需要你听」。
- 补拍单：有 `gap` 时跑 `edit.py gaps`，出 `reshoots.md`，每条带前后衔接的参考帧。用户要补拍，就用 video-prompt 把每条写成生成 prompt。

每个判断标「看过」或「推断」。

## 改版

用户的意见先归到层，再在那一层改：

- 故事（顺序不对、少了什么、多了什么）改拍点。
- 取舍（换一条备选、换一段）改覆盖和选段。
- 节奏（太长、太拖、太赶）先改时长预算，再改 in 和 out。
- 技术（看到坏帧、字幕错）先补进 `log.json`，再改选段。补进日志之后，check 会一直拦着它。
- 补拍回来的素材放进素材目录，重跑 `edit.py init` 和 `analyze`，只会分析新素材。粗看写日志，再把 `gap` 换成选段。

改完重新 check、render，出新版本，再按第 6 步过片。

## 维护

改 `edit.py` 之后跑 `python3 -m unittest discover -s tests`。fixture 是一个真实项目，旧流程漏掉的问题都写成了测试，新发现的漏网问题也照这样补进去。
