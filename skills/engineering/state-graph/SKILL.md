# State Graph

读者要判断一段逻辑会不会出错，但不一定熟悉形式化方法。交付物是一张他能看懂的状态图，加一条逐步讲清的出错路径。人推演执行顺序时只会想到顺利的那几种，所以穷举交给脚本，人只读结果。

全程只用三个词：**快照**（某一刻共享状态和每个参与者走到哪一步）、**动作**（一个参与者做一件事，快照因此变成下一张）、**规矩**（任何快照都必须满足的一句话）。

## 范围

- 用户指定的代码、设计或口述流程，其中两个以上参与者读写同一份状态。参与者包括进程、请求、标签页、worker、定时任务、重试、外部回调。
- 一次建一个流程。用户说「看看这段会不会出错」但没给范围时，先问是哪段流程。
- 不用于全面审查一个系统的所有故障场景，也不用于没有共享状态的单线程逻辑。

## 1. 建模

- **快照**只放判断规矩所需的字段：共享状态，加每个参与者走到哪一步。每多一个字段，图就大一圈，删掉与规矩无关的。
- **动作**是参与者在真实系统里一次原子完成的事。读和写之间没有锁、事务、条件更新或唯一约束包住时，读与写是两个动作。这一步决定模型能不能发现竞态：把它们合成一个动作，竞态就从图上消失了。原子性以代码里真实存在的机制为准，不以作者的意图为准。
- **规矩**写成业务语言的一句话，例如「里面最多一个人」「一个订单只扣一次款」「界面显示的是最后一次点击的结果」。
- **规模**取能暴露问题的最小值：两个参与者，每人跑一轮，重试次数和队列长度取 1 或 2。结论只对这个规模成立。
- 流程有合法终点时（所有人都办完了）导出 `done`，否则终点会被报成卡死。

**完成标准**：每个先读后写的步骤都判定了是一个还是两个动作，依据写成 `文件:行号` 或设计文档里的原话。

## 2. 写模型并穷举

照 [references/model-template.mjs](references/model-template.mjs) 的格式写模型文件，放在仓库外的临时目录，再运行：

```sh
node <skill 目录>/scripts/explore.mjs <模型文件.mjs> [--out <目录>]
```

stdout 是 JSON 报告：快照数、违规数、卡死数、最短出错路径。同时输出 `.dot`，本机有 Graphviz 时再出 `.png`。缺 Graphviz 时在 macOS 上执行 `brew install graphviz`。

标签写给读者。`describe` 和动作名用业务里的说法（「小A 看牌」「订单 已扣款」「标签页2 提交」），不用变量名和枚举值。读者不是工程师，或者说看不懂时，换成生活场景的类比。类比里每个角色、物件和动作都要一一对应真实系统里的东西，对应不上的类比会误导读者，宁可不用。

快照超过 40 个时，脚本只画出错路径。先尝试缩小模型。缩不下去时交付路径图，并在报告里写明完整状态数。

项目里已有 TLA+ 规格时，用 TLC 检查，不重写规格：`java -cp tla2tools.jar tlc2.TLC -dump dot,colorize,actionlabels out.dot <Spec>`。TLC 的图标签是变量原值，读者看不懂时，把反例轨迹按上面的标签要求改写成模型文件再出图。

## 3. 核对模型

模型报「没有违规」不等于系统没问题，可能是模型漏了东西。交付前做两件事：

1. **打开 PNG 看**。每个方框都要对应真实系统里可能出现的情况。出现不可能的快照，说明某个动作的条件写宽了；该出现的情况没出现，说明写窄了。
2. **拆掉保护再跑一次**。把真实系统里起保护作用的机制从模型里去掉，例如把原子动作拆回读和写两步。脚本必须报出违规。报不出来，说明规矩写错了，或者那个机制根本没起作用，回到第 1 步。

## 4. 修复对比

有违规或卡死时，写出修法，按修法改一份模型重跑，确认出错的快照不可达，两张图一起交付。修法在模型里只改对应真实机制的那一处，例如加锁就把读和写合成一个动作，加条件更新就给写入动作加上判断。

## 输出

1. 一句结论：在什么规模下，会不会违反哪条规矩，或者会不会卡死。
2. 场景：参与者、每人能做的动作、规矩。
3. 状态图的 PNG 路径。交付前已打开看过。
4. 出错路径逐步讲：每一步谁做了什么。指出从哪一步起某个参与者手里的信息已经过期，并对应到 `文件:行号`。
5. 修法和修复后的状态图。
6. 用户第一次接触时附对照表：快照即状态，动作即状态转换，规矩即不变式，出错路径即反例，整张图即状态转换图。

没有违规时，写明检查的规模、快照数，以及第 3 步拆掉保护后报出的违规。拆掉保护那一步是「没有违规」这个结论的证据。
