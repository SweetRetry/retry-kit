# Task Breakdown

将已确认的需求、RFC 或接口契约拆成 `docs/tasks/{taskfolder}/` 任务包。拆解不自动启动开发，执行范围沿用用户授权。

## 拆解流程

使用 [任务文档模板](references/templates.md)，按顺序达到各步完成标准。

### 1. 锚定当前规格

- 在 `00-overview.md` 写明目标、范围、核心实体、业务规则与关键决策。
- 按业务行为定义交付切片：触发条件、可观察结果、失败状态与验收方法。
- 跨模块契约未验证时，安排代表性最小场景跑通真实链路；已有稳定链路则引用证据。
- 涉及数据访问时，补充数据规模、性能目标与索引约束。注明来源，未知项显式标记。

**完成标准**：总览包含当前规格、链路验证安排、业务验收条件与最终审查配置。公共规则及契约各有唯一权威来源。

### 2. 按语义归属分工

- 将交付切片映射到执行任务（Phase）。纵向验收覆盖真实调用链，各任务按模块职责分工。
- 为每个任务分配独占写入范围、上下游契约和专属测试。频繁互改同一规则或依赖对方内部实现时，合并或串行。
- 为共享类型、入口、迁移、依赖清单及锁文件指定唯一写入责任人；消费者提交修改需求。
- 写明前置任务、启动条件、可并行任务与集成责任人。就绪任务持续集成，接线与联调随切片推进。
- 读取 [执行契约](references/execution-contract.md)，配置能力画像、派发、审查、证据门禁与恢复规则。
- 近期任务生成 `0X-phase-{slug}.md`，包含场景、契约来源及版本、消费方、参考实现、步骤与验证命令。仅摘录执行所需约束。
- 远期任务在总览保留目标、依赖、验收与细化条件，执行前再展开。任务数量随责任边界与验收范围调整。

**完成标准**：每个切片都有实现及集成验收责任人；并行任务的写入与资源无冲突；任务均有能力画像。近期任务可独立执行，未满足前置条件的任务保持不可派发。

### 3. 初始化记录与看板

- 创建 `issues.md`、`legacy-burdens.md`、`changes.md`，分别记录未决问题、必要的临时兼容与规格变更。
- 复制 [看板模板](assets/kanban.html)，只填入 `board-data` JSON。字段与字符串编码要求见模板注释。
- 将尚未执行的任务标为 `Todo`，证据标为未运行。总览链接看板并记录初始恢复断点。
- 打开看板，核对任务数量、依赖与状态；确认验收计数、待决事项与更新时间实际可见。

**完成标准**：文档与看板一致；业务已验收和任务已集成分别计数；阻塞与待决事项可见。

### 4. 交付任务包

先给出看板入口，再报告文档路径、切片与任务映射、关键规则及数据约束、首批可启动任务与未决条件。

**完成标准**：用户可找到任务包，并区分已就绪任务与受阻任务。

## 维护任务包

- **老代码**：当前范围内低风险可修正的就地处理；确需隔离外部协议或不稳定实现时增加适配层。必要的临时兼容记录代价、移除条件与责任人。
- **规格变更**：总览与任务文档始终反映当前要求；`changes.md` 追加旧要求、新要求、原因、依据与影响范围。
- **契约变更**：暂停受影响依赖，由契约责任人在指定集成分支提交变更；更新规格及验收，按仓库策略同步分支，复核受影响证据后恢复。
- **状态汇报**：任务启动、状态或阻塞变化、审查裁决与集成验收后，主控核对任务及代码版本，再更新看板和时间；旧汇报不得覆盖新状态，子 Agent 只汇报。
- **状态归属**：Markdown 保存规格与恢复上下文，看板保存当前进度快照。技术证据按需展开；刷新查看更新，仅修改数据区。
