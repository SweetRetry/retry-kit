# 执行契约

将适用规则写入任务包的派发、审查、集成与恢复配置。

## 能力画像

根据复杂度声明 `tier` 与 `effort`，具体模型及参数由执行宿主在派发时映射。

| 复杂度 | 适用任务 | tier | effort |
| :--- | :--- | :--- | :--- |
| 低 | 机械样板、配置、文档、遵循已有模式的增量 | fast | off |
| 中 | 常规业务、多分支组件、契约明确的接口与重构 | standard | low 或 medium |
| 高 | 核心算法、竞态、复杂状态机、底层协议或高不确定性排障 | reasoning | high |

任务文档保持厂商中立，不固化具体模型版本。预算、权限等硬限制由宿主实施；不支持的限制标为执行约定。

## 两级审查

- **局部收敛**：实现前确定语义归属与复用点；提交前核对新增的重复规则或状态、无用途扩展点、无职责转发层、应移除的旧路径及临时代码。证据明确且范围内可低风险消除的就地处理，保留有实际职责的抽象。
- **任务审查**：相关检查通过并形成语义完整的提交后异步审查。记录 base/head 与覆盖范围，结合调用方核对下列阻塞项。复杂度未收敛则退回最小修复；纯风格偏好不挂单，有价值的非阻塞后续工作才记入 `issues.md`。
- **最终验收**：核验集成后的业务行为、跨任务交互、共享状态与目标遗漏。运行项目要求及风险相称的回归，复用仍有效的局部证据。必需检查未运行或失败不能算通过，既有失败须有基线证据。`SIGN_OFF` 仅表示验收通过。

以下问题判为 `BLOCKER`：

1. 为通过检查弱化断言、跳过必需测试、吞掉必须暴露的错误，或用假数据冒充实现。需求变更时，由验收责任人按新契约更新并复核测试；测试 fixture 不算假实现。
2. 破坏总览规定的业务规则。
3. 大表查询存在无索引关联、无条件 `LATERAL JOIN`、全表扫描、N+1 或无分页全量加载。
4. 存在真实可达的空指针、竞态或死锁。
5. 以历史包袱为由引入范围内可低风险消除的重复规则、无效层，或绕过业务约束。

涉及 DB/ORM 改动时，审查者检索仓库 Schema、Migration 或 DDL，核验查询匹配的具体索引及字段。缺少必要索引且未补迁移则退回；单测不能替代性能证据。跨范围治理另记收益与代价，交由责任人裁决。

## 并行与证据门禁

- 并发任务分配独立 `.worktrees/phase-X`。端口、测试数据库、迁移与外部环境另分配所有权或串行访问。
- 主控维护看板与全局台账，子任务回传局部记录。
- 任务状态为 `Todo → Implementing → Verifying → Reviewing → Ready → Integrated`；受阻进入 `Blocked`，解除后回到实际步骤。
- `Ready` 需绑定当前代码版本的验证与明确审查通过；`Pending`、未知或“没有 BLOCKER”均不足以放行。
- 集成责任人合并 `Ready` 任务，通过相关检查后标为 `Integrated` 并推进依赖。交付切片另需业务验收通过。
- 异步审查期间可推进独立任务；依赖未通过门禁的契约或行为时等待。
- 修复、rebase 或契约变化后复核证据覆盖，仅补查失效部分。

## 预算与恢复

- 按不确定性设置预算。同一失败与假设无新证据时诊断或换路；同一修补思路无增量失败两次即停止。有新证据时可在预算内继续。
- 预算耗尽、环境故障与需求缺失分别记录续接条件，独立任务继续。
- 总览记录恢复断点：分支、base/head、未提交改动位置、证据、进行中的操作及下一步。外部副作用另记操作标识与完成证据。
- 恢复时先核对 Git 与实际现场，再修正看板；确认外部操作的执行状态后决定是否重试。
- 提交已集成、必要证据已保留且无未提交工作后，清理 Worktree。
