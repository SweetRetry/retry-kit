# Codex Review

每次新开的 Codex review 都会从头读 diff、项目规则和相关文件，消耗额度。所以每一次调用都要换来新的信息：对象准确、只跑一次、追问复用同一会话。Codex 在这里是只读的发现者：它找问题，不改文件，修法也不由它定。Claude 负责核实、排轻重、定修法。

## 1. 定范围

把用户的说法映射到唯一的审查对象，并用对应命令确认对象非空：

| 用户说的 | 提示里的写法 | 非空检查 |
| --- | --- | --- |
| 当前改动、没提交的 | 当前未提交的改动（`git diff HEAD` 与未跟踪文件） | `git status --short --untracked-files=normal` |
| 这个分支、PR、相对 main | 相对 `<分支>` 的改动（`git diff <分支>...HEAD`） | `git diff --stat <分支>...HEAD` |
| 某个提交 | 提交 `<sha>` 引入的改动（`git show <sha>`） | `git show --stat --format= <sha>` |

检查结果为空就告诉用户并停止，不调用 Codex。对象无法判断时再问。

**完成标准：**选定一个对象，且已确认它的改动非空。

## 2. 写提示

提示只写 Codex 从仓库里读不到的东西：

- **审查对象**：第一句用上表的写法点明。
- **意图与约束**：这次改动要达成什么、不该改变什么，例如“只改文案，不应改变行为”。“严重”与“多余”都以它为基准。
- **要发现什么**：默认两类。严重问题，即会损坏数据、越权或让主流程出错的缺陷。过度设计，即达成意图用不上的抽象、配置、兼容层与防御代码。用户点名了别的维度或最担心的地方就加上，只要查某一类就只写那一类。
- **已排除的点**：Claude 在本对话里已核实的部分，让 Codex 把额度花在别处。

Codex 会自己读 diff、`AGENTS.md` 和相关文件，提示里不贴 diff，也不复述项目规则。

**完成标准：**提示第一句写明审查对象，并写了意图和要发现什么。

## 3. 运行

```sh
out=$(mktemp -d)

# 经引号定界的 heredoc 从 stdin 传入，提示里的反引号与 $ 保持原样
codex exec review -c sandbox_mode='"read-only"' \
  -o "$out/review.md" - > "$out/run.log" 2>&1 <<'EOF'
<提示>
EOF
echo "exit=$?"

echo "$out"; grep -m1 'session id' "$out/run.log"
```

- `codex exec review` 才有 `-o`；`codex review` 没有。
- `sandbox_mode` 强制只读。受信任项目默认是 `workspace-write`，审查不该改文件。
- 模型与推理强度沿用用户的 Codex 配置；用户指定时才加 `-m` 或 `-c model_reasoning_effort=...`。
- stdout 是几万字的执行记录，只写进 log，不读进上下文。
- 一次 review 可能持续数分钟。给足超时并等它结束；看起来慢时继续等，重新发起会重复扣额度。
- 非零退出时，读 log 末尾判断原因。登录失效或额度用尽就如实告诉用户并停止，Claude 自己的审查不能顶替 Codex 的结论。

**完成标准：**退出码为 0，`review.md` 非空，并记下输出目录的绝对路径与 `session id`。后续 shell 调用拿不到 `$out`，一律写这个绝对路径。

## 4. 核实与汇报

只读输出目录里的 `review.md`。每条发现都是待核实的主张，回到代码逐条判定：

- **成立**：缺陷给出 `文件:行号` 与触发条件；过度设计给出删掉它后意图仍然达成的依据。
- **不成立**：说明哪段代码或哪条约束否定了它。
- **无法判断**：写明缺什么证据。

成立的发现按后果排轻重：触发条件在这次改动的真实使用中会不会出现，出现后用户或数据损失什么。Codex 的优先级标记是它的主张，与核实结果不一致时写明理由。触发条件靠假设的排在最后。改动之前就存在的问题按真实后果定级，并标明不在本次改动范围。

修法由 Claude 基于核实结果给出，Codex 附带的修复建议只当线索。

汇报按后果从重到轻排：真实使用中会触发的逐条展开，排在最后的各用一行带过并说明为什么可以不修。Codex 原话与 Claude 的核实结论分开写。Codex 未发现问题时，照实转述它检查过什么。用户没要求时不改代码，也不再跑一轮 review。

## 5. 追问与复查

用户追问某条发现，或要求修复后让 Codex 确认时，续接同一会话。会话里已有仓库上下文，比新开一次 review 省额度：

```sh
codex exec resume <session id> -c sandbox_mode='"read-only"' \
  -o <输出目录>/followup.md - > <输出目录>/followup.log 2>&1 <<'EOF'
<问题或已做的修复>
EOF
echo "exit=$?"
```

退出码为 0 且 `followup.md` 非空才算拿到回答，失败时按第 3 步的规则处理。

改动范围已明显变化，或用户要求完整复审时，再回到第 1 步新开一次。
