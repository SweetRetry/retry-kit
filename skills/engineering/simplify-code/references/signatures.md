# 偏离签名

按理想形状的四项决定分组。同一个签名在前端和后端长相不同，根因相同，所以放在同一行。右列是常见的成立理由，命中时到第 4 步查证。

## 状态

| 签名 | 前端常见样子 | 后端常见样子 | 常见成立理由 |
| --- | --- | --- | --- |
| 一份数据有多个所有者 | 服务端数据拷进全局 store 或组件 state；同一筛选条件同时存在 URL、store 和 state | 同一数据在缓存、进程内存与表里各自更新；冗余列 | 离线草稿或乐观更新；有测量支撑的缓存 |
| 存了能算出来的值 | 用 state 加 effect 同步派生值 | 能由其他字段推出的计数或状态列 | 有性能测量；需要保存某一时刻的快照 |
| 能表示非法状态 | isLoading、isError、data 几个布尔值并存；一串布尔 props 互相冲突 | 几个可选字段与布尔值的组合；状态是自由字符串 | 这些字段确实各自独立 |
| 同一状态被多处直接修改 | 多个组件直接改同一个 store 字段 | 多个服务直接写同一张表 | 修改方天然隔离 |

## 边界

| 签名 | 前端常见样子 | 后端常见样子 | 常见成立理由 |
| --- | --- | --- | --- |
| 校验或判空在边界之内反复出现 | 类型过宽，组件层层判空 | 同一参数在每层各校验一次 | 该层还有别的入口；各层错误不同 |
| 映射层多于边界数 | 每个调用处各自重塑接口响应 | 请求 DTO、领域模型、ORM 实体、响应 DTO 字段一一对应，各写一遍映射 | 要对外隐藏内部字段；两侧字段已分化 |
| 只转发的层 | 包装组件只透传 props；prop 穿过多层不用它的组件 | Controller、Service、Manager 只转发 | 隔离外部依赖；事务或权限边界 |
| 横切逻辑散落 | 每个页面各写权限判断或埋点 | 每个 handler 各写鉴权、日志、响应拼装 | 各处规则确实不同 |
| 边界设置散在内部 | 各处直接读环境变量或全局配置 | 业务代码各处读环境变量；客户端、服务层、调用处各配一层重试或超时 | 需要热更新；各层针对的失败类型不同 |
| 跨端契约各写一份 | 手写接口类型、状态字面量、校验规则，或重算后端已算的业务规则 | 同一份类型、枚举与规则在后端另写一份 | 两端不同仓库且无共享构建；乐观更新需要本地计算 |

## 概念

| 签名 | 前端常见样子 | 后端常见样子 | 常见成立理由 |
| --- | --- | --- | --- |
| 只有一种用法的抽象 | 只被用一次的通用组件；配置驱动的渲染只有一份配置 | 单实现接口；只调用一次的工厂；只有一个插件的插件机制 | 测试替身；外部扩展方 |
| 同义词与多义词 | 同一实体在组件、hook、类型里叫不同名字 | 同一实体在表、模型、接口里叫不同名字 | 名字来自外部协议 |
| 一个元素承担几种用途 | 组件靠 flag props 切换成几种不同的东西 | 函数靠 flag 参数做几件不同的事 | 只是同一件事的参数微调 |
| 重做已有能力 | 手写请求状态、表单状态或工具函数，而项目已有对应的库 | 手写标准库、框架或仓库已有的工具 | 现成的在边界条件、错误或性能上行为不同 |
| 假合并 | 两个改动原因不同的界面共用一个组件，靠条件分叉 | 两个业务共用一个函数，靠条件分叉 | 两处确实总是一起改 |
| 契约不需要的元素 | 无引用的组件、样式、特性开关 | 无调用方的代码；所有调用方都传同一个值的参数 | 被反射、动态调用、序列化或外部使用 |

## 流程

| 签名 | 前端常见样子 | 后端常见样子 | 常见成立理由 |
| --- | --- | --- | --- |
| 连锁反应 | effect 改 state 触发下一个 effect；本该在事件处理函数里的逻辑放进 effect | 只有一个订阅者、发布方同步等结果的事件总线；层层钩子 | 同步外部系统；解耦部署或削峰（改为直接调用会改变并发语义，归为需改契约的提议） |
| 主流程被埋 | 一个巨大的条件 JSX 包含所有界面状态 | 主流程藏在深层嵌套的条件里 | 各分支对称且同等重要 |
| 主流程被切碎 | 一个界面拆成一串只用一次的小组件 | 一串只调用一次的小函数和临时变量 | 某段计算独立且复杂 |
| 状态转移散落 | 状态切换逻辑分散在多个事件处理函数里 | 状态切换规则分散在多处条件判断里 | 只有两种状态 |
| 错误层层包装 | 每个组件各自 try 并各自展示错误 | catch 后原样重抛；逐层包装同一个错误 | 补充上下文；释放资源 |
| 没有测量的优化 | 无依据的 useMemo、useCallback、memo | 手写缓存或预计算 | 有测量；下游依赖引用稳定 |
| 同一用例多处实现 | 两个页面各写一遍同一个提交流程 | 定时任务、命令行与接口各写一遍同一段业务 | 各处规则确实不同 |
| 依赖方向倒挂 | 通用组件引用业务模块 | 循环依赖；底层模块引用上层 | 框架强制该结构 |
