# 故障模型

每一类边界都必须假设下列故障会发生。同一类故障在前端和后端长相不同，所以放在同一行对照。

| 边界 | 必须假设的故障 | 前端常见样子 | 后端常见样子 |
| --- | --- | --- | --- |
| 网络调用 | 请求丢失；响应丢失；重复送达；超过超时才到；乱序到达 | 切换筛选后，旧请求晚到并覆盖新结果；提交超时后用户再点一次 | 调支付超时后重试；外部回调重复投递；消息队列至少一次投递 |
| 进程与页面生命周期 | 任意两步之间被杀或崩溃 | 请求还没回来时组件卸载、页面刷新、标签页关闭、后退；从往返缓存恢复出旧页面 | 写库后、发消息前重启；发布时进程被杀；事务外的第二步没执行 |
| 并发 | 读与写之间有另一个参与者写入 | 两个标签页各改同一份数据；双击提交；乐观更新与服务端推送冲突 | 两个请求同时扣库存；两个 worker 领到同一个任务；先查后插导致重复记录 |
| 时间 | 时钟不同步；时区、夏令时、跨日跨月；令牌、锁、缓存、会话在流程中途过期 | 填表途中会话过期，提交被拒，输入丢失；用客户端时间判断截止 | 锁过期后原持有者仍在写；定时任务在夏令时切换时重复执行或被跳过；缓存过期瞬间大量请求击穿 |
| 数据 | 空、null、超长、极值、精度、编码、旧格式 | 本地存储里是旧版本的数据结构；金额在客户端舍入后与服务端不一致 | 队列里是旧格式的消息；金额精度丢失；空集合使批量操作变成全量操作 |
| 版本 | 新旧版本同时运行；回滚；迁移执行到一半 | 浏览器缓存的旧前端调用已改过的接口；服务端删掉了旧前端仍在读的字段 | 滚动发布时新旧 worker 读写同一份数据；回滚后旧代码读不懂新写入的数据；迁移中途失败 |
| 规模 | 数据量放大 100 倍；队列积压；重试风暴 | 列表数据量暴涨；后台标签页里的轮询堆积 | 积压的消息过期或越过业务时限；重试成倍放大对下游的压力 |
| 恢复路径 | 重试、补偿、清理本身失败，或与正常流程同时运行 | 手动重试按钮与自动重试同时发出 | 补偿任务与原流程并发；对账任务重复补偿 |
| 权限与身份 | 流程中途权限被收回、用户切换 | 登出后旧请求的响应写进了新用户的界面；切换账号后缓存没清 | 异步任务按入队时的权限执行；权限变更后长连接仍然有效 |
