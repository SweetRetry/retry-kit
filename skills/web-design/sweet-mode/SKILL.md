# Sweet Mode

`reference/` 中的类名、Token、阈值与禁令是硬约束。

## 1. 对齐项目锚点

reference 中的 `globals.css`、`packages/ui` 指目标项目里的对应位置。先找到：

- 样式入口：定义颜色、圆角、字号与字体族 Token 的文件。阶梯以它为准，reference 表格里的 px 值只是缺省；缺少语义 Token 时在这里补，业务代码只消费语义名。
- 同类先例：写控件、确认、加载与报错反馈、空状态、页头或界面文案前，先在项目里搜同类既有实现并沿用；同一对象用已有的名称。只有语义不同才新增变体。
- 组件库（`packages/ui` 或 `components/ui`）：圆角、表面、按压反馈等外观改在变体里，调用点只负责布局。改动用到的组件先对照下表，未达标的在变体里改，再写调用点：

| 组件 | 基线 |
| --- | --- |
| Button | 按压反馈、时长与过渡属性按 `motion.md` §2–§4 |
| Card | 无阴影；`card` 与 `background` 有明度差时无边框，同色时用低对比边框 |
| Skeleton | `bg-muted` |
| Sheet | 缓动与时长按 `motion.md` §2 |
| Popover / DropdownMenu / Tooltip | 展开方向按 `motion.md` §3 |

## 2. 读取规则

开工前读完 `reference/` 全部 8 个文件：规则跨文件交叉，一个带删除弹窗的表格同时受层级、字形、稳定与交互约束。新建页面或重组信息时，写界面前先列字段去留表：当前场景可用的每个字段与操作各判为呈现、延后或删除。呈现须写出它满足 `hierarchy.md` §2 的哪一条判据，写不出的归延后或删除；延后的写明载体。按这张表定主次与披露层次，再选组件和样式。

只改当前任务触及的范围，范围外的违规列入交付。

## 3. 打磨

新建页面或重组信息时，首次渲染后按下列顺序各打磨一遍。每遍只动一个维度，先截图再改，改完再截图对比（`scripts/render-check.js`，用法见 §4）；前一遍定下的结果不在后一遍推翻，要推翻就回到那一遍重做。

1. **对齐轴**：`layout.md` 对齐、光学对齐。
2. **间距节奏**：`layout.md` 间距。
3. **标题层级**：`typography.md` 字阶。
4. **正文可读性**：`typography.md` 字阶、`layout.md` 宽度、`surface.md` §2 次要文字。
5. **元数据位置**：`hierarchy.md` §1 一个字段一个位置、`layout.md` 对齐。

每遍用一句话记下改了什么；没有可改处时写出截图里支持这一判断的观察。

## 4. 验收

验收范围随任务体量。不新增页面、不改变字段去留与分组的是局部修改；拿不准时按新建页面处理。

| 项目 | 局部修改 | 新建页面或重组信息 |
| --- | --- | --- |
| 小节结论 | 改动触及的 reference 小节 | 全部小节 |
| 渲染状态 | 改动影响的状态 | 加载、空值、报错三态与收起、展开两态 |
| 键盘走主流程、减少动态效果 | 改动涉及交互或动效时 | 必做 |
| 独立复核 | 不做 | 必做 |

每条小节结论带证据，没有证据的记为未检查：修复写 `file:line` 与改法，通过写截图或 audit 输出里支持它的观察，不适用写一句原因。

1. 静态扫描，修复到输出为空：

   ```bash
   node <skill 目录>/scripts/ui-guardrails.js --changed <目标项目路径>
   ```

   `--changed` 只扫描相对 `HEAD` 有改动的文件；改动已提交时传分支起点（`--changed=main`）。脚本跳过组件库、第三方、测试与 skill 目录；组件库的外观按 §1 基线表核对。任意圆角与间距、内联 style 与 CSS 中的色值人工核对。
2. 渲染检查。启动开发服务器，在目标项目目录执行：

   ```bash
   node <skill 目录>/scripts/render-check.js <改动页面 URL>...
   ```

   它在 375×812 与 1280×800 两个视口执行 `render-audit.js` 并各截一张整页图，输出 JSON。
   - 修复到每项 `violations` 为空。`secondary.descriptions` 逐条按 `hierarchy.md` §1 次要文字限额定去留。
   - 查看每张截图，按 `hierarchy.md` §4 逐项判断。
   - 交互才能到达的状态用浏览器工具到达，以 evaluate 执行 `scripts/render-audit.js`（整个文件是一个无参函数）并截图。解析不到 playwright 且无法安装时，两个视口也按此方式完成。

   启动受阻时先排除可修复的原因：依赖、端口、环境变量；缺后端或登录时用临时 mock 渲染改动页面，交付前移除。仍无法运行时，渲染检查记为未通过，交付失败的命令与报错。
3. 独立复核。一个未参与实现的子 agent 重做小节结论与 `hierarchy.md` §4 的判断：只给它 diff、截图路径、audit 输出与 `reference/` 路径，不给实现思路与作者的结论。它返回带证据的逐节结论，与作者结论不一致的项按未通过处理；修复后交回复验一次。环境无法派生子 agent 时自行完成，交付中注明未经独立复核。

交付改动位置、任务体量、字段去留表、打磨记录、各小节结论、两个视口的 audit 输出与截图路径、范围外的违规。
