# Sweet Mode

`reference/` 中的类名、Token、阈值与禁令都是硬约束。编写或修改界面时全部遵守。

## 1. 对齐项目锚点

`reference/` 中的 `globals.css` 与 `packages/ui` 指目标项目里的对应位置。动手前先确认三处锚点：

- **样式入口**：找到定义颜色、圆角、字号与字体族 Token 的文件。所有阶梯以样式入口为准，`reference/` 中的 px 值只作缺省。缺少语义 Token 时，在样式入口补充，业务代码只消费语义名。
- **同类先例**：编写控件、确认流程、加载与报错反馈、空态、页头或界面文案前，先搜索项目里的同类实现并沿用。同一对象全应用只用一个名称。只有语义不同时才新增变体。
- **组件库**：找到 `packages/ui` 或 `components/ui`。圆角、表面、按压反馈等外观只在组件变体中修改，调用点只负责布局。使用下表组件前先对照基线，未达标时先改变体再写调用点。

| 组件 | 基线 |
| --- | --- |
| Button | 加载态锁宽高（`resilience.md` §1）。纯图标按钮满足热区与可访问名（`interaction.md` §1、`icon.md` §1）。按压与过渡按 `motion.md` §3–§5。 |
| Card | 无阴影。`card` 与 `background` 有明度差时无边框，同色时用低对比边框。 |
| Skeleton | 使用 `bg-muted`。 |
| Dialog / AlertDialog / Sheet | 打开落焦与关闭回焦按 `interaction.md` §1。退出期冻结内容按 `resilience.md` §5。缓动与时长按 `motion.md` §3。 |
| Popover / DropdownMenu / Tooltip | 展开方向按 `motion.md` §4。相邻 Tooltip 即时切换按 `interaction.md` §1。菜单触发的弹窗挂在菜单外（`resilience.md` §5）。 |

## 2. 读取规则

动手前读完 `reference/` 全部 8 个文件。规则跨文件联动，例如带删除弹窗的表格同时受层级、字形、韧性与微交互约束。

新建页面或重组信息时，写代码前先列一张**字段去留表**：

1. 列出当前场景可用的每个字段与操作，逐项判为**呈现**、**延后**或**删除**。
2. 判为呈现的条目，写出它满足 `hierarchy.md` §2 的哪一条判据。写不出的改为延后或删除。
3. 判为延后的条目，写明承载它的披露载体。
4. 按这张表定好主次与披露层次，同时标出本视图做微交互工艺的 1–2 个核心触点（`motion.md` §1–§2），再选组件和样式。

只修改当前任务触及的范围。范围外的既有违规记入交付，不顺手修改。

## 3. 打磨

新建页面或重组信息时，首次渲染后截一张图，对着这张图按以下顺序逐个维度打磨，全部改完再截一张确认。后一个维度不推翻前一个的结论。需要推翻时，退回那个维度重做。

1. **对齐轴**：检查 `layout.md` 对齐与光学对齐。
2. **间距节奏**：检查 `layout.md` 间距。
3. **标题层级**：检查 `typography.md` 字阶。
4. **正文可读性**：检查 `typography.md` 字阶、`layout.md` 宽度与 `surface.md` §2 次要文字。
5. **元数据位置**：检查 `hierarchy.md` §1 单字段单位置与 `layout.md` 对齐。

每个维度用一句话记录改了什么。没有可改处时，写出截图里支持该判断的观察。页面打不开时按 §4 记为未检查。

## 4. 验收

验收只覆盖改动触及的 reference 小节与改动影响的渲染状态，每步执行一次。只用现成可达的页面、数据与登录态。

1. **静态扫描**。运行以下命令，修复到输出为空：

   ```bash
   node <skill 目录>/scripts/ui-guardrails.js --changed <目标项目路径>
   ```

   `--changed` 只扫描相对 `HEAD` 的改动。改动已提交时传入分支起点（例如 `--changed=main`）。脚本自动跳过组件库、第三方、测试与 skill 目录。组件库外观按 §1 基线表核对。任意圆角、任意间距、内联 style 与 CSS 色值人工核对。

2. **渲染检查**。开发服务器能直接打开改动页面时，在目标项目目录运行：

   ```bash
   node <skill 目录>/scripts/render-check.js <改动页面 URL>...
   ```

   脚本在 375×812 与 1280×800 两个视口运行 `render-audit.js`，各截一张整页图并输出 JSON。
   - 修复改动范围内的每项 `violations`。`secondary.descriptions` 按 `hierarchy.md` §1 次要文字限额逐条定去留。
   - 查看截图，按 `hierarchy.md` §4 逐项检验。
   - 需要交互才能到达的状态，有浏览器工具时操作到位后，通过 evaluate 执行 `scripts/render-audit.js`（整个文件是一个无参函数）并截图。无法解析 playwright 时，两个视口也按此方式完成。
   - 页面要登录、要后端数据或没有浏览器工具而打不开时，渲染检查记为未检查，交付原因与没看到的状态。

3. **交互核对**。改动涉及交互或动效时，在渲染检查的同一次会话里把改动的触点操作一遍，核对 `interaction.md` §1 的键盘主流程与浮层落焦、回焦。`prefers-reduced-motion` 读代码核对。

改动触及的每个小节写一条结论并附证据。已修复的项写 `file:line` 与改法。通过的项写截图、操作记录或 audit 输出里的观察。没执行的检查写未检查与原因。

交付内容包括：改动位置、字段去留表与打磨记录（新建页面或重组信息时）、各小节结论、audit 输出与截图路径，以及范围外的违规。
