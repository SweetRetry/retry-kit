# 微交互与交互反馈

微交互是「触发 → 规则与状态 → 反馈 → 焦点收尾」的闭环；过渡时长设为 `0ms` 后，语义与可操作性必须完整。

## 1. 控件级微交互

- **热区**：独立控件至少 `24×24px`，窄屏主操作 `40–44px`；紧凑视觉用伪元素（`relative before:absolute before:-inset-2`）扩区，段落行内链接除外。
- **即时与短循环**：独立开关与轻量切换点击即生效，不配保存按钮；短时确认（复制、同步）在触发控件原地切换约 `1.5–2s` 后复原，复原前再点重置计时，不额外弹 toast；相邻 Tooltip 跳过开启延迟即时切换。
- **校验（晚报错、早消错）**：失焦或提交时报错，报错态下随输入实时消错；提交失败聚焦首个报错字段。
- **禁用可解释**：需要告知解锁条件时写可见前提，或用 `aria-disabled="true"` 保持可聚焦并就近提示。
- **焦点闭环**：打开浮层落到首个输入或安全项（破坏性弹窗绝不自动聚焦破坏性按钮）；`Escape` 只退最内层并回焦触发器；删除当前项后焦点顺移相邻项或空态入口，不掉回 `body`。
- **可打断**：连续操作与浮层开关随时从当前状态衔接新意图，业务逻辑不等动画结束。

## 2. 反馈形态

由两个问题决定，不看消息严重程度：

1. **用户要在原处修改输入吗？** 要 → 就地 inline：字段错误在字段旁（配 `role="alert"`），对话框内的提交失败留在对话框内。toast 消失会带走修正入口，这类错误不用 toast。
2. **状态持续多久？** 一次性结果（保存、删除、导出）→ 自动消失的 toast（`toast.success` / `error`），成功不弹 Dialog。持续状态保持可见直到解除：局部的（无数据、加载失败）落在所在区域，按成因（首次使用、筛选无结果、无权限、加载失败）给出下一步操作；全局的（连接中断）用固定 `id` 的驻留 toast，恢复时 `toast.dismiss(id)`。

- 同一动作只给一种反馈。
- toast 只写一句话，细节留在原处。
- 批量部分失败用一条 `toast.warning`，带成功与失败数。
- 局部提交的等待放在触发按钮内；只有跨页面或原上下文已消失的长任务用 `toast.loading` 取 `id`，结束时用同一 `id` 转为 success / error。

## 3. 等待与恢复

结果可撤销且极少失败 → 乐观更新（optimistic update）：先按成功渲染，提交前保存快照，失败时回滚并就近说明，不以刷新代替恢复。不可逆或常失败 → 悲观更新（pessimistic update）：等服务端确认再变更界面，反馈放在触发控件上。

| 等待时长 | 反馈 |
| :--- | :--- |
| < 100ms | 直接完成，不加 Loader |
| 100ms–1s | 触发控件内局部反馈，不遮蔽上下文 |
| 1s–10s | 展示真实执行状态，进度与步骤有真实来源 |
| > 10s 或持续数据流 | 提供取消或离开后重入；区分停止客户端等待与取消服务端工作 |

- **防重**：会重复扣款、创建或写冲突的操作按下即防重；可安全重复或持续输入的操作不禁用。
- **竞态**：切换、分页、筛选时丢弃不属于最新意图的响应。
- **保留输入**：提交、校验或网络失败后保留已填内容与选项。
- **不可逆**：在不可逆时点前确认影响范围，或提供有效撤销。
- **破坏性操作隔离**：不与正向主按钮紧挨并列。弹窗与表单底部正向主按钮在端侧，破坏性按钮取弱样式并拉开间距；菜单中破坏性条目置于最底部，用 `DropdownMenuSeparator` 隔开并取 `variant="destructive"`。
