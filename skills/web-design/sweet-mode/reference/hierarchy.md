# 信息层级与渐进式披露

先理清信息关系，再选组件承载。

## 1. Canvas 与 Chrome

压缩 Chrome，把视区留给 Canvas 与焦点：

- **Canvas**：用户此刻处理的工作对象（流程的当前步骤、看板的数据、工具里的作品）与它的大块留白。对象越需要专注，Chrome 越让位。
- **Chrome**：导航、筛选、工具栏与上下文属性，取完成任务所需的最小体量。
- **焦点**：推进任务的主操作或偏离常态的状态，连同隔离它的留白。单线流程只留一个推进主操作；主操作归属当前步骤尚未完成的目标动作（收集输入时在底栏提交键，交付结果供取用时在内容区的取用动作而非底栏关闭键）。

- **列表靠留白分组**：用留白、共享左对齐轴与 `space-y-*` 组织。Card 只给语义、结构和操作同级的对象，卡片不套卡片。
- **元数据安静**：`text-xs text-muted-foreground`；Badge 只给强状态或核心分类。
- **一个字段一个位置**：不用 `·`、`•`、`|`、`/` 把多个字段拼成一行，标题里也不拼状态。每个字段先按「每条信息有增量」定去留，留下的各占结构位置：分组、对齐的列或行尾、图标、Badge。
- **权重决定大小**：主导指标单独放大，次要指标紧凑排列。
- **平涂表面**：表面只用 Token 色平涂，层次靠明度差。不用渐变文字、彩色渐变、光晕、纹理与玻璃卡片。渐变只做两件事：压在图片与视频上托住文字和按钮的遮罩，滚动边缘的淡出；色标只取 `transparent`、`black` / `white` 透明度或表面 Token。模糊只用 `backdrop-blur-*` 透出下方滚动的内容。
- **图标有配额**：图标只出现在纯图标按钮（`size="icon*"`）、导航或菜单的同级扫视锚点（同组全有或全无）与异常状态提示。页面标题、CardTitle、DialogTitle、纯文字 Tab 与常规文字按钮（保存、取消、提交、确认）不加图标；图标不放进彩色圆形或方块底色。
- **每个元素有真实承接**：元素来自需求与现有产品，并接上真实数据源或事件逻辑。不渲染假搜索框、通知铃、装饰头像菜单、空链接、页头凑数统计卡与没有历史基线的涨跌百分比；列表预期不超过一屏（≤ 7 项）且无服务端过滤时，不放搜索框、筛选器与分页器。
- **标题自明不写描述**：CardTitle、DialogTitle 或区块标题已交代工作对象时，不补 CardDescription 或副标题重述；说明文字只写不写就会引发误操作的业务约束。
- **宽表优先**：数据表格享有最高水平空间优先级，横向滚动或全宽，不为旁侧内容压缩列宽。
- **每条信息有增量**：每句文字、数字与标签都是一条陈述。用户从界面已能得到的（标题含义、可见项数量、控件已表达的状态）和不影响任何判断或操作的（其他角色的权限、系统内部归属）删除；有用但不满足 §2 判据的延后披露。字号与颜色不改变一条信息是否多余。

## 2. 渐进式披露（Progressive Disclosure）

以当前场景的用户任务为单位，满足任一条直接呈现，其余延后披露：

1. **影响此刻决定**：缺少会判断错误或阻断流程（代价、不可逆后果、禁用原因、报错、立即生效还是异步）。原因未知时写明未知，不补造诊断。
2. **需要并排比较**。
3. **当前任务的高频主操作**。

披露载体由四个问题推出：

1. 保留当前上下文 → 就地展开或锚定浮层；脱离且须专注 → 模态或独立页。
2. 临时查看 → 易关闭的浮层；持续使用 → 留在内容流（折叠区、分段切换、侧栏）。
3. 纯解释 → 最轻的提示；含输入或选择 → 可聚焦、可键盘操作的载体。
4. 互斥 → 同一时间只显示一个分支；并列 → 分组后折叠次要组。

常见结果：Popover / DropdownMenu（保留上下文、临时、含交互）；Tabs / ToggleGroup / Accordion（保留上下文、持续或互斥）；Dialog / Sheet（脱离、须专注）；独立路由（需深链或分享）。推不出时沿用应用内同类场景的处理，同类内容全应用一种披露方式。

披露边界：

- 只有一两个次要操作，或折叠后入口比原内容更难懂时，直接呈现。
- 表格行只留识别与判断所需的列和主操作，其余操作进尾部溢出菜单，详情进抽屉或详情页。
- 专业工具与设置的高频项一次点击可达，危险设置直接可见。
- 悬停只做增强：后果、禁用原因、报错与操作都有不依赖悬停的可见入口，触屏与键盘可达。
- 披露入口是带可访问名称的图标或带状态的标签，不依赖隐藏手势。
- 浮层不嵌套浮层；二级内容改为模态内分步或锚定浮层。
- 展开后的内容不推翻用户基于收起态已做出的判断。

## 3. 功能编排

菜单、导航、工具栏、设置页等多操作容器用位置回答“这项操作作用于什么”。先给每项定归属（作用对象与影响范围），再推出分组与顺序：

- **位置即归属**：作用于同一对象的条目聚成一组，紧贴该对象；由一组内容派生的操作（新建、批量、查看全部）留在组内。只在归属改变处分组。
- **顺序沿单一维度**：组间按离当前上下文由近到远，入口图标与文案承诺的用途排最前；组内按当前任务的使用频率。离开当前上下文或不可逆的操作排在所属组末尾，与同组条目隔开。
- **一个对象一个位置**：选能同时承接它的状态（当前、选中）与管理操作的那一处。列表行只能承接选择时，把该对象提出列表单独呈现并带上操作。
- **名称脱离位置仍成立**：同类操作作用于不同对象并存时，名称写出作用对象；只有一个对象时省略。
- **权重跟随可交互性**：分组标题、元数据等不可交互文字的视觉权重低于可交互条目。

## 4. 检验

- **缩略图**：整页截图缩到约 400px 宽查看，首要焦点、分组与阅读路径仍清楚，无等权区块混战。
- **Data-ink ratio**：逐项移除卡片、边框、背景、图标、颜色与动效，不损失信息或意符（signifier）的不恢复。
- **同级**：重复结构的对象语义、结构与操作相同；不等价对象已用排序、分组、占比或密度区分；同级图表共享基准轴，面积与数值线性对应。
- **移植**：只换文案后，组织方式能直接套给无关业务，说明构图由模板主导，按内容重做。
- **窄屏**：375px 截图中靠重排保持层级与操作，关键内容完整，正文字号不变。
