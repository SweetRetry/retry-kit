# 一致性与设计漂移

## 概念

- **内部一致性**（internal consistency）：同一种东西在产品里每个地方的做法都一样。用户在一处学会的，到别处直接可用。
- **外部一致性**（external consistency，Jakob's law）：与平台惯例和用户在其他产品里学到的一样。两者冲突时外部优先，除非产品有明确理由并在全应用统一地偏离。
- **设计漂移**（design drift）：内部一致性在长期迭代中被侵蚀。每次改动只参照离它最近的代码或临时发明，局部都说得通，累积起来同一种东西有了三四种做法。Agent 编码会加速漂移：它按局部上下文生成看起来合理的新变体，而不去找已有的那一个。
- **语义判据**：差异只用来表达语义差异。相同的东西看起来、用起来相同；不同的东西看起来、用起来不同。危险操作更醒目是语义；两个同级主按钮高度差 4px 不是。反向违例同样计入：语义不同却长得一样（可恢复删除与永久删除用同一个确认框）。

## 漂移分层

逐层盘点。每层先用代码定位全部实现，再用渲染确认用户实际看到的差异；只看渲染会漏掉还没出现在走查路径上的变体，只看代码会漏掉样式覆盖造成的视觉差异。

| 层 | 同类物 | 代码里找 | 渲染里看 |
| --- | --- | --- | --- |
| 取值 | 颜色、字号、圆角、间距、阴影、z-index、时长与缓动 | 绕过 Token 的任意值、近似重复值（`#333` 与 `#343434`，13px 与 14px） | census 同角色多签名 |
| 组件 | Button、Input、Dialog、Dropdown、Table、Toast、DatePicker、Avatar、Empty | 同一原语多份定义（`Button`、`MyButton`、`ButtonV2`、页面内手写 `<button className=...>`）；同一职责多个库（两个图标库、两个 toast 库、两个日期库）；调用点用 `className` 覆盖变体外观 | 同角色多签名、同角色交互不同 |
| 模式 | 删除与确认、表单校验时机、提交与保存模型（自动保存或显式保存）、加载（spinner 或 skeleton）、报错（toast 或就地）、空状态、新建入口（弹窗或页面）、列表行操作（悬停图标或溢出菜单）、分页（页码、加载更多或无限滚动）、搜索与筛选位置 | 每种模式的全部实现，按做法分组计数（`confirm(` 与 AlertDialog，`toast.error` 与就地错误） | 走查中同类操作的步骤与反馈不同 |
| 结构 | 页头构成（标题、面包屑、主操作位置）、内容宽度、区块间距、设置页布局、详情页布局 | 各页面的布局组件与外层容器 | 同类页面截图并排比较 |
| 语言 | 同一对象的名称、同一动作的动词、大小写与标点、语气、日期数字货币格式、单位 | 界面字符串与 i18n 文件里的同义词组；格式化调用（`toLocaleDateString`、`format(`、`dayjs(`） | census 的 terms，走查截图里的格式 |
| 行为 | Esc 与回车、点击外部是否关闭、关闭后焦点回到哪里、返回键、筛选与分页是否进 URL、默认排序、乐观或悲观更新、撤销是否可用、必填标记 | 各弹层与列表的事件处理与路由同步 | 走查中逐一按键验证 |

## 判定与规范变体

每类同类物盘点出全部变体后：

1. 按语义判据分成「有语义」与「漂移」。拿不准时问：用户能说出两者为什么不同吗？说不出就是漂移。
2. 漂移组选一个**规范变体**，依次看：设计系统或 Token 文件已定义的 → 外部惯例 → 最近一次有意决策（提交说明、设计文档）→ 使用次数最多的。写出选择依据。
3. 写出**收敛清单**：偏离规范变体的每处位置与数量，便于估算修复量与写 codemod。

## 根因与防复发

漂移会在修复后重新长出来，除非补上让它无从发生的结构。每条漂移写出缺失的那个结构，并给出对应的护栏：

| 缺失 | 护栏 |
| --- | --- |
| Token 或 Token 未被强制 | 补语义 Token；lint 禁止任意值与硬编码色值 |
| 共享组件 | 抽出唯一实现，变体收进组件；`no-restricted-imports` 禁止旧实现与第二个同职责库 |
| 模式约定 | 把模式做成组件或 hook（`useConfirmDelete`、统一的请求反馈层），让正确做法成为最省事的做法 |
| 词表 | 建领域词表文件，界面字符串经词表或 i18n key 取值；lint 或脚本检查同义词 |
| 格式化 | 唯一的格式化工具函数，禁止调用点直接格式化 |
