# SaaS 文案组件与反 AI 腔参考

编写或改写具体控件、校准领域术语或清理 AI 腔时按需查阅。

## 产品形态与称谓

按产品实际的组织治理模型选用称谓，不跨模型借词：

| 产品形态 | 容器 | 人员与身份 | 典型关系动作 | 边界提醒 |
| --- | --- | --- | --- | --- |
| **团队协作**<br>（文档、设计、研发、项目管理） | 工作区、团队、项目、空间 | 成员、访客、协作者、管理员、所有者 | 邀请、加入、移出、分配、共享、转让所有权 | 不用“员工、下属、部门、工号、离职”等行政称谓 |
| **企业管控**<br>（HR、财务、OA、IAM、ERP） | 组织、企业、部门、主体 | 员工、部门负责人、审批人、组织管理员 | 录入、入职、调岗、离职交接、授权、审批 | 保持正式清晰，不用松散或娱乐化称谓 |
| **多租户商户**<br>（电商后台、CRM、客服台） | 店铺、站点、商户、环境（生产 / 测试） | 内部：运营、客服、子账号；外部：客户、买家、订阅者 | 上架、发布、派单、接待、分群、封禁 | 明确区分内部操作者与外部终端客户，不统称为“用户” |
| **个人工具**<br>（单人创作、笔记、效率工具） | 账户、个人空间、库、合集 | 直接称呼资产，必要时用 `你 / 你的` | 创建、导入、导出、发布、分享链接、备份 | 不暴露多余的“工作区、席位、管理员”层级 |

## 动作词边界

按数据后果选唯一动词：

| 类别 | 标准动词与后果边界 |
| --- | --- |
| **新建与引入** | `创建 / 新建`（从零生成） · `添加`（将已有项纳入集合或接入配置） · `导入`（从文件或外部系统批量迁入） · `邀请`（通知成员加入） |
| **解除与销毁** | `移出`（解除成员与工作区/项目归属，账号保留） · `移除 / 取消关联`（拿掉集合中的引用，原对象保留） · `归档`（冻结隐藏，保留且可恢复） · `移至回收站`（软删，限期可恢复） · `永久删除`（物理清除，不可恢复） |
| **凭证与状态** | `启用 / 停用`（开关功能、规则、集成或账号） · `吊销 / 撤销`（令密钥、令牌、邀请或授权立即失效） · `重置`（恢复默认或重新生成凭证） |
| **流转与交付** | `保存`（持久化修改） · `发布 / 应用`（使配置或内容生效） · `提交审批`（进入审核） · `导出`（生成下载文件） · `同步`（与外部源拉齐） |

批量与容器规则：

- **批量沿用单项动词加范围词**：行内 `删除` 对应页头 `全部删除`（`Delete` / `Delete all`），不另起容器动词（如用 `清空回收站` / `Empty trash` 造成同一后果有两个动词）。确认弹窗用 `永久删除全部项目？` + `[全部永久删除]`。
- **容器已锁定后果时简化行内按钮**：在回收站里删除只能是永久删除，行内按钮单用 `删除`（`Delete`），不可逆字样留给确认弹窗。

## 常见控件落字

| 控件 | 做法 | 干净示例 |
| --- | --- | --- |
| **导航、Tab、表头、菜单** | 2–4 字（英文 1–2 词）；同级统一词性与颗粒度，相邻项首字可区分 | `成员 / 权限 / 账单`；`Members / Roles / Billing` |
| **操作按钮** | 具体动词，容器未锁定对象时补对象；同组一项补对象则其余项同步补齐；取消与次要按钮保持中立 | `邀请成员`、`创建密钥`、`取消`、`暂不升级`；`Invite member`, `Create key`, `Not now` |
| **确认弹窗** | 标题直问动作与对象，不用“温馨提示”或“你确定要……吗”；正文只写实际后果、影响范围与资产去向；主按钮原样复刻标题动词 | 标题 `移出林夏？` / 正文 `移出后立即失去工作区访问权限，其创建的文档保留在工作区。` / 按钮 `[取消]` `[移出]`<br>标题 `Delete "Q4 Plan" permanently?` / 正文 `14 files and shared links will be removed. This can't be undone.` / 按钮 `[Cancel]` `[Delete permanently]` |
| **空状态** | 区分三种情形：<br>1. 首次使用且对象自明（项目、任务）：只写现状 + 按钮，不说教；<br>2. 首次使用且属配置/集成：现状 + 一句交代当前产品实际用途 + 按钮；<br>3. 筛选/搜索无结果或已清零：说清原因 + 清除入口（或安静留白） | 1. `暂无项目` + `[新建项目]`<br>2. `暂无 Webhook` / `任务变更或发布完成时，向你的服务推送事件。` + `[添加 Webhook]`<br>3. `没有匹配的成员` + `[清除筛选]`；`全部已读` |
| **表单与搜索** | 标签写简洁属性；占位符放真实格式示例或可搜字段，不写“请输入……”；固定规则放输入框旁，不藏进占位符；报错内联写达标条件 | 标签 `工作邮箱` / 占位符 `name@company.com`；搜索框 `搜姓名或邮箱`<br>校验错：`至少 8 位，需包含字母和数字` |
| **Toast、Banner、状态标签** | Toast 用 3–8 字说已完成事实，可逆附 `[撤销]`；驻留 Banner 说明全局状态与处理入口；状态标签 2–4 字对称短语 | `已保存`、`已移至回收站` `[撤销]`、`链接已复制`<br>状态：`运行中 / 已停用 / 待审批 / 已逾期` |
| **报错、权限与配额** | 说清具体原因与此刻可做的事；不甩锅，不空泛致歉；非开发者界面不裸露内部报错码 | `需要工作区管理员权限才能修改安全设置。`<br>`当前套餐上限 5 名成员。` + `[升级套餐]`<br>`保存失败，网络已断开。` + `[重试]` |
| **计费与开发者设置** | 计费写清单位、周期、生效时机与折算；密钥与集成交代一次性可见与吊销即断 | `¥99 / 成员 / 月，按年付折算`；`立即生效，按剩余天数折算差价`<br>`密钥仅显示一次，请立即保存。`；`吊销后，使用该密钥的请求将立即失败。` |

## 反 AI 腔校准

AI 写 SaaS 文案常落入下面四种假腔，改写时对照右侧回归平实具体：

| 常见 AI 腔 | 典型表现 | 回归平实具体 |
| --- | --- | --- |
| **营销虚词与口号体** | “一站式高效管理团队成员，轻松协同增效” / “极速同步 — 实时拉齐，告别等待” / “Streamline and elevate your workflow effortlessly” | 删掉副标题，或只写具体规则：`免费版包含 5 名成员，访客不计入席位` / `修改后自动同步至外部数据源` |
| **机器人说明书与公文腔** | “尚未添加 Webhook。添加后可在工作区事件触发时自动推送通知至外部服务。” / “系统已成功为您保存修改” / “对记录进行导出操作” | `暂无 Webhook` + `任务变更或发布完成时，向你的服务推送事件。` / `已保存` / `导出记录` |
| **英文直译与底层泄漏** | “你确定要删除这个项目吗？” / “还没有任何项目” / “发生了一个错误，请稍后重试” / “Token 校验失败 (401)” | `删除「项目名」？` / `暂无项目` / `保存失败，请重试。` / `登录已过期，请重新登录。` |
| **拟人撒娇与情绪施压** | “这里还空空如也哦，快来创建吧！” / “残忍拒绝” / “✨ 升级解锁无限可能！” | `暂无文档` + `[新建文档]` / `暂不升级` / `[升级至专业版]` |

## 中英文落字惯例

- **中文**：直接以对象或动词起句，省去多余的“一个、你的、任何、已被、将会、从而、用于”；短标题、按钮、Toast 和表格内短语不加句号，完整陈述句加句号；日常界面不用感叹号与装饰 Emoji；中英文及数字间的空格习惯与项目现有文案保持一致。
- **英文**：标题、Tab、按钮与表单标签默认用 Sentence case（除非产品已有明确的 Title Case 规范）；优先主动语态与短动词（`Save`、`Remove`、`Revoke`、`Copy link`）；正常界面可使用自然缩写（`Can't connect`、`You don't have access`），除非产品明确走正式合规语调。
