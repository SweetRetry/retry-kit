# 取值模式

比较对象是色彩、字体、圆角、密度、层级表达或动效参数时使用。细微差异本身就是要判断的东西，但先定立场再细分。

1. **只为会改变使用感受且尚未决定的维度做选项**。每个维度先给少数一眼可辨的立场，每个立场都是这个产品说得通的选择，能说出它适合哪种使用情境或产品性格；“不用”说得通时也是一个立场，如无强调色、只用描边。选项按感知效果命名（冷、暖、紧凑、宽松），数值本身就是通用说法时才用数值作标签。立场选定后，下一轮在它附近细分，直到再细分已看不出差别。
2. **只做一个画面**。复制模板后只保留一个 section，放一张 Foundations 样张（色彩配比、表面层级、圆角、字阶、状态、按钮与输入）和一到两张真实页面，用真实内容。
3. **选项落在变量上**。每个维度做成一组选项控件，切换时改写 `:root` 上的 shadcn 变量（`--primary`、`--radius`、`--font-sans` 等）或根节点 data 属性，Basecoat 组件与 utility 同时跟随；各维度自由组合，整个画面同步变化。控件固定在画面一角，是这个模式下画布唯一允许的非候选 UI。
4. **每轮交付**路径、各维度当前的选项，以及需要用户判断的组合问题。用户反馈后，各维度删去落选项，或在选定立场附近细分；选定的维度删除控件，取值写死到 `:root`。
5. **收尾**。所有控件删除后剩下的画面就是设计版，记录全部选定取值供 design.md 与 Token 引用；是否留存、留在哪里由用户决定。

完成标准：每轮各维度的选项数不增加；所有控件删除并获用户确认。
