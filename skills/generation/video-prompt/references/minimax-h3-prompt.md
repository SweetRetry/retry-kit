# MiniMax H3 Prompt Reference

只在目标入口明确为 MiniMax-H3 时使用。素材解释、信息顺序、格式与能力限制以本文件为准；其余内容与连续性原则见 `video-prompt` 主文档。

官方依据：[Video Generation Guide](https://platform.minimax.io/docs/guides/video-generation.md)、[H3 Prompt Examples](https://platform.minimax.io/docs/guides/video-prompt.md)。

## 1. 先选 prompt 模式

| 模式 | 写作目标 |
| --- | --- |
| Text-to-Video | 从文字建立完整场景、主体、连续动作、摄影机、光色和声音 |
| First／Last-Frame | 将给定画面作为严格开场、结尾或两者，正文只描述中间的自然变化与到达方式 |
| Reference-to-Video | 从图片、视频、音频中继承指定的角色、动作、镜头、风格、音色或节奏，再生成新故事 |

- 每次只按一种模式组织 prompt。首尾帧是开始／结束画面的锚点，不把它们写成普通风格参考；参考素材则必须说明每份素材控制哪个维度。

## 2. 素材可用性

- 首帧／尾帧最多 2 张图片；图片宽高为 `256–5760`，宽高比为 `2:5–5:2`。
- 参考模式最多使用 9 张图片、3 个视频、3 个音频，合计不超过 12 个文件。每段参考视频或音频为 `2–15s`，同类型总时长不超过 15 秒。
- 图片支持 JPG、JPEG、PNG、WEBP、HEIC、HEIF；视频支持 H.264/AVC、H.265/HEVC；音频支持 WAV、MP3。单文件上限：视频 50 MB、图片 30 MB、音频 15 MB；整次素材请求不超过 64 MB。
- 素材超出上限、格式不被支持或时长不合规时，先替换、剪短或拆分素材；不要继续输出会引用无效素材的 prompt。

## 3. 参考素材 prompt

官方 gallery 的多参考组织是“格式／媒介 → 素材编号与职责 → Core story → Tone／style → 可见的镜头、剪辑和声音”。

1. 先逐项绑定：`Image 1: mood, setting, film grain. Image 2: character. Image 3: product. Video 1: motion rhythm. Audio 1: voice timbre.`
2. 写 `Core story`：主体在哪里、从什么状态开始、如何行动、与谁或何物发生何种可见关系、结束画面是什么。
3. 写 `Tone`、style、剪辑节奏、声音设计与必须准确出现的屏幕内容。

- 多个素材不是自动合并；角色身份、产品外观、场景气质和动作来源有冲突时，回到“编号—职责”重新划分，不让模型猜测优先级。
- Reference video 可以控制动作、镜头或节奏，reference audio 可以控制音色、音乐、节拍或氛围；正文必须写清继承层与当前故事主动改变的层。

## 4. 无素材与首尾帧 prompt

- 无素材时，从媒介／构图开始，再写主体、空间、连续动作链、镜头行为、光色、声音和结束画面。短视频只保留一个核心观看任务和可读的状态变化。
- 首帧或尾帧模式中，正文描述人物、物体、摄影机和环境怎样从锚点进入下一状态；不要重述锚点已确定的静态外观。
- 官方示例允许直接写构图、媒介、镜头距离、表演张力、环境声和视觉材质；把它们绑定到当前时段的可观察结果，不堆叠抽象形容词。

## 5. Camera 与声音

- 将 camera movement 紧随它所作用的画面或动作之后。官方示例展示 `[pan]`、`[zoom]`、`[static]`。
- 其他摄影机行为用自然语言写机位起点、路径、速度和结束构图；不把其他 MiniMax 模型的 bracket command 迁移到 H3。
- 声音写声源、环境、角色声音或节奏，并在需要时绑定到剧情或动作点。

## 6. 输出前检查

- 当前模式、素材编号、职责与故事彼此一致；多份 reference 已完成“编号—职责”绑定。
- 素材数量、格式、尺寸、时长和文件大小符合第 2 节；无效素材已在写 prompt 前处理。
- 每个时间段都有可见动作、摄影机和必要声音，首尾状态与参考素材的继承范围不冲突。
- H3 的 bracket tag 只使用官方示例支持的形式；不把本文件的编号写法或 tag 迁移到其他模型。
