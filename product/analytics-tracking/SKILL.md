# Analytics Tracking

## 1. 核心心智模型 (Mental Model)

一条数据/事件有价值，**当且仅当它的数值变化能直接改变未来的产品、增长或业务决策动作**。
如果数值高、低或异常时，团队采取的下一步完全相同，该数据即为系统与认知噪声。

## 2. 价值推导四重判据 (Value Criteria)

判断任何事件或指标“该不该建/该不该留”，必须全部通过以下判据：

1. **业务疑问明确**：能明确写出一句可由该数据回答的具体业务问题（写不出问题则不埋）。
2. **消费主体与时机**：有明确的读者（产品/运营/增长）与固定的决策触发场景（无读者则无价值）。
3. **决策动作闭环 (If-Then-Else)**：数值变化能明确触发不同行动（如“若流失率 > X% 则触发 A，否则维持 B”；写不出动作分支则属于好奇心噪声，不埋）。
4. **不可替代性 (Non-derivability)**：无法从已有事件的属性（properties）或现有服务端事实中聚合推导出来；严禁重复埋点。

## 3. 信号与噪声对照表 (Signal vs. Noise)

### 天然高价值信号 (High Value Signals)
- **核心价值到达**：用户成功获得产品核心承诺的结果（验证是否交付价值）。
- **关键漏斗断点**：有序链路中的进入、提交、成功、阻塞与流失节点。
- **业务状态机跃迁**：核心对象从一个确定状态进入下一状态。
- **高意图探索**：搜索、精确筛选、保存、导出、分享等代表真实需求强度的动作。
- **失败与摩擦**：表单校验阻断、权限拦截、支付失败、接口异常（比单纯看成功数更能驱动迭代）。

### 噪声过滤清单 (Noise Patterns)
- **UI 细节与业务解耦**：仅记录纯视觉点击、无业务语义的坐标/动效，未对应业务事实。
- **可派生冗余**：能通过计算已有事件的时间戳或属性直接得出的中间事件。
- **命名语义漂移**：事件名携带动态值或页面层级；应统一为稳定业务事件名，差异收敛至 property。
- **客户端权威失真**：关键业务成功状态由客户端单方面上报而非以服务端权威事实为准。

## 4. 输出交付准则 (Delivery)

- **自适应交付**：根据审查（Review）或全新规划（Plan）任务，自适应呈现“业务问题 ↔ 建议事件 ↔ 剔除项与原因 ↔ 聚合复用方案”。
- **聚焦决策**：交付内容聚焦于数据如何驱动动作，不展开冗长套话文档。
