# 构图目录 (Composition Catalog)

> 本文件只描述布局结构和空间关系，用于页面结构决策与叙事编排。

---

## 使用方式（独立版）

将本文件用于 `Page Flow` 产出阶段，不用于视觉参数定义。

- Quick 模式：先选 1 个 Hero 构图 + 1 个核心 Section 构图，确保页面能快速落地。
- Deep 模式：为每个构图补充“为什么选它”“替代方案是什么”“潜在风险是什么”。
- 若信息不足，可用 `[Assumption]` 标注，不阻塞输出。

建议映射：

- `Page Flow`：从本文件选构图并写入每段的叙事作用。
- `Optimization Backlog`：优先处理“构图与产品类型不匹配”或“密度连续过高”的问题。

## 一、Hero 构图详解

### 1. Split（左文右图）

**结构：** 左侧文案区（标题 + 副标题 + CTA）+ 右侧视觉主体，各占约 50%。

- **变体：** 右文左图（视觉主体在左，适合 RTL 或想打破惯性时）
- **响应式退化：** 移动端堆叠——文案在上，视觉主体在下
- **最佳匹配：** UI 型 SaaS，产品截图本身即卖点
- **避免：** 视觉主体是横向宽幅内容（如全景视频），强行压缩到半屏效果差

### 2. 居中堆叠

**结构：** 标题居中 → CTA 居中 → 视觉主体在下方占满宽度。

- **变体：** 视觉主体在上方（产品截图预览 → 标题 → CTA），适合"先看产品再读文案"的策略
- **响应式退化：** 天然适配窄屏，无需结构性调整
- **最佳匹配：** 产品演示视频、Dashboard 全幅截图、需要宽幅展示的工具
- **避免：** 文案过长导致视觉主体被挤出首屏

### 3. 全幅沉浸

**结构：** 大幅媒体主体（图片/视频）占满整个视口，文案叠加在上层。

- **变体：** 叠层文本（主媒体 + 遮罩层 + 文案层）；分区叠层（媒体占 2/3，文案区占 1/3）
- **响应式退化：** 移动端可改为固定背景 + 滚动文案，或退化为居中堆叠
- **最佳匹配：** 品牌驱动的产品、创意工具、需要视觉冲击力的场景
- **避免：** 主媒体信息密度不足却强行全屏；文案层与主体信息互相干扰

### 4. Editorial

**结构：** 超大标题占据主视觉位置，辅助视觉元素（小图、图标、装饰线）作为配角点缀。

- **变体：** 标题 + 右下角小图预览；标题跨行排版 + 行间嵌入小视觉元素
- **响应式退化：** 标题字号缩小，辅助视觉移到标题下方
- **最佳匹配：** 概念型产品（AI、区块链）、内容平台、文案本身就是最大卖点
- **避免：** 有实际产品 UI 需要展示但没放——用户会想"这产品到底长什么样？"

### 5. Product Showcase（产品展台）

**结构：** 产品（实物渲染/3D/大号截图）居中放大，文案在上方或环绕产品。

- **变体：** 单产品居中 + 辅助说明；多角度产品展示（并列或轮播）
- **响应式退化：** 产品缩小居中，文案移到产品上方
- **最佳匹配：** 实体商品、硬件产品、设计工具、需要突出产品形态的 App
- **避免：** 产品视觉不够精致——产品展台会放大一切细节，低质素材会适得其反

### 6. 交互先行

**结构：** 可操作的交互元素（搜索框、代码编辑器、命令行、配置面板）作为 Hero 的视觉主体。

- **变体：** 输入框 + 实时结果预览；代码片段 + 运行按钮；可拖拽的演示组件
- **响应式退化：** 交互区域全宽，简化交互复杂度（减少拖拽，增加点击）
- **最佳匹配：** 开发者工具、搜索引擎、AI 产品（输入 prompt → 看结果）
- **避免：** 交互逻辑复杂到用户首次使用就卡住——Hero 的交互必须零学习成本

## 二、Section 构图详解

### 1. Bento Grid

**结构：** 不等尺寸的卡片组成网格，用面积编码功能优先级。主功能占 2×2 或 1×2，次要功能占 1×1。

- **密度：** 高——信息量大，视觉节奏紧凑
- **节奏角色：** 信息密集区，适合放在呼吸留白之后
- **响应式退化：** 移动端退化为单列堆叠，按优先级排序

### 2. Feature Zigzag

**结构：** 左图右文 → 右图左文交替排列，每行介绍一个功能。

- **密度：** 中——每个功能有独立空间展开
- **节奏角色：** 中段叙事主力，适合逐步建立信任
- **响应式退化：** 移动端全部变为图上文下的单列
- **注意：** 图片应展示实际产品 UI 或具体场景，避免使用纯装饰性插画。与任务无关或“广告样式化”的视觉元素更容易被忽略。

### 3. Icon Grid

**结构：** 等宽网格（3×2 或 4×2），每格：图标 + 标题 + 一句利益描述。

- **密度：** 中——信息分散但数量多
- **节奏角色：** 轻量信息展示，适合功能列举
- **响应式退化：** 移动端 2 列或单列

### 4. Sticky Scroll（滚动叙事）

**结构：** 左侧文案列表（可点击/可滚动），右侧视觉区域随选中项切换内容。基于 `position: sticky` 实现的 scrollytelling 模式。

- **密度：** 高——信息和视觉都很丰富
- **节奏角色：** 深度功能展示，适合需要演示多个状态的产品
- **响应式退化：** 移动端变为纵向手风琴，点击展开图片

### 5. Stats Section（数据统计带）

**结构：** 3–4 个大号数字横向排列，每个数字下方有简短标注。

- **密度：** 低——信息点少，视觉留白大
- **节奏角色：** 呼吸区 + 信任信号，适合在密集 Section 之间做过渡
- **响应式退化：** 移动端 2×2 网格或纵向堆叠

### 6. 时间线

**结构：** 垂直或水平连线，3–5 个步骤节点，每个节点含序号 + 标题 + 简述。

- **密度：** 中——线性叙事，节奏清晰
- **节奏角色：** How It Works 的最佳载体，降低复杂度认知
- **响应式退化：** 水平时间线移动端转为垂直

### 7. 对比分割

**结构：** 左右对比（Before/After）或上下对比（Without/With），用分割线或滑块区分。

- **密度：** 中——对比本身就有视觉张力
- **节奏角色：** Pain→Solution 的视觉化表达，制造认知反差
- **响应式退化：** 移动端改为上下堆叠对比

### 8. Statement Section（声明区）

**结构：** 居中大段文案（1–2 句核心信息），可搭配单一辅助视觉（插画/图标/引用标记）。

- **密度：** 低——大量留白，聚焦单一信息
- **节奏角色：** 呼吸区，用于品牌宣言、核心理念、或密集 Section 后的视觉缓冲
- **响应式退化：** 天然适配窄屏

## 三、产品类型 × 构图匹配速查表

| 产品类型 | 推荐 Hero | 推荐 Features 构图 | 节奏建议 |
|----------|-----------|-------------------|----------|
| **SaaS 工具**（UI 型） | Split / 居中堆叠 | Bento Grid · Sticky Scroll | 密→疏→密：Hero(密) → Social Proof(疏) → Features(密) → Stats(疏) → CTA |
| **开发者 API / CLI** | 交互先行 / Editorial | Icon Grid · 时间线 | 交互→解释→信任：Hero(交互) → Icon Grid(中) → 时间线(中) → Stats(疏) → CTA |
| **概念型产品**（AI / 区块链） | Editorial / 全幅沉浸 | Feature Zigzag · 对比分割 | 叙事驱动：Hero(Editorial) → 对比分割(中) → Zigzag(中) → Statement(疏) → CTA |
| **电商 / DTC 消费品** | Product Showcase / 全幅沉浸 | Bento Grid · 对比分割 | 视觉冲击：Hero(Showcase) → Stats(疏) → Bento Grid(密) → 证言(中) → CTA |
| **B2B 企业服务** | Split / 居中堆叠 | Feature Zigzag · Sticky Scroll | 信任优先：Hero(Split) → Social Proof(疏) → Zigzag(中) → Stats(疏) → Pricing → CTA |

## 四、密度曲线示例

### 示例 A：SaaS 成长期产品（7 个模块）

```
密度  ██████  ▓▓  ██████  ▓▓  ████  ▓▓  ████
模块  Hero    SP  Bento   Stats Zigzag Stmt  CTA
构图  Split   Bar Grid   数据  交替   声明  居中
密度  高      低  高      低    中     低    中
```

SP = Social Proof Bar

### 示例 B：开发者 API（5 个模块）

```
密度  ██████  ████  ████  ▓▓  ████
模块  Hero    Icons  时间线  Stats CTA
构图  交互    Grid   垂直   数据  居中
密度  高      中     中     低    中
```

### 示例 C：消费品 DTC（6 个模块）

```
密度  ██████  ▓▓  ██████  ████  ████  ████
模块  Hero    Stats Bento  对比   证言   CTA
构图  展台    数据  Grid   分割   卡片   居中
密度  高      低    高     中     中     中
```

密度交替的核心原则：高密度 Section 之后接低密度 Section，让用户有"呼吸"的空间。连续两个高密度 Section 会造成信息过载。
