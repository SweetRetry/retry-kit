# Landing Structure

## 工作流程

### 第一步：收集上下文

从用户输入中提取以下信息。至少需要前 3 项才能输出有效方案；缺失项用 `[Assumption]` 标注，不阻塞输出。

| 必要项 | 说明 |
|---|---|
| 产品价值 | 一句话说清产品做什么 |
| 目标用户 | 谁、当前痛点是什么 |
| 主转化目标 | 页面唯一的目标动作（注册 / 购买 / 下载 / 获取 API Key…） |

| 可选增强项 | 影响 |
|---|---|
| 产品阶段（MVP / 成长 / 成熟） | 影响模块选择和信任信号策略 |
| 行业类型（SaaS / 开发者工具 / DTC / 移动应用） | 影响模块组合和 CTA 风格（见行业模式） |
| 已有信任素材 | 客户 Logo、案例数据、媒体背书、GitHub Stars 等 |
| 受众意识阶段 | 影响文案框架选择（见下文） |
| 价格策略 | 是否需要 Pricing 模块 |
| 流量来源 | 付费广告 / 自然搜索 / 社交 / 邮件 — 影响 Hero 消息匹配 |
| 语言 / 地区 | 影响文案风格和合规要求 |

### 第二步：确定文案框架

根据受众对产品的了解程度选择框架。冷流量偏场景与问题，暖流量偏差异与证据。

| 受众意识阶段 | 常用框架 | 页面策略 |
|---|---|---|
| **完全不知道** | AIDA（注意→兴趣→欲望→行动） | 用场景唤醒痛点，再引出方案 |
| **知道问题** | PAS（痛点→放大→方案） | 先共鸣痛点，再展示产品如何解决 |
| **知道方案** | BAB（现状→理想→桥梁） | 聚焦竞品差异和选择理由 |
| **知道产品** | 社会证明 + 异议消除 | 用案例和 FAQ 消除最后的犹豫 |
| **最了解** | 直接报价 / 限时优惠 | 短页面，CTA 前置 |
| **品牌叙事型** | StoryBrand | 用户是主角，产品是向导 |
| **需要先造欲望** | 4Ps | 承诺开场，证明收束 |

框架可以混用；不明确时默认 PAS。卖点必须能落到用户结果；Hero 必须呼应引流来源的承诺。

### 第三步：选择模块

每个模块都要回答“它如何推动用户走向 CTA”；回答不了就删。

**核心模块**（几乎所有落地页都需要）：

| 模块 | 作用 |
|---|---|
| Hero | 10 秒内讲清「这是什么、给谁、为什么重要」 |
| 主 CTA | 唯一目标动作。长页面在首屏和尾部各放一次，中间再放 1-2 次 |

**选配模块**（按需选择）：

| 模块 | 加入条件 | 作用 |
|---|---|---|
| Social Proof | 有真实客户 / 数据 / 背书 | 用真实数据降低信任门槛 |
| Pain → Solution | 受众未充分意识到痛点 | 先共鸣再给方案 |
| Features / Benefits | 核心卖点 ≥ 3 个 | 讲清能力与收益 |
| How It Works | 产品流程理解成本高 | 用 3 步降低认知门槛 |
| Interactive Demo | 产品可即时体验（尤其开发者工具、AI 产品） | 让用户先试后买，显著降低理解成本和试用门槛 |
| Comparison Table | 用户在横向对比竞品 | 用结构化对比引导选择 |
| Testimonials | 有真实案例和数据 | 用他人的成功消除犹豫 |
| Pricing | 价格影响决策 | 透明比较与锚定。放在社会证明之后（先证明价值再谈价格） |
| Objection Handling / FAQ | 存在重复异议 | 消除临门一脚的阻力 |
| Footer | 始终保留 | 法务与次要入口 |

### 第四步：匹配行业模式

确定行业类型后，读取 [references/industry-patterns.md](references/industry-patterns.md) 获取参考组合；不匹配时跳过。

### 第五步：组织叙事

将模块排成一条线性说服链，每一段都要把用户推向下一步。

#### 叙事排序检验

- 前一个模块建立的认知，是否被下一个模块利用？
- 是否有模块打断了说服链（用户看到这里会想"所以呢？"）？
- 信息密度是否有变化？连续多个重信息段会导致阅读疲劳

**节奏规则**：不要连续放两个以上重信息模块（Features、How It Works、Pricing）。在它们之间插入低密度模块（Stats Section、Statement、Logo Wall）作为呼吸区。

#### 页面长度决策

| 因素 | 倾向长页面（1000+ 词） | 倾向短页面（< 500 词） |
|---|---|---|
| 产品复杂度 | 高，需要解释 | 低，一看就懂 |
| 受众熟悉度 | 新产品/新品牌 | 已知品牌 |
| 决策成本 | 高价/高承诺 | 低价/免费试用 |
| 信任基础 | 弱，需要大量证明 | 强，已有口碑 |

没有普遍赢家。用解释成本、决策风险和信任门槛决定篇幅。

构图词汇用于描述每个模块的信息骨架（Split、Bento Grid、Timeline 等），详见 [references/composition-catalog.md](references/composition-catalog.md)。这些是结构描述工具，不是视觉指令——选择哪种构图取决于信息类型，视觉呈现由设计环节决定。

### 第六步：标题与 CTA

#### 标题原则

- **清晰 > 创意**：具体标题通常比模糊标题更稳定，也更容易形成消息匹配
- **一句话传达**：这是什么 + 给谁 + 为什么重要
- **6 词左右最佳**，不超过 12 词
- **利益导向**：不说"USB 充电六刀便携搅拌机"，说"随时随地，一杯健康奶昔"

**常用标题公式**：

| 公式 | 结构 | 示例 |
|---|---|---|
| How-To | "如何 [利益] 而不 [痛点]" | "如何让团队每周少开 3 场会" |
| 具体结果 | "[数字] + [时间] + [结果]" | "28 天，让你的皮肤说出改变" |
| 问题式 | 直击痛点的提问 | "还在手动分配任务？" |
| 证言式 | 借他人之口 | "[客户类型] 如何用 [产品] 实现 [结果]" |

#### CTA 原则

- **唯一目标**：一个页面只保留一个主 CTA 动作；次要动作要降级，避免目标竞争
- **重复放置**：在首屏、关键说服节点和尾部重复出现同一个 CTA，每次配不同的支撑文案
- **按钮文案**：2-5 词动作短语，用具体利益替代通用词

| 弱 | 强 | 原因 |
|---|---|---|
| 提交 | 免费获取 API Key | 说明用户将得到什么 |
| 了解更多 | 看看 30 秒 Demo | 降低行动成本感知 |
| 注册 | 免费开始 — 无需信用卡 | 消除风险顾虑 |
| 开始 | Start Building with X | 具体化动作 |

- **位置效果**：不要把唯一 CTA 埋在页面底部；首屏和关键节点都应能看到明确的行动入口
- **风险消除微文案**：在 CTA 按钮附近加一行小字消除犹豫（"无需信用卡"/"随时取消"/"30 天退款保证"）

### 第七步：信任信号策略

#### 信任信号分层

| 层级 | 类型 | 示例 | 放置位置 |
|---|---|---|---|
| Tier 1：即时信誉 | 可一眼验证的硬指标 | 客户 Logo 墙、用户数、GitHub Stars | Hero 下方 / 紧跟首屏 |
| Tier 2：具体证言 | 有名有姓有数据的案例 | "转化提升 35% — 张明，XX 公司产品总监" | 中段，Features 之后 |
| Tier 3：权威背书 | 第三方认证和专家引用 | 行业认证、媒体报道、专家评价 | 中后段 |
| Tier 4：安全信号 | 降低交易风险 | 安全徽章、退款保证、隐私承诺 | CTA 附近 |

**核心规则**：
- 只使用真实可验证的素材
- 没有信任素材时，不放 Social Proof 模块——空洞的信任区比没有更糟糕
- 评论/证言通常能降低犹豫，但必须真实、具体、可验证
- 购买前查看评价是常见行为，因此评价展示要优先强调真实性而不是数量堆砌
- 早期产品替代方案：团队背景、开源记录、公开路线图、Beta 用户数

### 第八步：自检

输出方案后，过一遍以下检查项。如果发现问题，直接修正后再交付：

| 维度 | 检查 |
|---|---|
| 清晰度 | 首屏能否在 5 秒内传达价值主张？ |
| 消息匹配 | Hero 标题是否呼应了引流来源的承诺？ |
| 唯一性 | 是否只有一个主 CTA？有没有竞争性目标动作？ |
| 说服力 | 卖点是停在术语还是到达了用户利益？ |
| 信任感 | 社会证明是否真实可验证？有没有伪造的数据？ |
| 完整性 | 用户的核心异议是否被回答了？ |
| 节奏 | 是否有连续的高密度模块？中间有没有呼吸区？ |
| 移动端 | 模块在单列堆叠后是否仍然通顺？CTA 按钮是否容易点击？ |
| 可删减 | 有没有删掉后不影响转化的模块？ |

## 输出格式

按问题范围选择输出粒度。只问局部问题时，不输出完整方案。

### 完整方案（用户要求规划整个落地页时）

```
## Context
产品、用户、主 CTA、阶段、行业类型、文案框架选择理由

## Page Flow
| 序号 | 模块 | 构图 | 叙事作用 | 与 CTA 的关系 | 信息密度 |
（每行一个模块）

## Hero + CTA
- 标题：2 个候选
- 副标题：1 个
- 主 CTA：2 个候选（含风险消除微文案）

## Gaps
- [Assumption] 标注假设
- 列出缺失信息及其影响

## Next Steps
- 2-3 条最高优先级的优化建议
- 每条包含：做什么 / 预期影响 / 验证指标
```

**多变体意识**：当用户提供了不同的流量来源或受众群体时，在方案中标注哪些模块/标题/CTA 应为不同来源准备变体版本。

### 局部优化（用户只问某个模块时）

直接给出该模块的方案，不需要输出完整的 5 段格式。但要说明该模块在整体叙事中的位置和作用。

## 常见反模式

| 反模式 | 怎么发现 | 影响 | 怎么修 |
|---|---|---|---|
| 多 CTA 竞争 | 页面有多个目标动作在争抢注意力 | 用户难以判断下一步，主目标被稀释 | 选一个主 CTA，其余降级或删除 |
| 术语堆砌 | 卖点全是产品内部用语，用户看不懂 | 用户 5 秒内跳出 | 对每个卖点追问"用户得到什么" |
| 模板填充 | 模块齐全但内容空洞（如空的 Testimonials） | 空洞信任区比没有更糟 | 没有真实内容支撑的模块直接删 |
| 信任伪造 | 编造的数据、不存在的客户 | 被发现后信任崩塌 | 替换为真实素材或删掉模块 |
| 节奏单调 | 连续多个信息密集的模块 | 阅读疲劳导致中途放弃 | 在重信息段之间插入轻量过渡 |
| 消息断裂 | Hero 标题与引流广告/链接的承诺不匹配 | 用户感到"来错了地方"直接跳出 | Hero 标题必须呼应流量来源 |
| 移动端忽视 | 只按桌面端设计，未考虑单列堆叠效果 | 移动端阅读链条断裂，CTA 更容易被错过 | 从单列堆叠视角审视模块顺序和 CTA 大小 |
| CTA 埋没 | CTA 只在页面底部出现一次 | 错过早期决策者 | 首屏、中段、尾部各放一次 |
