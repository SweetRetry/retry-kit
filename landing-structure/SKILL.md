# Landing Structure — 独立可执行版

## 目标与边界

本规范只处理落地页的结构与叙事，可独立执行。

- 模块组合：选择哪些 Section，删掉哪些 Section
- 叙事顺序：先讲什么，后讲什么
- 转化路径：用户如何从首屏走到主 CTA
- 文案框架：将特性翻译为用户利益
- 构图策略：为每个 Section 选择合适结构

不处理具体视觉参数（色值、字号、间距、动效时长）与框架实现细节，除非用户明确要求生成代码。

## 使用模式

### Quick 模式（默认）

适用于信息不完整、用户要快速结果的场景。

- 缺信息时先产出可执行草案
- 明确标注 `[Assumption]`，不阻塞输出
- 先给页面流和 CTA 草案，再迭代细化
- 同步给出一条最小验证动作（看哪个指标、何时复盘）

### Deep 模式

适用于高风险页面（大促、投放、正式上线）。

- 先补齐关键信息再输出
- 对每个模块给出保留/删除理由
- 输出风险与验证计划（必须落在固定输出格式中，见第 5 段）
- 每个关键决策都绑定验证指标，避免“只给建议不落地”

## 输入契约

至少获取以下 3 项；其余可选：

1. 产品价值（一句话）
2. 目标用户（谁、当前痛点）
3. 主转化目标（唯一主 CTA）

可选增强项：产品阶段、信任素材、价格策略、区域/语言。

当信息不足时，按 Quick 模式继续，并在输出中列出缺口。

## 工作流程

1. 提炼目标：定义唯一主 CTA，确认成功动作，并指定本轮关注指标（`Primary CTA CTR` / `CTA Reach Rate` / `Conversion Rate` 至少 1 项）
2. 选模块：按阶段与信息密度选最小可行模块集；无法证明价值的模块先不放
3. 排顺序：构建线性叙事，确保每段都推进 CTA；长页面在首屏与末段都要有主 CTA 触点
4. 写文案：Hero 与核心卖点执行 "So What?" 三级跳，避免术语堆砌
5. 自检与迭代：删除填充模块，补齐信任与异议处理，并给出下一轮单变量验证动作

## 页面架构决策

### 必选模块

| 模块 | 作用 |
| --- | --- |
| Hero | 10 秒内讲清「这是什么、给谁、为什么重要」 |
| 主 CTA | 明确唯一目标动作。长页面建议在首屏和末段各出现 1 次；单屏或超短页可只出现 1 次 |

说明：该条是结构经验规则，不是法规要求。最终以页面目标和实验数据（如点击率、到达率、转化率）校正，并在 `Assumptions & Gaps` 记录取舍原因。

### 选配模块

| 模块 | 何时需要 | 作用 |
| --- | --- | --- |
| Nav | 页面较长或多锚点 | 导航与品牌锚定 |
| Social Proof | 有客户/数据/背书 | 降低信任门槛 |
| Pain → Solution | 用户痛点未被唤醒 | 先共鸣再给方案 |
| Features / Benefits | 核心卖点 3 个以上 | 讲清能力与收益 |
| How It Works | 流程理解成本高 | 降低复杂度认知 |
| Testimonials | 有真实案例 | 用结果消除犹豫 |
| Pricing | 价格影响转化决策 | 透明比较与锚定 |
| FAQ | 存在重复异议 | 消除临门一脚阻力 |
| Footer | 始终建议保留 | 法务与次要入口 |

### 阶段化默认组合

| 阶段 | 推荐最小组合 |
| --- | --- |
| 早期 MVP | Hero → Features → CTA |
| 成长期 | Hero → Social Proof → Features → How It Works → Testimonials → CTA → FAQ |
| 成熟期 | Hero → Pain/Solution → Pricing → Testimonials → CTA → FAQ |

## Hero 与 CTA 标准

### Hero 标题检验

读完标题后，用户应能回答：

1. 产品帮我完成什么具体动作？
2. 我会得到什么结果？

避免空洞定位句（如“领先平台”“一站式方案”）。

### CTA 文案检验

- 动词开头
- 包含具体利益
- 与真实承诺一致

避免泛词（如“提交”“了解更多”）作为主 CTA。

## 文案框架：So What? 三级跳

每个卖点按以下顺序转换：

`技术特性 -> 直接利益 -> 终极利益`

示例模板：

`我们提供 [特性]，因此你可以 [直接利益]，最终实现 [终极利益]。`

若无法从特性推导到终极利益，该特性不应进入落地页主叙事。

## 构图与节奏

目标：信息密度交替，防止阅读疲劳。

- 高密段：Hero、核心功能说明
- 低密段：数据带、声明区、过渡 CTA
- 焦点迁移：避免连续 2 段完全同重心布局

常用构图词汇：Split、Centered Stack、Bento Grid、Zigzag、Icon Grid、Timeline、Before/After、Statement。

## 信任信号策略

只使用真实可验证素材：

- 客户 Logo
- 可量化结果（时间节省、转化提升等）
- 第三方背书（认证/媒体/评测）
- 早期阶段可用：团队背景、公开路线图、开源记录

禁止伪造社会证明。

## 必须输出格式

每次输出必须包含以下 5 段：

1. `Context Snapshot`
- 产品、用户、主 CTA、阶段、已知信任素材

2. `Page Flow`
- 用表格列出：Section / 目标 / 核心信息 / 与 CTA 的关系

3. `Hero + CTA Draft`
- Hero 标题 2 个候选
- 副标题 1 个
- 主 CTA 文案 2 个候选

4. `Assumptions & Gaps`
- 显式列出 `[Assumption]` 与缺失数据

5. `Optimization Backlog`
- 3 条优先优化建议（按影响从高到低）
- 每条建议必须包含：`Action` / `Expected Impact` / `Metric`

Deep 模式附加要求：第 5 段必须追加以下两个子段。

- `Risk Register`：列出前 3 个转化或可信度风险（含触发条件与影响）。
- `Validation Plan`：列出对应验证动作（事件埋点、A/B 假设、成功阈值）。

## 审查清单

- 是否只有一个主转化目标？
- 首屏是否能在 10 秒内讲清价值？
- 每个 Section 是否都推动 CTA？
- 卖点是否完成三级跳，而非停留在术语？
- 是否存在不真实或不可核验的社会证明？
- 是否有可删掉且不影响转化的填充模块？
- 是否为本轮结构改动指定了验证指标与复盘时间？

## 反模式

| 反模式 | 症状 | 处理 |
| --- | --- | --- |
| 多 CTA 竞争 | 页面出现多个主目标动作 | 只保留一个主 CTA，其余降级为辅助 |
| 特性堆砌 | 全是术语，缺少用户收益 | 对每个特性执行三级跳 |
| 模板填充 | 模块齐全但信息空洞 | 删除无真实信息支撑模块 |
| 信任真空 | 无任何可信依据 | 补一个真实信任信号模块 |
| 节奏单调 | 连续高密段造成疲劳 | 插入低密过渡段 |
