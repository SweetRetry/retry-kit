# Tool Use 描述写法

聚焦 System Prompt 中的工具定义（Tool Definition）质量，使模型准确识别何时用何工具、如何传参。不覆盖运行时编排。

## 四个质量维度

| 维度 | 用途 | 常见问题 |
|------|------|----------|
| `name` | 识别身份，快速分类 | 太泛（`process`）或太长 |
| `description` | 判断何时调用 | 只描述功能，不描述触发场景 |
| `parameters.description` | 理解参数含义和约束 | 缺类型/范围/示例 |
| 工具间边界 | 多工具选择 | 描述重叠导致随机选择 |

## name：命名规范

**格式**：`snake_case`，动词 + 名词。

**原则**
- 动词精确：`get`（只读）/ `search`（模糊查询）/ `create` / `update` / `delete` / `send`（外部动作）
- 名词具体：不用 `data`/`info`/`item`，用 `user_profile`/`order_detail`
- 长度：≤ 4 个单词

## description：描述写法

**三段式**：`[做什么] + [何时用] + [不适用场景（可选）]`

**触发场景**：明确列出触发工具的用户意图或关键词。

**边界声明**：功能相似的工具在 description 中互相声明边界，指向对方工具名。

## parameters：参数设计

**每个参数必须包含**
```json
{
  "name": "snake_case 参数名",
  "type": "string | number | boolean | array | object",
  "description": "含义 + 约束 + 示例",
  "required": true/false
}
```

**description 三要素**：含义 + 约束（类型/范围/格式）+ 示例值。

**枚举值**：description 中列出所有合法值及含义。

**可选参数**：说明缺省时的默认行为。

## 多工具场景：避免选择稀释

工具数 > 8 或 description 语义重叠时，模型选择准确率下降。

**缓解策略**
1. **工具分组**：在 `<context>` 中按数据查询 / 操作执行 / 外部服务等逻辑分组
2. **选择指导**：在 `<task>` 中给出决策树（意图 → 工具）
3. **精简工具集**：单次暴露 ≤ 8 个；必须超过时按意图动态注入子集

## 自检
- 所有 name 是否 `snake_case` + 动词开头？
- description 是否含「何时用」而非只描述功能？
- 相似工具是否声明彼此边界？
- 每个参数是否含义 + 约束 + 示例齐全？
- 枚举参数是否列出所有合法值？
- 可选参数是否说明缺省行为？
- 工具 > 8 个时是否分组声明？
