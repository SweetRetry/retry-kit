# 四要素结构详解

## P — Persona 角色设定

赋予模型明确身份，决定回复口吻、深度和专业程度。

**写作要点**
- 一句话定义：**专业领域 + 资历级别 + 行为风格**
- 角色越具体，输出越稳定
- 可叠加行为约束（语气、表达偏好）

**反模式**
- 角色过载：一个 Persona 塞入不相关能力
- 角色空泛：无领域锚定
- 角色矛盾：行为约束与身份冲突

## T — Task 任务描述

**写作要点**
- 祈使句开头，一句话说清核心动作
- 复杂任务拆解为有序步骤
- 精确动词：分析 / 生成 / 转换 / 评估
- 指定完成标准

**反模式**
- 任务模糊（"帮我看看"）
- 步骤缺失（只给终点不给路径）
- 多任务混杂

## C — Context 上下文背景

**写作要点**
- 回答三问：**为什么做 / 给谁看 / 边界在哪**
- 用 `<context>` 标签包裹
- 仅提供模型无法自行推断的信息
- 关键术语给出明确定义

**反模式**
- 上下文过载（整本文档塞入）
- 上下文缺失
- 隐含假设（默认模型懂业务术语）

## F — Format 输出格式

**写作要点**
- 明确结构类型：JSON / 表格 / 列表 / 代码块
- 提供输出骨架（skeleton）
- 关键字段说明数据类型和约束
- 放在 `<format>` 标签内

**反模式**
- 格式模糊（"整齐一点"）
- 格式过度（简单问答强套 JSON）
- 格式与任务脱节

## 组装顺序与优先级

顺序：`Persona → Context → Task → Format`（符合"身份 → 背景 → 行动 → 呈现"的认知流程）

| 优先级 | 模块 | 说明 |
|--------|------|------|
| 最高 | Task | 任务不清晰，其他再好也白搭 |
| 高 | Context | 缺上下文只能猜边界 |
| 中 | Format | 格式错可重生，但浪费 token |
| 基础 | Persona | 影响风格和深度，不影响正确性 |

**模块协同**
- Persona 决定 Task 执行深度
- Context 约束 Task 执行范围
- Format 匹配 Task 消费场景
- 四模块互相印证，不应矛盾
