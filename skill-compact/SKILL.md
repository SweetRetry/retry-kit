# Skill Compact

## 目标

删掉不改变行为的内容，同时保住三件事：

1. 触发边界
2. 决策规则
3. 输出约束

## 工作流程

### 1. 先找核心能力

先写一句话回答：

- 这个 skill 的核心职责是什么
- 哪些内容绝对不能删
- 哪些相邻职责应该拆出去

没有这一句，不要开始删内容。

### 2. 逐段判断动作

每段内容只允许落到这四类之一：

- `Keep`：触发条件、关键 workflow、输出模板、会改变行为的稳定规则——删了会伤到触发、决策或输出
- `Condense`：同义重复、长解释、可更短表达的规则——保留意思，压缩表达
- `Move`：时效性实践、行业变体、benchmark、长案例、有争议的补充——下沉到目标 skill 的 `references/`
- `Delete`：不影响行为的背景知识、可有可无的附加章节、会诱导照抄的完整范文、单一来源且不关键的硬结论

当前这个元 skill 可以保持单文件；这里的 `Move` 指目标 skill 在 compact 后应如何处理内容。

### 3. 按风险从低到高删减

1. 删重复解释、教学腔背景
2. 删冗长示例、单一来源的硬规则
3. 降级或删除弱规则
4. 合并相邻章节
5. 最后才动核心 workflow、输出格式和 frontmatter

如果某段删掉后会少一个关键决策或关键产物，那段就不该删。

### 4. 专门检查过拟合

重点看：

- frontmatter / 触发描述是否过宽，试图覆盖相邻任务
- 示例是否多到诱导照抄
- 时效性实践是否写死在 `SKILL.md`（无日期、无来源）
- 单一来源观点或软经验是否被写成默认规则
- 一个 skill 是否塞进了多个相邻职责
- 是否把某个 agent 产品的局部习惯误写成通用规则（如必须保留，标注为环境前提）

### 5. 行为验证

至少用几条 prompt 验证：

- 该触发的还能触发，触发没有变过窄
- 不该触发的不再误触发
- 局部请求不会被拉成大而全答案
- 决策表没有被删到只剩空口号
- 输出格式仍能稳定交付

## 交付格式

```md
## Findings
- 触发问题
- 过拟合问题
- 知识分层问题
- `references/` 组织问题

## Delete
- 直接删除

## Condense
- 保留但压缩

## Keep
- 不能动的触发、规则、输出

## Residual Risks
- 仍可能过宽、过窄或示例过强的点
```
