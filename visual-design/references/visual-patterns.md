# 视觉结构模式库（执行版）

用于在 `Elevate` / `Forge` 中快速选择页面构图。`Elevate` 默认做结构重排，不输出模板化保守布局。

---

## 选择矩阵

| 页面类型 | Preserve | Elevate | Forge |
|---------|--------|---------|---------|
| Dashboard / Workbench | 保持现有壳层 | 优先 `Dashboard Shell` + `Data Hero` + `Zig-Zag` 信息区 | 可加局部品牌区，但主工作区不重排 |
| Landing / Marketing | 保持已有骨架 | `Split Hero` + 1 个差异化 Feature 结构 | 可用 `Immersive Hero` + 节奏化 Section |
| Settings / Form | 维持单栏可读性 | 优化分组和层级 | 不建议重技法 |
| Empty State / Onboarding | 保守引导 | 允许轻品牌语气 | 可增强首屏记忆点 |

---

## 风格签名到构图映射

| 风格签名 | Hero 首选 | Feature 首选 | 禁止项 |
|---------|----------|--------------|-------|
| `Precision Editorial` | `Split Hero` / `Data Hero` | `Zig-Zag` | 大面积炫光与重材质叠加 |
| `Cinematic Minimal` | `Immersive Hero` | `Single Visual` + 节奏段落 | 多焦点并列 CTA |
| `Neo-Modern Brutal` | `Split Hero`（硬分割） | `Bento`（硬边界） | 软糯圆角与弱对比 |
| `Soft Tech Luxury` | `Split Hero`（柔层次） | `Bento` + 局部沉浸区 | 全页纯平无材质变化 |

## Hero 模式

### 1) Split Hero（默认推荐）

```txt
[左侧] 标题 + 描述 + 主 CTA
[右侧] 产品图/示意图
```

适用：大多数产品介绍页、功能介绍页  
回退：移动端改单列，媒体内容下沉

### 2) Data Hero（Tool）

```txt
[标题/筛选]
[3-4 个核心指标卡]
```

适用：仪表盘首页、运营看板  
回退：指标卡过多时拆为两行，保持可读性

### 3) Immersive Hero（Brand）

```txt
[强视觉背景]
[单一主叙事 + 单一主 CTA]
```

适用：品牌页、发布页  
风险：信息密度过低导致转化弱  
回退：增加辅助描述和次级证据区

---

## Feature Section 模式

### 1) Zig-Zag（交替左右）

```txt
Section1: 文左图右
Section2: 图左文右
Section3: 统一收束（居中或单栏）
```

适用：连续介绍 3+ 功能点  
回退：内容过短时直接改单栏列表

### 2) Bento（主次分明）

```txt
[主卡(2x)] [副卡]
[副卡]     [副卡]
```

适用：功能信息密度不均  
回退：改为两列网格，移除跨行主卡

### 3) Single Visual（单视觉焦点）

```txt
标题 + 描述
单张主视觉/演示区
```

适用：一个核心卖点需要被放大  
回退：缩小视觉区，补充要点列表

---

## 应用页模式

### Dashboard Shell

```txt
[Sidebar] [Main]
Main: Topbar + Content
```

建议：边界层次用一种主方法（边框或底色差）

### Settings Stack

```txt
标题
分组1（字段）
分组2（字段）
底部操作区
```

建议：优先可读性与操作稳定，不引入重动效

### Empty State

```txt
图标/插图
标题
说明
唯一主 CTA
```

建议：视觉弱化，动作清晰化

```md
- 方案：...
```

## 反保守检查

若是新页面或用户要求”高级感/重做”，输出前必须满足：

1. 至少 1 处明显构图变化
2. 至少 1 处清晰视觉焦点
3. 移动端有可读性回退

## 信息架构反模式（Audit 必查）

以下模式是视觉混乱的根因，先于视觉审查诊断。

### 反模式 A：领域大杂烩

**特征**：
- 单页同时出现不同业务实体的 CRUD 操作（如”用户 + 订单 + 商品”在同一页管理）
- 导航入口分属 3+ 个独立业务域但都放在同一层级
- 页面标题无法概括页面全部内容（说明内容已溢出单一领域）

**处方**：
- 按业务域划分路由，每条路由对应一个领域
- 引入二级导航或 Tab 承接同域内的多个视图，而非跨域混用
- 参考 `Dashboard Shell` 模式，用子路由隔离领域边界

---

### 反模式 B：信息密度失控

**特征**：
- 首屏无滚动可见元素 > 12 个（按钮、链接、输入框等可交互元素）
- 同屏数据指标 > 8 个且无主次区分
- 卡片内同时包含统计数字、操作按钮、状态标签、列表

**处方**：
- 遵循”5 ± 2”信息组规则，同屏有效信息组控制在 3–5 个
- 次要信息折叠（Collapse / Tooltip / Drawer）
- 高频操作前置，低频操作收进”更多”菜单
- 使用 `Data Hero` 模式聚焦 3–4 个核心指标，其余下沉

---

### 反模式 C：功能分区未规划

**特征**：
- 区块之间无明确分隔（视觉边界缺失导致”流”在一起）
- 相似操作分散在页面不同位置（同一操作的触发入口 > 2 处）
- 内容区与操作区混排，用户无法预判”在哪里点”

**处方**：
- 引入”区块可命名”原则：用 `aria-label` 或视觉标题锚定每个功能区
- 操作收拢：同一实体的所有操作放在同一 ActionBar / ContextMenu
- 用底色差或边框明确区隔内容区 / 操作区 / 导航区

---

### 反模式 D：导航层级坍塌

**特征**：
- 全局导航、页面导航、内容导航混在同一层（用户无法判断”现在在哪里”）
- 面包屑、Tab、侧边栏同时出现且语义重叠
- 点击导航项无明确激活态反馈

**处方**：
- 三层导航分层：全局导航（Sidebar/Topbar）→ 页面导航（Tab/Sub-nav）→ 内容导航（锚点/步骤条）
- 同一层级内只保留 1 种导航组件，不混用
- 激活态必须有颜色 + 位置双重视觉信号

---

### 快速判断卡

在 Audit 时先运行此卡，命中即标注对应反模式：

```
□ 无法用一句话概括这个页面”是干什么的”       → 反模式 A（领域混杂）
□ 首屏看完眼花，不知从哪里开始              → 反模式 B（密度失控）
□ 页面区块之间没有视觉边界或命名             → 反模式 C（分区未规划）
□ 导航多且重叠，不清楚”现在在哪”            → 反模式 D（导航层级坍塌）
```

命中 `≥ 2` 条 → 先做信息架构重构，再做视觉优化。
