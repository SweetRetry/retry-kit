# 网页设计美学原则

所有视觉决策必须能追溯到以下某条原则。**原则优先于模式**。
本文件讲设计判断，不讲 CSS / token 等工程实现。

---

## 1. 视觉层级 (Visual Hierarchy)

**用户扫描页面的顺序应该是被设计的，不是随机的。**

### 层级的四个维度

不要只靠尺寸。**最好的层级同时使用 2-3 个维度**：

| 维度 | 强层级 | 弱层级 | 常见失败 |
|------|--------|--------|---------|
| **尺度** | ≥ 3:1 | < 2:1 | 14/15/16/18 泥浆层级 |
| **字重** | Bold vs Regular | Medium vs Regular | 全文同一字重 |
| **色彩** | 高对比 | 相近色调 | 所有文字同色 |
| **空间** | 重要元素被留白包围 | 均匀分布 | 均匀=无焦点 |

### 自检：层级失败 vs 层级成立

```
失败（泥浆层级）              成立（强层级）
─────────────────             ─────────────────
功能介绍                       FUNCTION
我们的产品有以下特点           ─────────────
功能一 说明文字说明文字         我们的产品
功能二 说明文字说明文字         有以下特点
功能三 说明文字说明文字
                              ► 功能一
所有元素同字号同字重            说明文字
视线无处着陆                   ► 功能二
                              说明文字

                              尺度 3:1 + 字重 Bold/Regular
                              + 缩进 + 空间隔离
```

### 排版层级原则

**用更少的尺寸、更大的对比**。5 级覆盖绝大多数需求：xs / sm / base / lg / xl+。
比例选一个并坚持：1.2 / 1.25 / 1.333 / 1.5 / 1.618（小到大对应工具感→编辑感）。

### 垂直节奏

行高是所有垂直间距的基准单位。文字与空间共享同一套数学基础——间距感才会自然。

### Squint Test

把页面模糊后还能识别"最重要、第二重要、清晰分组"吗？模糊后所有东西一样重 = 层级失败。

## 2. 排版 (Typography)

**排版是界面的骨架。90% 的网页设计是排版。**

### 网页排版的特殊性

| 维度 | 印刷 | 网页 |
|------|------|------|
| 媒介 | 反光（纸张） | 发光（屏幕） |
| 尺寸 | 固定 | 从 375px 到 2560px 可变 |
| 行长 | 可控 | 必须设计上限，否则大屏上无法阅读 |
| 字体 | 确定可用 | 可能加载中、可能回退 |
| 行高 | 固定值 | 需考虑不同字号的视觉补偿 |

### 字体选择：避免隐形默认

Inter、Roboto、Open Sans、Lato、Montserrat、Poppins 到处都是——用了就是 AI 味。

| 你想要 | 别用 | 改用 |
|--------|------|------|
| 中性无衬线 | Inter / Roboto | Instrument Sans / Onest / DM Sans / Figtree / Plus Jakarta Sans |
| 编辑/高级感 | Playfair Display | Fraunces / Newsreader / Lora |
| 几何感 | Montserrat / Poppins | Outfit / Bricolage Grotesque |
| 性能优先 | （随便挑无衬线） | 系统字体栈（原生、即时、零成本） |

### 字体配对：通常不需要

一个家族用不同字重就能创建清晰层级。**配对前先问：单字体真的不够吗？**

如果配对，必须在多个轴上制造**强对比**：

| 对比轴 | 例子 | 效果 |
|--------|------|------|
| 衬线 vs 无衬线 | Fraunces × 中性无衬线 | 结构对比 |
| 几何 vs 人文 | Outfit × Newsreader | 性格对比 |
| 窄体 vs 宽体 | 窄体 Display × 常规 Body | 比例对比 |

**永远不要配对相似但不同的字体**——视觉效果像 bug 不像设计。

### Display / Heading / Body 的视觉重量配比

不同气质要的反差不同：

| 设计范式 | display:body 比例 | display 字重 | body 字重 |
|------|-------------------|--------------|-----------|
| Typographic-First | 4:1 ~ 6:1 | Light / Regular（靠尺寸） | Regular |
| Geometric & Technical | 2:1 ~ 3:1 | Medium / Semibold | Regular |
| Content-Immersive | 5:1 ~ 8:1（首屏夸张） | Bold / Black | Regular |
| Data-Dense & Utility | 1.5:1 ~ 2:1 | Semibold | Regular |
| Human-Centric & Soft | 3:1 ~ 4:1 | Medium | Regular |

### 行长 / 行高 / 字距判断标尺

| 文本类型 | 行长（字符） | 行高 | 字距 |
|----------|-------------|------|------|
| 长文阅读 body | 60–75 | 1.5–1.7 | 0 |
| 界面 body | 45–65 | 1.4–1.5 | 0 |
| Heading | 不限 | 1.1–1.25 | -0.01em ~ -0.02em |
| Display 大字 | 不限 | 0.95–1.1 | -0.02em ~ -0.04em |
| 全大写 / 标签 | 短 | 1.0 | +0.05em ~ +0.1em |
| 数字（表格） | — | — | 等宽数字 / tabular-nums |

**判断口诀**：字越大行高越紧、字越大字距越紧；全大写必须加正字距；数字表格必须等宽。

### Fluid 还是固定

- **标题/展示文字**：可以流式缩放（视口越大字越大）
- **App UI / Dashboard / 数据密集界面**：固定尺度，不流式。没有主流设计系统在产品 UI 中用 fluid type

### 自检：排版失败 vs 排版成立

```
失败（性格冲突）              成立（强对比配对）
──────────────                ──────────────
Welcome to our        →       Welcome to
amazing product               our amazing
[Montserrat Bold              product
 + Poppins Regular]           [Fraunces 56/56
两个相似无衬线，                + Inter 16/24]
视觉打架                       衬线×无衬线，
                              结构对比清晰
```

### 排版底线

- 正文最小可读 ≈ 16px
- 浅色文字在深色背景需更大行高
- 长文阅读需限制最大行长（网页上无约束会无限延伸）
- 字体回退栈应在视觉重量上接近首选字体（避免加载前后的"闪烁跳跃"）
- 不禁用用户缩放（无障碍底线）

## 3. 色彩 (Color)

**承诺一个有凝聚力的调色板。主色 + 锐利强调色 > 胆怯均匀分布。**

### Tinted Neutral：纯灰已死

给所有中性色加一丝品牌色相，创造潜意识凝聚力：

- 冷调灰（蓝调）→ 科技、专业、工具
- 暖调灰（黄调/红调）→ 品牌温度、生活方式
- 绿调灰 / 紫调灰 → 个性化情绪

### 60-30-10 是视觉重量，不是像素面积

60% 中性背景 / 30% 次要色 / 10% 强调色。强调色之所以有效，正因为稀有。

### 调色板结构

| 角色 | 用途 | 数量 |
|------|------|------|
| Primary | 品牌、CTA、关键操作 | 1 |
| Neutral | 文字、背景、边框 | 5–9 阶 |
| Semantic | 成功/错误/警告/信息 | 4 |
| Surface | 卡片、弹层 | 2–3 层 |

**除非真的需要，跳过 secondary / tertiary**。多数应用一个强调色就够。

### 色彩判断规则

| 规则 | 反例 | 正解 |
|------|------|------|
| 不用纯黑纯白 | `#000` / `#fff` | 加色相，如 `#0a0a0c` / `#fafaf7` |
| 彩色背景上不用灰文字 | 蓝 bg + `#888` | 用 bg 的深色版（同色相） |
| 大量透明度是设计气味 | 处处 alpha 30/50/80 | 为每个上下文定义明确颜色 |
| 渐变不跨色相 | 紫→粉→橙 | 同色相不同明度/饱和度 |

### 深色模式的层级表达

深色模式**用更亮的表面色创造层级，不是阴影**：

```
浅色模式层级           深色模式层级
─────────────         ─────────────
背景 #fafafa          背景 #0a0a0c
卡片 #ffffff          卡片 #161618    ← 比背景亮
浮层 #ffffff + 阴影    浮层 #1f1f22    ← 再亮一档
```

暗色模式不是"反色"，是**独立调色板**。纯反转会产生刺眼的高对比和错误的色彩情绪。

## 4. 节奏与韵律 (Rhythm & Flow)

**好的界面像好的音乐：有节拍、有起伏、有呼吸。**

### 间距数列

间距值来自有节奏的数列，不是随手填的数字：

```
4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96 / 128
```

**8 太粗——你会频繁需要 12**。Data-Dense & Utility 用小步长（4/8/12），Typographic-First 用大步长（48/96/128）。

### 韵律类型

```
均匀节奏：A - A - A - A         单调，慎用
渐进节奏：A - Aa - Aaa - Aaaa   引导视线
对比节奏：密 - 疏 - 密 - 疏      呼吸感
交错节奏：左图右文 - 右图左文     视觉趣味
```

### 自检：节奏失败 vs 节奏成立

```
失败（机械等距）              成立（呼吸节奏）
──────────────                ──────────────
[Section A 64px]              [Hero 160px]
[Section B 64px]
[Section C 64px]              [Section A 96px]
[Section D 64px]              [Section B 96px]
[Section E 64px]
                              [Section C 64px]
所有 section 等高              [Section D 64px]
读者麻木
                              [CTA 120px]

                              起 - 承 - 转 - 合
```

### 卡片不是必需品

间距和对齐自然创造视觉分组。只在以下场景用卡片：

- 内容真正独立可操作
- 需要网格对比
- 需要明确交互边界

**永远不卡片套卡片**。

## 5. 平衡与张力 (Balance & Tension)

**平衡 ≠ 对称。动态平衡比静态对称更有活力。**

| 平衡类型 | 特征 | 适用 |
|---------|------|------|
| 对称 | 左右镜像，稳定正式 | 企业、金融 |
| 不对称 | 视觉重量不均但整体平衡 | 产品页、创意品牌 |
| 放射 | 向中心或从中心发散 | 单焦点页面 |

**视觉重量**（重→轻）：大尺寸 > 小尺寸；深色/饱和 > 浅色；复杂纹理 > 纯色块；中心 > 边缘。

### 自检：对称 vs 不对称

```
对称（稳定但平庸）             不对称（动态平衡）
──────────────                ──────────────
   [    Title    ]            [Title          ]
   [  Subtitle   ]            [Subtitle       ]
   [   [CTA]     ]            [[CTA]      ████]
                                          ████
                                          ████
全部居中                       左 6:4 右
没有判断                       重量平衡但有方向
```

**张力的创造**：元素轻微打破网格、不对称图文比（1:2 而非 1:1）、意料之外的留白位置。

## 6. 格式塔原理 (Gestalt Principles)

**人脑会自动把零散元素组织成有意义的整体。**

| 原理 | 含义 | 应用 |
|------|------|------|
| 接近性 | 距离近 = 一组 | 相关控件放一起 |
| 相似性 | 相似 = 一组 | 同层级同样式 |
| 连续性 | 沿平滑路径移动 | 引导线、流程指示器 |
| 闭合性 | 大脑补全不完整形状 | 巧妙留白 |
| 共同命运 | 同向移动 = 一组 | 同步动画暗示关联 |
| 图形-背景 | 分离前后景 | 明确的卡片/浮层层次 |

## 7. 统一性与变化 (Unity & Variety)

**必须一致**：主色调、圆角语言、字体家族、间距系统、阴影语言。

**许可大胆**：首屏比内页大胆、营销页比工具页有氛围、特殊时刻（空状态、成功、错误）。

**绝不能变**：交互反馈方式、信息层级逻辑、可访问性底线。

## 8. 质感与深度 (Texture & Depth)

**深度服务于功能，不是为了"看起来高级"。**

### 优先级（从轻到重）

```
纯色层级 → 细微边框 → 轻阴影 → 背景渐变 → 模糊/玻璃/光晕
```

能用前一项就不用后一项。

### 各气质的质感预算

| 设计范式 | 阴影 | 边框 | 圆角 | 渐变 | 重技法上限 |
|------|------|------|------|------|-----------|
| Typographic-First | 0 | 1px 细线 | 0 / 4px | 0 | 0 |
| Geometric & Technical | 0 | 1px | 6 / 8px | 0 | 0 |
| Data-Dense & Utility | 0 / 1 级浅 | 1px | 4 / 6px | 0 | 0 |
| Content-Immersive | 1 大尺度 | 0 | 0 / ≥16px | 1 同色系 | 1 |
| Human-Centric & Soft | 1 级温和 | 0 / 模糊边 | 12 / 24px | 1 轻 | 2 |

### 重技法判定

毛玻璃 / Mesh Gradient / 噪点 / 光晕 / 视差 **不在默认工具箱**。要使用必须能回答：
**"拿掉这个效果之后，结构本身还成立吗？"** 不能 = 装饰在掩盖结构缺陷。

### 阴影原则

- 同页不超过 3 层：背景层 / 内容层 / 浮层
- 阴影要微妙——能清晰看到就太重了
- 深色模式用更亮表面色，不是阴影

## 9. 光学调整 (Optical Adjustments)

**几何正确 ≠ 视觉正确。**

| 调整项 | 现象 | 处理 |
|--------|------|------|
| 文字光学对齐 | 左对齐文字因字形左侧留白显得更靠右 | 必要时轻微负向偏移 |
| 图标几何居中 | 播放三角、箭头几何居中后看起来偏 | 三角右移、箭头朝向偏移 |
| 圆形 vs 方形同尺寸 | 等尺寸的圆看起来比方小 | 圆稍放大（约 +3~5%） |
| 触控目标 vs 视觉尺寸 | 按钮可以看起来小，但热区要够大 | 视觉重量与触控热区分离 |
| 大字字距 | 字越大看起来越松 | 标题/Display 用负字距收紧 |

## 10. Anti-AI-Slop：从"症状清单"到"自检问题"

AI Slop 不是"用 AI 做的设计"，而是**向统计平均收敛的设计**——缺乏设计判断、缺乏上下文特性、缺乏人类触感。

### 为什么 LLM 会产生 Slop

LLM 预测下一个 token 时，从训练数据中学习概率分布。"现代网站"在训练数据中最常见的关联：
- Inter 字体 + 白底 + 紫渐变 = "现代 SaaS"
- 居中 Hero + 三列卡片 = "landing page"
- 毛玻璃 + 大圆角 + 阴影 = "高级质感"

模型选择**概率最高的"安全"答案**，而不是**最适合当前上下文的答案**。结果就是所有输出向同一个中位数靠拢。

**打破收敛的关键不是"禁止元素"，而是"强制判断"**——每个选择都必须能用"因为..."解释。

---

### 维度 1：字体 — 有性格还是隐形？

**自检问题**：
> 我选择的字体有性格吗？能说出"为什么选它"吗？

| 诊断 | 信号 |
|------|------|
| ❌ 收敛区 | "因为它是安全的/常见的/默认的" |
| ❌ 收敛区 | Inter / Roboto / Arial / Open Sans / Lato / Montserrat / Poppins |
| ✅ 有判断 | "因为它的几何感呼应了产品的精确性" |
| ✅ 有判断 | "因为衬线的编辑感匹配了内容的人文深度" |

**有性格的方向**（不是强制替换，而是"有理由的选择"）：
- 需要中性但不默认 → Instrument Sans / Onest / DM Sans / Figtree
- 需要编辑感 → Fraunces / Newsreader / Lora
- 需要几何感 → Outfit / Bricolage Grotesque
- 需要性能 → 有意识地构建系统字体栈（不是"随便用一个无衬线"）

---

### 维度 2：颜色 — 从情境生长还是从默认继承？

**自检问题**：
> 我的配色是从情境中生长出来的，还是从训练数据中默认的？

| 诊断 | 信号 |
|------|------|
| ❌ 收敛区 | 紫色渐变在白色背景上（最强 AI 信号） |
| ❌ 收敛区 | "现代蓝色"、"科技蓝色"、"默认渐变" |
| ❌ 收敛区 | 胆怯均匀调色板（每个颜色都不敢做主） |
| ❌ 收敛区 | 纯黑 #000 / 纯白 #fff |
| ✅ 有判断 | "从品牌所在的物理空间汲取" |
| ✅ 有判断 | "从目标用户的文化语境中提取" |
| ✅ 有判断 | "这个产品的情绪是'清晨的冷静'，所以用冷调灰 + 薄雾蓝" |

**有判断的方向**：
- tinted neutral：给所有灰度加一丝色相（冷调 = 科技，暖调 = 品牌温度）
- 1 主色 + 1 锐利强调色：强调色之所以有效，正因为稀有
- 从文化/情境汲取："1970s 滑雪小屋配色"比"现代蓝色"有 100 倍的性格
- 同色系推导渐变：不跨色相

---

### 维度 3：布局 — 有方向还是随波逐流？

**自检问题**：
> 用户能预测下一屏是什么吗？如果能，设计没有惊喜。

| 诊断 | 信号 |
|------|------|
| ❌ 收敛区 | 居中 Hero + 三等分等宽卡片 + CTA |
| ❌ 收敛区 | Hero → Feature → Pricing → Footer 套路 |
| ❌ 收敛区 | 所有 section 等高、等距 |
| ❌ 收敛区 | 全居中排列 |
| ✅ 有判断 | "左重右轻的不对称创造了向前的动势" |
| ✅ 有判断 | "第三个 section 打破规律，防止视觉疲劳" |
| ✅ 有判断 | "单一大图比三张小图更能传递核心卖点" |

**有判断的方向**：
- 不对称分割（6:4、7:3）而非对称（5:5）
- Bento 主次比例（2:1、3:2）而非等分
- Zig-Zag 中第三个打破规律
- 网格打破：元素溢出边界、文字与图像重叠

---

### 维度 4：质感 — 服务功能还是假装高级？

**自检问题**：
> 每个质感元素都能回答"它服务什么功能"吗？

| 诊断 | 信号 |
|------|------|
| ❌ 收敛区 | 毛玻璃 / 发光 / 紫蓝渐变 = "看起来高级" |
| ❌ 收敛区 | 圆角大杂烩（0px / 4px / 8px / 16px / 24px 混用） |
| ❌ 收敛区 | 同页 5+ 种不同阴影 |
| ✅ 有判断 | "细边分隔了两个信息层级" |
| ✅ 有判断 | "阴影暗示这个元素可以拖拽" |
| ✅ 有判断 | "渐变背景创造了空间深度，让焦点浮起来" |

**递进原则**（从轻到重，能用前一项就不用后一项）：
```
纯色层级 → 细微边框 → 轻阴影 → 背景渐变 → 模糊/玻璃/光晕
```

---

### 维度 5：动效 — 帮助理解还是装饰填空？

**自检问题**：
> 动效是帮助用户理解发生了什么，还是为了"看起来有动效"？

| 诊断 | 信号 |
|------|------|
| ❌ 收敛区 | 每个按钮都有 hover 动画 |
| ❌ 收敛区 | bounce / elastic / 弹性过冲 |
| ❌ 收敛区 | 视差滚动 |
| ✅ 有判断 | "入场动画引导用户注意到新出现的内容" |
| ✅ 有判断 | "状态切换的过渡让用户理解'发生了什么'" |
| ✅ 有判断 | "加载序列创造了期待感" |

**有判断的方向**：
- 有编排的入场：staggered reveal with animation-delay
- 高冲击时刻：只在关键转换点使用动效
- 静态可降级：复杂动效必须能在静态下成立

### 维度 6：背景 — 设计了空白还是空白？

**自检问题**：
> 背景是"设计决策"还是"默认设置"？

| 诊断 | 信号 |
|------|------|
| ❌ 收敛区 | 纯白 #fff（因为是默认值） |
| ❌ 收敛区 | 缺乏氛围、深度、上下文关联 |
| ✅ 有判断 | "暖白底呼应了品牌的温度" |
| ✅ 有判断 | "微妙的渐变暗示了空间层次" |
| ✅ 有判断 | "纹理背景创造了材质感" |

**有判断的方向**：
- tinted neutral：即使是"白"也有色相倾向
- layered gradients：多层低透明度同色系渐变
- 几何纹理：细微的网格、点阵、线条
- 上下文相关：产品页用产品色系，品牌页用品牌情绪色

### 维度 7：组件 — 为上下文定制还是拖模板？

**自检问题**：
> 这个组件只能在这个产品上出现吗？换到别的产品还成立吗？

| 诊断 | 信号 |
|------|------|
| ❌ 收敛区 | 通用卡片（任何网站都能用） |
| ❌ 收敛区 | 卡片套卡片 |
| ❌ 收敛区 | 所有交互都弹窗（modal 滥用） |
| ❌ 收敛区 | 三等分图标卡片（three-boxes-with-icons cliché） |
| ✅ 有判断 | "这个卡片形态是由内容特性决定的" |
| ✅ 有判断 | "就地展开比弹窗更符合用户的上下文" |

**有判断的方向**：
- 为上下文定制：形态由内容决定，不是由模板决定
- 就地展开 / Inline edit / Undo：替代弹窗
- 间距自然分组：不用卡片，用留白和对齐

### 维度 8：完美 — 过度无菌还是有意不完美？

**自检问题**：
> 这个设计像 3D 渲染图还是像真实世界？

| 诊断 | 信号 |
|------|------|
| ❌ 收敛区 | 完美对称、完美等距、完美圆角 |
| ❌ 收敛区 | 无菌感、塑料感、没有手工痕迹 |
| ✅ 有判断 | "轻微的不对称创造了张力" |
| ✅ 有判断 | "可见的纹理暗示了材质" |
| ✅ 有判断 | "手工痕迹让设计感觉是被人创造的" |

**有判断的方向**：
- 轻微打破网格：元素不完全对齐
- 可见纹理：纸张、噪点、印刷感
- 不对称平衡：视觉重量平衡但不对称
- "活"的感觉：让设计感觉是被人类手创造的

### 打破收敛的四条策略

**1. 明确禁止（Negative Constraints）**
降低某些模式的概率权重。不是"不要用"，是"明确排除统计平均选项"。

**2. 正面引导（Positive Direction）**
"设计一个好看的页面" = 填平均。给出具体的情境描述，让模型向非平均区域探索。

**3. 参考驱动（Reference-Driven）**
给出 2-3 个具体参考的文字描述，让模型在特定审美线索上插值。

**4. 有意的"不完美"（Intentional Imperfection）**
在完美对称中加入一个打破、在干净背景中加入一层纹理、在机械节奏中加入一个变化。
