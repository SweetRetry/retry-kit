# 网页视觉结构模式

结构模式是**起点而非终点**。理解它们背后的视觉原则，然后根据具体情境打破它们。

本文件聚焦**网页的视觉结构决策**——不是信息架构（交给 ui-blueprint），而是"这个页面在视觉上应该长什么样"。

---

## 模式使用哲学

> "模式不是食谱，而是语法。掌握语法后，你可以写诗，也可以写散文。"

**正确使用方式**：
1. 理解模式解决的视觉问题（焦点、平衡、节奏）
2. 根据内容特性选择或变形
3. 必要时打破模式创造记忆点

**错误使用方式**：
- 无脑套用 "三等分卡片"、"Hero + Feature + CTA"
- 因为 "别人都这么做" 而做
- 为了用模式而用，忽视内容特性

---

## Hero 构图模式

### 1) 对称分割 (Split)

```
[左: 标题+描述+CTA]  [右: 视觉/产品图]
         ↓ 移动端 ↓
[标题]
[视觉]
[描述+CTA]
```

**解决的视觉问题**：平衡文字信息与视觉展示的重量
**适用**：产品介绍、功能页
**视觉比例**：
- 6:4（文字更重要）
- 5:5（图文并重）
- 4:6（视觉主导）

**打破方式**：
- 让视觉"溢出"网格边界
- 文字与视觉轻微重叠（需保证可读性）
- 非对称比例（如 7:3）

---

### 2) 沉浸全幅 (Immersive)

```
┌─────────────────────────────┐
│      [强视觉背景]            │
│                             │
│    [单一叙事 + 单一 CTA]      │
│                             │
└─────────────────────────────┘
```

**解决的视觉问题**：创造情绪冲击、品牌记忆
**适用**：品牌页、发布页、情感型产品
**风险**：信息密度过低、转化弱

**变化**：
- 视频背景（需静音、慢节奏）
- 大尺度插图/3D
- 纯色彩情绪（同色系渐变、深纯色）

---

### 3) 数据聚焦 (Data Hero)

```
[标题/筛选]
[指标1] [指标2] [指标3] [指标4]
      ↓ 或 ↓
[大数字 + 趋势图]
```

**解决的视觉问题**：工具类产品的效率优先展示
**适用**：Dashboard、运营看板、工具首页
**视觉原则**：3-4 个核心指标，有主有次

**变化**：
- 1 大 + 3 小（强调核心指标）
- 时间轴 + 实时数据
- 图表为主，文字为辅

---

### 4) 叙事滚动 (Narrative Scroll)

```
[固定视觉区]
[滚动内容区 ──────────>
     内容1
     内容2
     内容3]
```

**解决的视觉问题**：将复杂信息分步骤展示
**适用**：产品流程介绍、复杂功能说明
**注意**：移动端需重新设计，不能简单缩放

---

## Feature 展示模式

### 1) Zig-Zag（交替）

```
[文] [图]
[图] [文]
[文] [图]
```

**解决的视觉问题**：连续介绍多个功能点时的视觉趣味
**适用**：3-4 个功能点介绍
**风险**：过长会显得重复

**打破方式**：
- 第三个打破规律（居中、全宽、或不同结构）
- 引入不同尺度（一个大功能 + 两个小功能）

---

### 2) Bento（便当盒）

```
[主卡    ] [副卡]
[        ] [副卡]
[副卡] [副卡]
```

**解决的视觉问题**：信息块重要性不均时的主次表达
**适用**：功能亮点、能力展示
**注意**：主次比例要明显（如 2:1 或 3:2）

---

### 3) 单视觉焦点 (Single Visual)

```
[标题]
[大段描述]
[────────────────────────────]
[      巨大产品截图/演示       ]
[────────────────────────────]
[要点列表]
```

**解决的视觉问题**：一个核心卖点需要被放大展示
**适用**：核心功能演示、产品界面展示
**原则**：视觉区要足够大，细节可见

---

### 4) 时间轴/步骤 (Timeline)

```
●─── 步骤1
│
●─── 步骤2
│
●─── 步骤3
```

**解决的视觉问题**：流程、步骤、进展的可视化
**适用**：使用流程、项目进展、历史时间线
**变化**：垂直、水平、或交错

## 应用页模式

### Dashboard Shell

```
┌────────┬──────────────────┐
│ Sidebar│  Topbar          │
│        ├──────────────────┤
│        │                  │
│        │    Content       │
│        │                  │
└────────┴──────────────────┘
```

**视觉原则**：
- 导航区与内容区视觉分离
- 边界用一种方法：边框 或 底色差
- Sidebar 固定宽度，Content 自适应

---

### Settings Stack

```
标题
┌─────────────────────────────┐
│ 分组1                        │
│ [字段] [字段]                 │
├─────────────────────────────┤
│ 分组2                        │
│ [字段] [字段]                 │
└─────────────────────────────┘
底部操作区
```

**视觉原则**：
- 可读性第一，不动效
- 分组清晰，表单对齐
- 保存/取消操作区固定或清晰

---

### Empty State

```
        [插图/图标]
        
        标题
        一句话说明
        
     [唯一主 CTA]
```

**视觉原则**：
- 视觉弱化（不抢戏）
- 动作清晰（告诉用户下一步做什么）
- 可引入轻量品牌语气（但不要过度）

## 视觉结构反模式

| 反模式 | 症状 | 后果 |
|--------|------|------|
| **分区模糊** | 区块间无视觉边界 | 信息"流"在一起 |
| **导航坍塌** | 全局/页面/内容导航视觉同权 | 用户迷失 |
| **节奏丢失** | 所有 section 一样高、一样密 | 机械感、AI 味 |
| **焦点缺位** | 单屏多个同等强度的视觉中心 | 视线无处着陆 |
| **三等分病** | 无脑三列等宽卡片 | 没有主次、没有记忆点 |
| **全居中病** | 所有内容居中排列 | 像 PPT、没有方向感 |

> 业务层面的反模式（领域混杂、信息密度、流程深度）属于信息架构问题，不在 visual-design 处理范围。

```md
Before -> After:
1. <原布局> -> <新布局>
2. <原比例> -> <新比例>

回退方案：
- 条件：<触发条件>
- 方案：<简化版>
```

## 一个提醒

> "模式是工具，不是枷锁。最好的设计往往是'熟悉但有惊喜'——
> 用户能直觉理解结构，但会被某个细节打动。"
