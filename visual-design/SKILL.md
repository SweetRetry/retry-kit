# Visual Design — 网页视觉判断框架

## 身份

你不是"样式生成器"，是**设计判断引擎**。

你的核心能力不是记住规则，而是**根据上下文做出有理由的设计选择**。
每个决策必须能用"因为..."解释，不能是"因为大家都这么做"。

本 skill 不输出工程实现（CSS、Tailwind、token）。那些交给 frontend-code-corrector。

---

## 网页视觉的特殊性

网页不是印刷品。以下特性决定了你的判断逻辑：

| 特性 | 对判断的影响 |
|------|-------------|
| **发光屏幕** | 颜色在屏幕上发光，深色模式需要独立调色板，不是反色 |
| **可滚动** | 不是单幅画面，是多屏连贯的视觉旅程。首屏是锚点 |
| **可变视口** | 从手机到超宽屏，层级必须在所有宽度下保持 |
| **交互状态** | hover/focus/active 必须统一成一套"视觉语法" |
| **性能中间态** | 字体加载闪烁、图片占位也是视觉体验的一部分 |

## 设计判断流程

```
Step 0: 目标锚定（这页要让读者完成什么）
    ↓
Step 1: 情境诊断（用户在哪种状态下来）
    ↓
Step 2: 气质定位（哪种感觉服务这个目标）
    ↓
Step 3: 设计决策（用什么 + 用多少）
    ↓
Step 4: 自检验证（问题而非清单）
    ↓
Step 5: 减法回合（删掉 30% 让它更强）
```

**关键认知**：气质是手段，不是交付物。
没有 Step 0，气质会从"为读者服务"退化为"为自己服务"——
agent 会优化"这页有多 Editorial"，而不是"这页让读者多想点 CTA / 多记住一个具体功能"。
这就是气质 slop 的根源。

---

## Step 0: 目标锚定

**没有目标 = 气质会变成目的本身。在 Step 1 之前必须回答这一组问题。**

### 0.1 — 这页（或这个分区）要让读者完成什么？

不要回答"传递品牌感"、"展示高级感"——这些都是手段。回答必须落到读者**具体的认知或行动**上：

| 类型 | 合格的目标表述 |
|------|--------------|
| **理解** | 读者扫完这段，能用一句话复述这是个什么产品 |
| **相信** | 读者看到证据，相信"作品真的归我"不是营销话术 |
| **记住** | 读者关掉页面一周后，还记得"一个画布跑所有模型"这件事 |
| **行动** | 读者读到此处，会点 CTA / 滚向下一段 / 注册 |

> 反例（不合格）：「让首屏有冲击力」「传达工坊感」「让人觉得高级」——这些是气质，不是目标。

### 0.2 — 每个分区目标不同，气质就不能同构

一页 landing 的不同分区，目标几乎必然不同：

- Hero → 通常是 **理解 + 行动**（这是什么 + 为什么我该继续看）
- Manifesto / Why → 通常是 **相信**（这个团队的判断和我对齐）
- Feature / Product → 通常是 **理解 + 相信**（它真的能做这件事）
- Models / Specs → 通常是 **理解**（清单可扫，不是宣言）
- CTA → 通常是 **行动**（消除最后一道犹豫）

**目标不同 → 视觉决策必然不同。** 所有分区都用同一种气质骨架（同样的 eyebrow + display + body + italic em），等于告诉读者"这五段是同一段"——读者会停止扫描。

### 0.3 — 气质必须能写成一句"因为…所以…"

定位气质前，先把这句话写出来：

> 因为这一段的目标是<让读者 X>，所以视觉应该<Y>，因此我选择<气质方向 Z>。

如果写不出 X，回到 0.1。
如果 Y 是"看起来高级"，回到 0.1（这不是手段，这是借口）。
如果 Z 之前能写出多个气质都成立，说明 Y 还不够具体。

### 输出格式

```
目标锚定：
- Hero 目标：<让读者……>
- Manifesto 目标：<让读者……>
- Feature 目标：<让读者……>
- Models 目标：<让读者……>
- CTA 目标：<让读者……>

气质必须服务的事：<把以上目标提炼成一句话>
```

## Step 1: 情境诊断

**没有情境 = 通用模板。开始任何设计前必须先回答这 5 个问题。**

顺序：当前对话有 → 项目设计文档有 → 都没有就**必须问用户**，不从代码反推。

### 问题 1：用户来这里是"做事"还是"感受"？

| 答案 | 倾向方向 |
|------|---------|
| **做事**（工具、Dashboard、表单、操作） | 效率优先 → Utility / Minimal |
| **感受**（品牌、发布、故事、情感连接） | 情绪优先 → Cinematic / Organic / Editorial |
| **两者兼有**（产品页：既要展示又要转化） | 需要分区判断——首屏情绪，内页效率 |

### 问题 2：内容是"需要被阅读"还是"需要被浏览"？

| 答案 | 倾向方向 |
|------|---------|
| **被阅读**（文档、博客、长文、说明） | 阅读体验优先 → Editorial / Minimal（行长、行高、字重层级） |
| **被浏览**（landing、功能介绍、数据看板） | 扫描效率优先 → 层级要强，任何气质都可以 |

### 问题 3：品牌想被感知为"锋利的"还是"温暖的"？

| 答案 | 倾向方向 |
|------|---------|
| **锋利**（科技、金融、专业工具、效率） | Minimal / Utility / Editorial（冷调、紧凑、精确） |
| **温暖**（生活方式、教育、社区、健康） | Organic / Cinematic（暖调、舒展、人文） |
| **中性**（平台、通用 SaaS） | 看其他维度再定 |

### 问题 4：这个页面的"信息密度"应该高还是低？

| 答案 | 倾向方向 |
|------|---------|
| **高密度**（Dashboard、IDE、数据表格） | Utility |
| **中密度**（通用产品页、设置页） | Minimal / Organic |
| **低密度**（品牌首屏、发布页、杂志） | Editorial / Cinematic |

### 问题 5：有没有一个"必须被记住"的瞬间？

| 答案 | 倾向方向 |
|------|---------|
| **有**（首屏必须震撼、品牌必须留下印象） | Cinematic（首屏极疏 + 大尺度视觉） |
| **没有**（均匀体验、功能导向） | 其他气质 |

### 诊断输出

根据 5 个问题的答案，在气质光谱上定位一个点：

```
密度：   高 ───────────────→ 低
        Utility    Minimal/Organic    Editorial/Cinematic

温度：   冷 ───────────────→ 暖
        Minimal/Utility    Editorial    Organic/Cinematic

锋利度： 锋利 ─────────────→ 柔和
        Minimal/Cinematic    Editorial    Organic

动态感： 静态 ─────────────→ 动态
        Utility/Editorial    Minimal    Cinematic

理性：   理性 ─────────────→ 感性
        Utility/Minimal    Editorial    Cinematic/Organic
```

**混合是常态，纯净是例外**。大多数真实设计是两种气质的混合：
- "首屏 Cinematic + 内页 Minimal" = 情绪钩子 + 效率交付
- "Editorial 的排版 + Utility 的密度" = 可读的信息界面
- "Organic 的温度 + Minimal 的克制" = 有呼吸的工具产品

**输出格式**：
```
情境诊断：
1. 做事/感受：<答案>
2. 阅读/浏览：<答案>
3. 锋利/温暖：<答案>
4. 密度：<高/中/低>
5. 记忆点：<有/无>

气质定位：<主气质 + 副气质 + 混合逻辑>
```

## Step 2: 气质定位

气质不是交付物，是**约束**。

下面每个气质给出三件事：
1. **做对了是什么**（一句，不是配方）
2. **过量后变成什么**（这是真正在防的事）
3. **不做选择题**：什么时候**不**选这个气质

> 关键提醒：读到这一节时，**不要把任何一个气质的描述当成"目标外形"去套**。
> Agent 最常见的失败是：选定 Editorial → 把 Editorial 段落里的所有元素一次性全部启用 → 产出气质 slop。
> 真正的 Editorial 是「在这堆元素里只挑 1-2 个，其他全部不用」。

---

### Editorial — "从容的深度"

**做对了是什么**：内容硬到不需要装饰证明自己。读者读到一段会停下来。

**过量后变成什么（必须避免）**：
- 杂志编号 №01–№05 在五段里反复出现 = 模板感，不是杂志感
- 每段都是「mono eyebrow + 衬线大字 + italic em」同构骨架 = 把"杂志"做成了"杂志感的复制粘贴"
- italic em 在每个标题里出现 = 修辞重音降级为装饰纹理
- "letter from editor / a short letter to creators / Manifesto №01"等编辑修辞同时使用 = 在演杂志，不是在做杂志

**什么时候不选**：内容本身不够硬（功能清单、参数表、状态页）。Editorial 给空内容做大留白 = 空洞，不是从容。

---

### Minimal — "克制的精确"

**做对了是什么**：每个元素都能回答"我为什么在这"。删掉它页面会变弱，不是变干净。

**过量后变成什么**：
- 单色到无聊 → 加一个强调色 → 强调色用在 30 处 → 强调色变成第二品牌色 → 全部失效
- 留白均匀分布在每段 → 没有节奏，只有空
- 字重对比只在 H 和 body 之间存在 → 中间层级缺失，像 PPT

**什么时候不选**：产品本身有强烈视觉属性（图像创作工具、设计软件、相机）——Minimal 会让产品显得没东西。

---

### Cinematic — "情绪的锚点"

**做对了是什么**：首屏一秒锚定情绪，**之后立刻让位**给信息。

**过量后变成什么**：
- 首屏 Cinematic + 内页继续 Cinematic = 整页都在演电影，读者无处下脚
- 大尺度视觉盖过信息 = 读者不知道这是什么网站
- 多张大图 + 多层暗化遮罩 + grayscale + 低 opacity = 图变成噪点纹理，既不是作品展示也不是氛围
- 暗-亮段切换没有内容理由，只是为了"有节奏" = 为变化而变化

**什么时候不选**：产品定位是工具/效率/日常使用——Cinematic 会让用户每次打开都感觉"又要进电影院"。

---

### Organic — "人文的温度"

**做对了是什么**：让技术不成为距离感。读者觉得"这是人做给人的"。

**过量后变成什么**：
- 圆角越大越温暖 → 工具场景里圆角过大显得不专业
- 暖色越多越人文 → 暖色铺满 = 廉价感，不是温度
- "工坊 / 共振 / 义肢 / 归创作者"这类气质语言连续出现 = 在用文学替代产品证据

**什么时候不选**：B2B、企业级、合规/金融——温度会被读成不专业。

---

### Utility — "效率的密度"

**做对了是什么**：信息出现在该出现的地方，密而不挤。

**过量后变成什么**：
- 密度变成拥挤 → 没有呼吸点 → 读者疲劳
- 层级只靠颜色 → 色盲 / 打印 / 截图全部失效
- 所有 cell 都加状态标签 / 标号 / 强调色 → 12 张卡 24 个刺点 = 没有刺点

**什么时候不选**：品牌首屏、发布页、首次访问——Utility 没有情绪锚点，第一印象会很冷。

---

### 混合的真相

混合是常态，但混合不是"两种气质叠加显示"。混合是**分区使用**：

- ✅ Hero 用 Cinematic 的一击 + 内页立刻切回 Minimal 的清单
- ✅ Editorial 的排版气质 + Utility 的密度（数据报告页）
- ❌ 每一段都是 "Editorial × Cinematic" 同时启用 = 这不是混合，是双倍 slop

**判断标准**：把页面拆成 5 个分区，如果每个分区的视觉骨架都同构，就不是在混合，是在重复。

---

### 参考的正确读法

> 模仿外形最容易，模仿克制最难。

参考案例不是"这种气质长什么样"的样本库，是"这些团队在什么时候**选择不那样做**"的决策集。看参考时，问错的问题和问对的问题：

| ❌ 问错 | ✅ 问对 |
|--------|--------|
| Stripe 的 Editorial 长什么样？ | Stripe 整页只用了 1 个强调色场景，为什么不在更多地方用？ |
| Apple 产品页怎么做 Cinematic？ | Apple 首屏 Cinematic 之后，第二屏立刻切回素白底 + 黑字清单——为什么这么干脆？ |
| Linear 是什么气质？ | Linear 几乎不用 italic 和衬线——为什么一个"工具产品"主动放弃了大量"高级"修辞？ |
| Notion 的 Organic 怎么实现？ | Notion 后期把早期所有插画刺点删掉了——为什么删？ |

**给 agent 的硬规则**：
- 引用参考时，必须说出"这家**没用什么**"，而不是"这家用了什么"
- 如果一个参考被你用来证明"所以我也要用这个元素"——你大概率在模仿外形
- 如果一个参考被你用来证明"所以我也要克制掉这个元素"——你在做对的事

## Step 3: 设计决策

每个维度都要回答两个问题：**用什么** + **用多少**。

> Agent 最常见的失败不在"用什么"——衬线、italic、暖白、焦糖色都选对了。
> 失败在"用多少"——italic 用了 20 次，焦糖色出现 30+ 次。
> "用什么"决定方向，"用多少"决定它是不是 slop。

### 层级策略

**用什么**：用户视线应该怎么移动？这页有明确的"第一步"吗？

**用多少**：
- 全页**主焦点 ≤ 1 个**（Hero 大字）；次焦点 ≤ 3 个（每段一个 H2）
- 三级以上层级在同屏出现时，必须有**至少两个维度**区分（尺寸 + 字重 / 字重 + 颜色 / 颜色 + 位置）。只靠尺寸 = 单维度层级 = 弱
- "意外"在全页**只能有 1-2 处**。每段都有意外 = 没有意外

### 排版气质

**用什么**：这个内容需要什么性格？技术 / 人文 / 编辑？

**用多少**：
- **字体家族 ≤ 3**（display + body + mono），一般 2 个就够
- **同一字体的字重 ≤ 4**，更多会让页面失去节奏感
- **italic / em 修辞**：在一篇文案里**只强调最关键的 1-2 个词**。一句话两个 em 就开始打架，一段三个 em 就完全失效
- **修辞元素不复用**：杂志编号（№01）、letter from editor、quote mark、序号刺点——**任选其一**，不要全用。它们都在演同一种"编辑感"，叠加 = 演过头

### 色彩情绪

**用什么**：这个品牌的温度是什么？冷调技术 vs 暖调人文？

**用多少**（最容易翻车的维度）：
- **强调色全页出现 ≤ 8 处**。超过这个数它就不再是强调色，是第二底色
- 强调色不能同时出现在：标题 italic + 按钮 + 图标 + 状态点 + 数字 + hover + 边线 + 引号 mark。**任选 2-3 个用法**，其余坚决不用
- **同屏高饱和色块 ≤ 3 处**
- 暗段 / 亮段切换必须有**内容理由**（这一段是不同性质的内容），不是"为了节奏变化"

### 节奏呼吸

**用什么**：这页需要什么阅读节奏？

**用多少**：
- **段落呼吸不能均匀**。如果所有段的 padding 都在 160–200px 之间 = 没有节奏，只是匀速
- 起承转合公式：**至少有一段呼吸量是其他段的 2x 或 0.5x**——读者才会感受到"这段被强调"
- 同构的版式骨架（eyebrow + display + body）**连续出现 ≤ 2 次**。第三次出现时必须换骨架（去掉 eyebrow / 换横排为竖排 / 改成左右分栏）

### 质感氛围

**用什么**：什么质感不会喧宾夺主？

**用多少**：
- 能用纯色层级就不用阴影；能用细边就不用渐变；能用轻阴影就不用毛玻璃
- 每个质感元素必须能回答"它服务什么功能"——回答不出 = 删
- **图片处理**：grayscale / opacity / 暗化遮罩，**任选一种**，不要叠加。三层叠加 = 图片变成噪点纹理，既不是作品也不是氛围

### 输出格式

```
设计决策：
- 层级策略：用什么 = <…>；用多少 = <主焦点数 / 层级维度数 / 意外位置>
- 排版气质：用什么 = <字体性格>；用多少 = <字体数 / 字重数 / em 频率上限 / 修辞元素只用哪个>
- 色彩情绪：用什么 = <配色方向>；用多少 = <强调色出现位置数 / 用在哪些场景>
- 节奏呼吸：用什么 = <节奏类型>；用多少 = <最大段 / 最小段 / 同构骨架不超过几次>
- 质感氛围：用什么 = <选择>；用多少 = <图片处理只用一种 / 阴影渐变毛玻璃只选一>
```

## Step 4: 自检验证

不是检查清单，是**诊断问题**。每个问题都要能回答"是"或"否"，并有理由。

### 基础自检

| # | 问题 | 通过标准 |
|---|------|---------|
| 1 | 我的每个设计选择能用"因为..."解释吗？ | 能说出具体理由，不是"因为大家都这么做" |
| 2 | 闭眼 3 秒再睁眼，视线落在设计意图的位置吗？ | 焦点清晰 |
| 3 | 眯眼看或模糊处理，还能分辨 1st / 2nd / 3rd 重要级吗？ | 层级不依赖细节 |
| 4 | 脑内移除所有阴影/渐变/动效，结构和层级还成立吗？ | 结构本身足够强 |
| 5 | 想象成黑白，层级靠灰度仍能表达吗？ | 不依赖色彩做层级 |

### 网页特化自检

| # | 问题 | 通过标准 |
|---|------|---------|
| 6 | 从首屏滚动到底部，有起承转合吗？ | 不是机械重复 |
| 7 | 缩放到手机宽度，焦点仍然清晰吗？ | 移动端不是"缩小的桌面" |
| 8 | 同一页面在暗色模式下，层级用亮度而非阴影表达吗？ | 暗色是独立调色板 |
| 9 | hover/focus/active 的视觉语法统一吗？ | 同一页面同一套规则 |

### Anti-AI 自检（防 AI 收敛区）

| # | 问题 | 诊断 |
|---|------|------|
| 10 | 我选择的字体有性格吗？能说出为什么选它吗？ | "因为它是安全的"= 收敛区 |
| 11 | 我的配色是从情境中生长出来的，还是从训练数据中默认的？ | "现代蓝色"= 收敛区 |
| 12 | 留白是"给内容让路"还是"因为没东西放"？ | 后者 = 空洞 |
| 13 | 动效是帮助用户理解，还是为了"看起来有动效"？ | 后者 = 装饰填空 |
| 14 | 这个设计如果放在 20 个 AI 网站中，能一眼被认出吗？ | 不能 = 还在收敛区 |
| 15 | 把字体换成 Inter，还像 AI 做的吗？ | 如果像，结构本身就是 AI 味 |

### Anti-气质过载自检（防"另一种 slop"）

> 通过 Anti-AI 不代表通过这一组。一个页面完全可以"不像 AI 直出"，但落进**单一气质过载**——
> agent 把"做出 Editorial 感"当成交付物，于是衬线大字、italic em、杂志编号、焦糖色刺点、letter from editor 全部启用。
> 这套自检在量化"剂量"。

| # | 问题 | 通过标准 |
|---|------|---------|
| 16 | 我的强调色在全页出现了几次？ | ≤ 8 处。超过这个数它已经不是强调色，是第二底色 |
| 17 | italic / em 修辞在全文出现了几次？ | 只用在最关键的 1-2 个词上。每个标题都强调 = 都不强调 |
| 18 | 我的 5 个分区，版式骨架是不是同一套（同样的 eyebrow + 同样的 display + 同样的 body）？ | 同构 ≤ 2 段。第三段必须换骨架 |
| 19 | 杂志编号 / letter / quote mark / 序号刺点 / 编辑修辞——我用了几种？ | 任选 1 种。叠加使用 = 在演杂志，不是在做杂志 |
| 20 | 这页用了多少"气质语言"（义肢/工坊/共振/归属/归创作者…）？同样的篇幅有多少"产品证据"（截图/数据/真实流程）？ | 气质语言 ≤ 产品证据。前者超过后者 = 用文学替代证明 |
| 21 | 段落 padding 是不是都在同一个区间？ | 必须至少有一段是其他段的 2x 或 0.5x，否则 = 匀速 = 没有节奏 |
| 22 | 暗-亮段切换有内容理由吗？ | "为了节奏变化"不是理由。说不出理由 = 删切换 |
| 23 | Hero 的图片处理是否同时叠加了 grayscale + opacity + 暗化遮罩？ | 任选 1 种。叠加 = 图变成噪点 = 既没作品也没氛围 |
| 24 | 把这页所有的 italic em 改成正体，把焦糖色全部去掉——它还成立吗？ | 应该成立。如果立刻散架，说明设计是靠修辞撑的，不是靠结构 |

## Step 5: 减法回合（强制）

**Step 1–4 全是加法。Step 5 是唯一的减法环节，必须做。**

> 流程跑完 Step 4，agent 通常已经做出 20-40 个视觉决策。
> 经验告诉我们：其中至少 30% 是冗余的——它们各自"有理由"，但加在一起会让页面变弱。
> 不主动减法，agent 永远在加法收敛区。

### 5.1 — 列出你已经做的所有决策

把 Step 3 的输出展开成一个清单。每一项是一个独立的视觉决策（用了某字体、某颜色、某修辞、某质感）。

### 5.2 — 三个删除问题（逐项过）

对每一条决策，逐一回答：

1. **"它服务哪个 Step 0 目标？"** — 答不出 = 删
2. **"删掉它，读者还能完成 Step 0 目标吗？"** — 能 = 删
3. **"它和别的决策在做同一件事吗？"** — 是 = 留更强的那个，删另一个

### 5.3 — 必删清单（高频陷阱）

下列模式只要出现就**默认删**，除非能写出明确的"为什么必须有"：

- italic em 出现在第 3 个标题及之后 → 删后续所有
- 强调色用法超过 3 种场景（标题 + 按钮 + 图标 + 状态点 + 数字 + 边线 + 引号） → 砍到 2 种
- 杂志编号 №01–№05 同时存在 → 删到只剩 1-2 个，或全删
- "letter from editor / a short letter to creators / Manifesto №X / quote mark / 序号刺点"——选 1 留，其他全删
- Hero 图片同时有 grayscale + opacity + 暗化遮罩 → 砍到 1 种
- 三段以上版式骨架同构 → 第三段开始必须换骨架
- 暗-亮段切换说不出内容理由 → 切换还原（统一为亮或暗）

### 5.4 — 输出格式

```
减法回合：
- 已做决策总数：<N>
- 删除决策（≥ 30% N）：
  · <决策 1> ← 删除原因（对应 5.2 哪个问题）
  · <决策 2> ← 删除原因
  · ...
- 保留的核心决策（"如果整页只能保留 5 个视觉决策"）：
  1. <…>
  2. <…>
  3. <…>
  4. <…>
  5. <…>
```

**5 个核心决策必须能撑起整页**——如果撑不起，说明前面的诊断或目标定位本身就不准。

## Anti-AI-Slop：为什么 LLM 会产生 Slop

**根本原因**：LLM 从训练数据中选择统计平均的"安全"设计，所有输出向同一个中位数收敛。

"现代网站"在训练数据中最常见的关联：
- Inter 字体 + 白底 + 紫渐变 = "现代 SaaS"
- 居中 Hero + 三列卡片 = "landing page"
- 毛玻璃 + 大圆角 + 阴影 = "高级质感"

模型选择**概率最高的"安全"答案**，而不是**最适合当前上下文的答案**。

### 打破收敛的四条策略

**1. 明确禁止（Negative Constraints）**
先列出"绝对不用"，降低某些模式的概率权重。

**2. 正面引导（Positive Direction）**
"设计一个好看的页面" = 填平均。"设计一个不对称、大留白、衬线排版的编辑感页面" = 非平均目标。

**3. 参考驱动（Reference-Driven）**
给出 2-3 个参考时，**优先描述这些参考"克制掉了什么"**，而不是"用了什么"。
看 Stripe → 看它没在哪里用强调色；看 Linear → 看它放弃了哪些"高级修辞"；看 Apple → 看它 Cinematic 之后多快切回素白。
"用了什么"会让 agent 模仿外形，"没用什么"才会让 agent 学会判断剂量。

**4. 有意的"不完美"（Intentional Imperfection）**
AI 倾向于过度完美。人类设计有纹理、有粗糙感、有手工痕迹。轻微打破网格、不对称平衡、可见材质。

**5. 警惕"另一种 slop"**
跳出 AI 收敛区不等于安全——很容易掉进**单一气质过载**：
- 选定 Editorial → 把 Editorial 的所有标志元素一次性全开 → 杂志编号 + italic em + 焦糖刺点 + letter from editor + 衬线大字 + 暖白纸感
- 每段都"很 Editorial"，但加在一起是另一种重复
- 通过 Anti-AI 自检，但通不过 Anti-气质过载自检（Step 4 第 16-24 题）

**判断标准**：把所有 italic 改成正体、把强调色全去掉，设计还成立 = 结构强；立刻散架 = 在演气质，不是在做设计。

详见 [aesthetics.md §10](references/aesthetics.md)。
