  设计系统，(3) 审查 UI 代码的视觉质量，(4) 构建新组件或页面时需要确定视觉方向。

## Step 1. 风格定调（必须先做）

在写任何代码或给出任何视觉建议之前，先问用户以下三个问题：

> **Q1. 这个界面的主要用途是什么？**
> - A）用户每天都用来完成工作任务（SaaS 工具、后台、数据仪表盘）
> - B）用户第一次看，需要感受产品的价值和魅力（落地页、品牌页、发布页）
> - C）两者兼有（产品内的关键体验页，如 onboarding、空状态）
>
> **Q2. 你希望界面给人的第一感受是？**
> - A）专业、可信、高效——界面退到后台，任务本身最显眼
> - B）惊艳、有记忆点——界面本身就是体验的一部分
> - C）不确定，你来判断
>
> **Q3. 有没有参考产品？**（可以是产品名或 URL，可选填）

根据答案，映射到以下两种风格档位之一：

| 答案组合 | 风格档位 |
|---------|---------|
| Q1=A 或 Q2=A | **克制（Restrained）** |
| Q1=B 或 Q2=B | **表现（Expressive）** |
| Q1=C 或 Q2=C | 优先看 Q3；若无参考，询问用户倾向 |

**Q3 参考产品的处理方式**

若用户提供了产品名或 URL，用以下三个维度快速拆解，然后将结论代入档位判断：

1. **用途**：这个产品是高频工作工具，还是吸引新用户的展示面？
2. **色彩策略**：界面里品牌色占多大面积？是 90% 无彩色，还是大面积渐变/深色底？
3. **动效密度**：页面是静态为主，还是有明显的入场动效/视差/跟随？

得出结论后直接声明档位，无需征求用户确认。若参考产品本身是混搭风格（如 Stripe：落地页表现 + 文档页克制），说明这是路由级别的风格切换，分区对待。

## Step 2. 风格档位原则

### 克制（Restrained）
> 参照：Vercel、Linear、Notion、Raycast

**核心意图**：界面是工具，不是作品。每一个视觉决策都在问："这会不会分散用户对任务的注意力？"

**排版**
- 字号层级清晰但不夸张。H1 醒目但不抢镜，body 可读性第一
- 字重用 semibold / bold，不用 extralight（轻字重在高频界面读起来费力）
- 字体族：一种 Sans 贯穿全局，数字/ID/代码用 Mono。不引入 Display 字体

**色彩**
- 90% 无彩色底色（白 / 浅灰 / 近黑），品牌色只出现在主要操作节点
- 一屏只有 1 个彩色焦点，其余全部无彩色
- 状态色用语义 Token（success/warning/error），品牌色不复用为状态色

**深度**
- 选一种并全局统一：极淡 border 分组 / bg-muted 色块区分 / 无边框纯留白
- 不混用 border + shadow。弹出层（popover/dropdown）可加轻投影，不受主模型约束

**动效**
- 默认不加动效
- 只在三处允许：路由切换淡入、Hero 区入场（y ≤ 8px, opacity 0→1, 300ms）、主 CTA hover（scale 1.02, 150ms）
- 禁用 bounce / spring / parallax

**间距**
- 节奏均匀，密度适中。section 间距用标准档（py-16 ~ py-20）为主
- 相邻 section padding 要有变化，不允许超过 3 个连续等间距 section

---

### 表现（Expressive）
> 参照：Apple、Stripe、Loom、Framer

**核心意图**：界面是体验的一部分。用户应该在第一屏就感受到产品的气质和主张。

**排版**
- H1 要大胆：内容少时推到 text-7xl / text-8xl，用 extralight / light 字重制造张力
- 字重反差要强：H1 light + H2 semibold，不要两个都加粗
- 大标题必须 tracking-tight，text-7xl 以上用 tracking-tighter
- Display 字体（Cal Sans / Instrument Serif）在 Hero H1 是允许的

**色彩**
- 可以打破 90/10 限制：大面积深色底、Mesh 渐变背景、Neon glow 点缀都是合法手段
- 但视觉焦点必须有逻辑递进，不能让界面花哨错乱
- 渐变只用同色相（如 primary/80 → primary/20），禁止跨色相渐变（蓝→橙之类）

**深度**
- 可以选强表现力的深度模型：
  - 暗光 Cinematic：极暗底色 + border-t-white/10 切割卡片 + 光晕发光
  - 重质感：Glassmorphism 毛玻璃 / Neo-brutalism 强阴影粗边框
- 选定后全局统一，不混搭

**动效**
- 赋予页面生命感，动效是叙事的一部分
- 入场可以用大跨度位移（y: 40px→0）、尺寸回弹（scale 0.8→1）、staggerChildren 接力
- 允许 Spring 弹性、鼠标跟随 Spotlight、视差滚动
- 底线：掉帧就移除。动效服务于视线引导，不能喧宾夺主

**间距**
- Hero 区用宽松档（py-24 ~ py-32），让内容撑住整屏
- 内容少时放大标题 + 放大留白 = 张力感
- 相邻 section 用不同构图（全宽图 / Bento / 不对称双列）制造节奏变化

## Step 3. 通用底线（两种风格均适用）

无论选哪种档位，以下规则不可违反：


**视觉一致性**
- 圆角：选一个值全局统一（rounded-sm / rounded-md / rounded-lg / 0px 均可），混用是大忌
- 图标：一个项目一套图标库（Lucide / Phosphor / Heroicons）
- 每屏有且仅有 1 个视觉最重的 CTA

**无障碍基线**
- 文本对比度 WCAG AA ≥ 4.5:1
- 所有可交互元素有可见的 `:focus-visible` 样式
- 触控目标 ≥ 44×44px（移动端）
- 标题语义不跳级（h1 → h2 → h3）
- 动效必须处理 `prefers-reduced-motion`

**暗色模式**
- 不直接反色。用背景色阶梯建立层级（background → card → popover 逐级提亮）
- 避免纯黑 #000，用深灰底色

**定调完成后的输出格式**

在开始写代码之前，用一段简短声明锁定决策，格式如下：

```
风格档位：[克制 / 表现]
参考：[产品名或用户描述]
圆角：[选定值]
深度模型：[border 分层 / bg-muted 色差 / 暗光 Cinematic / 其他]
动效：[无 / 克制入场 / 表现级]
字体：[Sans 选择，如有 Mono/Display 则注明]
```

这个声明的作用是让用户可以在动手前纠正方向，不需要等到代码写完才发现风格跑偏。

## Step 4. 已有项目

进入已有项目时，优先级顺序：**现有代码风格 > 本 skill 规则 > Claude 默认行为**。

先扫描现有代码中的：圆角值、间距惯用值、深度模型（border / shadow / bg 色差）、字体族、动效库和参数。

**扫描后的冲突处理：**

| 情形 | 做法 |
|------|------|
| 现有风格自洽（有明确的圆角/深度/色彩策略） | 完全跟随，不引入本 skill 的偏好 |
| 现有风格部分缺失（如有圆角规范但无动效规范） | 缺失部分用本 skill 对应档位补位，已有部分跟随 |
| 现有风格本身混搭（圆角/深度/色彩不一致） | 跟随出现频率最高的那个值，并在输出声明中注明"现有代码存在不一致，以 X 为准" |
