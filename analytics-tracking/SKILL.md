# Analytics Tracking

只解决一个问题：这条数据、这个埋点，值不值得存在。

## 价值的定义

一条数据有价值，当且仅当它能改变一次未来的判断或动作。

具体来说，看到这个数据的人（产品、增长、运营、工程），会因为它的数值不同而采取不同的行为。如果数值高、低、异常，团队的下一步都一样，这条数据就是装饰。

## 推导价值的四步

面对任何一个"要不要埋 / 要不要看"的候选，按顺序回答：

1. **业务问题是什么**：具体到能写成一句疑问句。"用户是否完成首次核心动作"、"付费漏斗在哪一步流失最多"、"哪个来源的用户 7 天留存最高"。写不出问题，跳过。
2. **谁看、何时看**：有明确的读者和触发场景（周会、实验复盘、告警、A/B 决策）。没有读者的数据默认无价值。
3. **数值变化后会做什么**：能写出"如果 X > Y 就 A，否则 B"这种条件动作。写不出动作，说明只是好奇心，不埋。
4. **能否被现有数据推导**：如果可以从已有事件的 properties 聚合出来，就不新增。新增前先问"现有数据真的答不了吗"。

四步全部通过才值得埋。任何一步答不上来，默认不做。

## 什么行为的数据天然有价值

不是穷举清单，是判断线索：一个行为满足下列之一，通常值得埋。

1. **核心价值到达**：用户拿到了产品承诺的结果（发布成功、导出完成、支付成功、首次创建）。用来判断"产品是否真的在交付价值"。
2. **漏斗节点**：一段有序流程中的进入、开始、提交、成功、失败、放弃。用来判断"在哪一步流失"。
3. **状态转移**：草稿→发布、试用→付费、pending→succeeded/failed。用来判断"转化率与转化速度"。
4. **高意图行为**：搜索、筛选、保存、分享、复制链接、联系销售。用来判断"需求强度与方向"。
5. **收入与增长**：订阅、升级、取消、优惠码、推荐来源、campaign。用来判断"钱从哪来、为什么流失"。
6. **激活与留存**：首次完成关键动作、关键功能第 N 次使用、邀请协作。用来判断"新用户是否养成习惯"。
7. **失败与摩擦**：表单错误、权限拒绝、支付失败、接口失败、空状态。用来判断"为什么没走通"，比"走通了多少"更能驱动改动。
8. **实验与个性化曝光**：variant 曝光、推荐位曝光与点击。用来判断"实验/推荐真的生效了吗"。

共同点：每一类都能直接接一句"看到这个数字，我们会……"。

## 什么数据没有价值（用来反向校准）

出现下列任一特征，默认剔除：

1. **UI 噪声**：按钮点击、tooltip 悬停、滚动、弹窗关闭。UI 一改就失效，且不指向业务事实。
2. **可推导的重复事件**：能由已有事件 + properties 聚合得到（例：`User Active` 完全可以由任意核心事件按天去重推出）。
3. **事件名里带动态值**：`Clicked Plan Pro`、`Project Created From Header`。动态部分应该是 properties，否则事件会爆炸且无法聚合。
4. **没有业务问题的"以后可能有用"**：没有读者、没有动作，只有"先埋着"。这类事件几乎不会被回头清理。
5. **只埋成功、不埋失败**（或反之）：只能看到一半事实，不能解释转化率变化。
6. **关键状态只埋前端**：支付、订阅、发布这类"必须成功才算数"的事件如果只在客户端上报，会被刷新/重试/拦截污染，数值不可信，价值等于零。

## 输出格式

被要求设计或审查埋点时，按这个顺序输出，不要展开成文档：

1. **要回答的业务问题**（一句话一个）
2. **应埋事件**：事件名 + 它回答上面哪个问题
3. **不建议埋**：候选里被剔除的，标注剔除原因（对应上面"没有价值"的哪一条）
4. **可由现有数据推导**：不需要新埋点就能回答的问题，说明用哪些已有事件如何聚合
